# QGIS

> 隸屬：[GIS] › [GIS軟體]　·　狀態：初稿

> 對應維基百科：[中文維基百科：QGIS](https://zh.wikipedia.org/wiki/QGIS)　·　[English Wikipedia: QGIS](https://en.wikipedia.org/wiki/QGIS)

## 定義

QGIS 是一套自由且開放原始碼的跨平台地理資訊系統軟體。

白話說，QGIS 就是把地圖、位置資料與分析工具放在同一個工作環境中的軟體。

它可以用來開啟、編修、顯示與轉換地理資料，也能協助使用者進行空間查詢、製圖與分析。

在 QGIS 的脈絡中，[GIS] 所指的地理資訊系統，可白話理解為「能理解位置資料及其關係的電腦系統」。

QGIS 最早以 Quantum GIS 為名，後來因名稱與其他軟體相近而簡稱為 QGIS。

它不只提供地圖瀏覽功能，也是一套能處理向量資料、柵格資料及各種地理資料格式的完整工作平台。

與僅供閱讀地圖的軟體相比，QGIS 允許使用者修改圖層內容、調整符號、建立分析流程及製作符合需求的地圖。

## 白話解釋

想像一個城市規劃人員要回答「哪里的學校可能受到鐵路噪音影響」。

他不必只靠眼睛查看地圖，而是可以在 QGIS 中疊上學校分布、鐵路路線與住宅區資料。

接著，軟體會協助找出距離鐵路較近的學校，並把結果畫成容易理解的地圖。

這類「把位置關係交給電腦計算」的能力，就是地理資訊系統的核心用途。

QGIS 的角色，是把原本可能需要大量人工處理的地理資料工作，整理成可重複執行的流程。

它讓沒有大型商業預算的個人、學校、研究團隊及小型組織，也能建立專業的空間分析成果。

## 為何出現

早期GIS工作常仰賴昂貴且封閉的商業套件。

工具成本、授權限制與特定資料格式，使許多小型團體難以建立自己的地理資料工作流程。

另一方面，[GRASS] 等自由軟體提供強大的分析能力，卻不一定能讓所有使用者迅速上手。

QGIS 因此試圖在自由授權、圖形化操作、標準資料格式支援與社群擴充之間取得平衡。

它針對的主要瓶頸，是地理資訊工具取得成本高、學習入口不清楚，以及不同軟體間資料交換困難。

隨著開放資料運動與城市資料的累積，使用者也逐漸需要能在自己的電腦上檢查資料，而非只能接受別人提供的地圖成果。

QGIS 的出現，使更多人能從「資料使用者」進一步成為「資料整理者與空間分析者」。

## 前因後果

QGIS 把向量資料、柵格資料、圖層管理、符號設定與多種分析工具整合在同一介面中。

這項設計降低了初學者進入GIS領域的門檻，也讓專業使用者能以同一套環境完成資料準備到成果輸出的各階段工作。

自由且開放原始碼的特性，使程式設計師得以透過外掛機制補充特定產業或資料格式的支援。

社群因而能針對生態保育、道路管理、都市規劃與災害應變等需求，逐步形成共享的解決方案。

軟體支援多種通用地理資料格式，也有助於減少資料被單一供應商綁定的情況。

這些因素推动了GIS技能由少數專業機構向一般教育、地方社區與跨領域研究團體擴散。

使用者也更容易保存原始資料、分析步驟與最終圖面，使成果能夠被檢查、修正與重現。

QGIS 並未消除GIS工作的複雜度，但提供了較低成本的起點，讓更多元的組織能參與空間決策。

## 技術與理論的關聯

- [資料模型] 是QGIS組織資料的基礎。

  向量資料可白話理解為由點、線與面構成的地理物件。

  柵格資料則像一張由方格組成的數值影像，每格可保存高程、溫度或土地覆蓋資訊。

- 圖層可白話理解為「放在同一張透明紙上的資料」。

  QGIS 依圖層順序進行繪製，使使用者能控制哪些內容遮住其他內容。

- 拓樰可白話理解為「地理物件之間是否在空間上相接或包含」。

  QGIS能檢查面與面是否重疊、線是否跨越邊界，以及點是否落在某個面內。

- 座標參考系統決定資料如何對應到地球表面。

  若不同圖層採用的座標參考系統不一致，直接疊加可能造成位置偏移或距離失真。

- [空間分析] 將地理資料之間的位置關係轉換為可計算的結果。

  常見方法包括緩衝、疊加、鄰近分析、分類統計與路徑分析。

- 緩衝區可白話理解為「在指定物件周圍劃出一圈特定距離的範圍」。

  例如以道路中心線建立五百公尺緩衝區，可協助篩選可能受到道路影響的建築。

- 疊加分析可白話理解為「把不同主題的圖層放在一起計算」。

  例如將學校、洪水潛勢與人口分布疊加，可找出需要優先調查的地區。

- 符號系統負責把抽象資料轉換為可辨識的視覺資訊。

  顏色、線型、透明度與分類圖例能協助讀者分辨不同類別或數值範圍。

- 外掛機制讓使用者能在核心功能之外加入新的資料支援、製圖元件與分析工具。

  這種擴充方式使同一套軟體能配合不同領域的作業規範。

- 資料互通性指不同軟體與格式之間交換資料時，仍能保留主要內容。

  QGIS透過支援多種通用格式及資料庫連線，降低成果轉移與協作時的摩擦。

## 孫分類

QGIS 的使用形態可依工作環境與主要用途分成以下幾類。

| 類型 | 主要用途 | 典型工作 |
|---|---|---|
| 桌面環境 | 單一使用者進行完整的資料處理與製圖 | 編修圖層、設計符號、執行分析與輸出地圖 |
| 伺服器環境 | 將地圖與分析功能提供給多人或系統呼叫 | 發布地圖服務、支援網頁應用與批次處理 |
| 行動裝置環境 | 在外野蒐集、檢查與更新位置資料 | 記錄 GPS 點位、檢查圖層與離線作業 |
| 程式庫環境 | 讓其他程式重用地圖顯示與空間處理能力 | 嵌入地圖元件、處理格式或建立自動化流程 |

| 子類 | 與核心功能的關係 |
|---|---|
| 地圖編輯 | 協助維護[資料模型]中的點、線、面及其屬性資料 |
| 空間分析 | 提供[空間分析]所需的選取、統計與幾何運算工具 |
| 資料管理 | 支援[資料取得]後的格式轉換、清理、連結與品質檢查 |
| 地圖發布 | 將整理完成的圖層轉為圖片、地圖檔或供網頁使用的服務 |
| 外掛工具 | 依[應用領域]需求補充核心功能尚未涵蓋的工作 |

## 範例

以下是一個假設性的洪水風險篩選案例，用來說明 QGIS 如何把資料準備與空間分析串成一個流程。

情境中有一條河道、五百公尺的評估距離，以及一千兩百棟住宅建築的分布資料。

第一步是透過 [資料取得] 取得河道、住宅建築與行政區界資料。

取得後，先檢查各圖層的欄位、幾何類型與座標參考系統。

第二步是把所有需要計算距離的圖層轉換到適合當地、以公尺為單位的投影座標系統。

若直接使用經緯度計算，東西方向的距離會受到緯度影響，因此正式分析前必須先處理投影問題。

第三步是建立河道周圍五百公尺的緩衝區。

此處的五百公尺是題目設定的評估距離，實際研究應依洪水量、地形與災害規範調整。

第四步是以住宅建築中心點作為位置標記，計算哪些點位落在緩衝區內。

第五步是把重疊結果連回住宅建築的[資料模型]，並帶出地址、使用類型與結構數量等屬性。

假設計算結果如下。

| 距離河道範圍 | 建築數量 | 佔全部建築比例 |
|---|---:|---:|
| 零至二百五十公尺 | 三十一棟 | 約百分之二點六 |
| 二百五十至五百公尺 | 五十五棟 | 約百分之四點六 |
| 緩衝區外 | 一千一百十四棟 | 約百分之九十二點八 |
| 合計 | 一千二百棟 | 百分之百 |

接著可依調查優先順序，把不同距離範圍設為不同顏色。

圖面上可用深紅色表示較近的高風險區，淺紅色表示次高風險區，其餘建築則保持中性顏色。

最後輸出圖面與計算結果，並保存每一步使用的距離、座標系統及篩選條件。

這種做法的好處，是成果不只是一張漂亮地圖，也包含能夠被檢查與更新的計算紀錄。

若後續取得新的建築資料或修正河道位置，使用者可以重新執行相同流程，不必從頭手工比對。

## 操作流程

建立QGIS專案時，可先依照分析目的整理資料，而不是直接把所有檔案堆在同一資料夾中。

每個圖層應有容易辨識的名稱，並避免把暫存結果與正式成果混在一起。

進行距離分析前，應先統一量測單位與座標參考系統。

進行面對面疊加前，應先檢查是否有細碎裂隙、重複邊界或未修正的幾何錯誤。

分析結果應搭配比例尺、圖例、資料日期與方法說明，避免讀者誤讀。

涉及風險判斷時，電腦輸出的篩選結果只能作為決策依據之一，不能直接取代實地調查。

## 與相鄰分類的關聯

QGIS 屬於 [GIS軟體] 的範疇，與同類工具最大的差異之一，是其自由且開放原始碼的發展模式。

[ArcGIS] 是重要的商業GIS平台，常被大型政府機關、企業與專業服務單位採用。

它與 QGIS 都能處理向量、柵格及空間分析工作，但在授權成本、部署方式、組織支援與特定企業功能方面存在差異。

[GRASS] 同樣採自由軟體路線，其分析工具種類豐富，特別適合部分科學與專業研究工作。

QGIS 較強調容易上手的圖形化流程，而 GRASS 的部分工作流程通常需要較細緻的命令列操作與模型觀念。

兩者並非簡單的新舊替代關係，使用者仍可依研究方法、團隊能力與既有資料選擇工具。

在 [資料模型] 方面，QGIS 支援多種常見的點、線、面與柵格資料結構。

正確的模型設計仍是分析可靠性的基礎，軟體只能協助操作，不能自動消除資料本身的語意錯誤。

在 [空間分析] 方面，QGIS 提供圖形介面、處理模型、批次處理與外掛工具等不同執行方式。

同一項分析若要成為正式成果，仍須明確記錄參數、假設、資料品質與適用限制。

在 [資料取得] 方面，QGIS 可協助接收既有檔案、連接資料庫及檢查圖層資訊。

但資料來源的可信度、時效性與授權條件，仍須由使用者判斷。

從 [應用領域] 的角度看，同一套 QGIS 核心技術可被用於自然保育、都市規劃、交通管理、農業估產、公共衛生及災害風險分析。

各領域真正需要的成果不同，因此分類方式、符號設計與分析參數也必須跟著調整。

## 發展沿革

2002年，Gary Sherman 開始發展早期名為 Quantum GIS 的專案，目標是提供自由且可在一般電腦上使用的GIS工具。

早期版本聚焦於讓使用者以圖形介面操作資料，而不是只提供低階的資料轉換功能。

隨著社群參與增加，專案逐步補足符號系統、投影處理、圖層樣式與分析工具。

2013年，專案正式以 QGIS 為名，降低與其他資訊系統名稱混淆的機會。

2014年，QGIS基金會成立，推動社群治理、資金支持與長期維護。

後續版本持續強化資料庫支援、處理模型、列印排版、地圖發布及行動裝置能力。

這段沿革顯示，QGIS 已從個人研究工具發展為可被政府、教育、企業與社群共同維護的GIS平台。

## 優點與限制

QGIS 的主要優點是取得成本低、跨平台、資料格式支援廣，並具有活躍的使用者社群。

它也允許使用者透過處理模型與外掛工具建立可重複執行的工作流程。

自由軟體並不代表完全沒有維護成本，組織仍須考量人員訓練、版本管理、備份與相容性。

對部分大型組織而言，QGIS 的企業支援、治理文件及既有商業流程整合能力，可能與 [ArcGIS] 等產品有所不同。

在精確度要求極高或資料量極大的工作上，還需要依需求評估效能、服務架構與專業協助。

免費工具也能降低創新實驗成本，讓研究團隊先驗證方法，再決定是否擴充為企業級系統。

## 使用原則

應先定義問題，再選擇資料與分析方法，避免因軟體中提供某個工具就反過來設計無意义的分析。

距離、面積與密度等結果，都應交代單位、投影方式及邊界處理方法。

對每個圖層保留來源、日期、處理步驟與負責人，有助於後續更新與審核。

成果發布前，應檢查圖例、比例尺、方向標、標題、資料註記及誤導性的視覺設計。

涉及敏感位置或個人資料時，應依法律與倫理要求進行最小化蒐集及適當保護。

同一專案若要多人協作，應建立一致的檔案命名、版本保存與交接紀錄。
