# SAT求解

> 隸屬：[邏輯學] › [計算邏輯]　·　狀態：初稿

> 對應維基百科：[中文維基百科：SAT求解](https://zh.wikipedia.org/wiki/SAT)　·　[English Wikipedia: SAT solver](https://en.wikipedia.org/wiki/SAT_solver)

SAT 求解（satisfiability solving）是求解布蘭公式（CNF）是否可滿足的演算法技術。它是現代計算邏輯最成功、最普及的技術：從晶片驗證到排程、從生物資訊到軟體驗證，SAT 求解器都是核心引擎。

它的成功之道在於 **Cook-Levin 定理**：SAT 是 NP-完全問題，代表它既不弱（可表達所有 NP 問題）又不強（沒有更簡單的統一格式）。

## 一、輸入與輸出

**輸入**：一組子句，每個子句是文字（變數或其否定）的析取。

**輸出**：若可滿足，回傳一個滿足指派；若不可滿足，回傳不可滿足的證據（衝突分析）。

**範例**：

$$
(\neg x_1 \lor x_2) \wedge (\neg x_2 \lor x_3) \wedge (\neg x_1 \lor \neg x_3)
$$

求解過程：若 $x_1$ 為真，第一式得 $x_2$ ，第二式得 $x_3$ ，第三式要求 $\neg x_3$ ，矛盾；若 $x_1$ 為假，前兩式可同時滿足（例如 $x_2 = x_3 = \text{假}$ ）。故公式可滿足，指派 $x_1 = \text{假}, x_2 = \text{真}, x_3 = \text{假}$ 即為一解。

## 二、演算法的演進

| 演算法 | 年份 | 核心思想 |
| --- | --- | --- |
| DPLL | 1960 | 單純回溯 + 單位傳播 |
| WalkSAT / GSAT | 1992 | 隨機局部搜尋，只找可滿足解 |
| DPLL 的現代化 | 1990s | 子句權重、學習子句、restart |
| CDCL | 2001 | 衝突分析學習子句，決定學習 |
| Luby 序列 | 2005 | 以幾何級數序列安排重啟 |

**範例（單位傳播）**：若某子句只剩一個未賦值的文字，該文字必為真，於是可直接賦值而無需分支。CDCL 會反覆做單位傳播，直到無法再推進。

## 三、CDCL 的關鍵機制

1. **子句學習**：從衝突中推導新子句，使搜尋不重蹈覆轍。
2. **非平稱回溯**：只回溯到衝突真正需要的層級，而非全部回溯。
3. **VSIDS**：以變數在衝突中的出現次數決定分支優先序。
4. **重啟與隨機化**：定期重啟並擾動啟發式，避免陷入局部最深處。

**範例（學習子句的效果）**：若某次衝突推導出新子句 $(\neg x_1 \lor x_4)$ ，那麼未來任何把 $x_1$ 設為真的分支都會立刻導致 $x_4$ 被設為假，等於把「這條路走不通」的資訊記錄下來。

## 四、實務效能

| 面向 | 觀察 |
| --- | --- |
| 典型工業實例 | 數千到數十萬變數，可在秒級求解 |
| 最壞情況 | 指數時間（NP-完全） |
| 效能關鍵 | 編碼品質、預處理、啟發式 |
| 硬實例 | 密碼分析、組合設計等仍可能極難 |

**範例**：整數規劃問題若直接編碼成 SAT，效能往往差於專用求解器；反之，某些結構性問題（如晶片時序驗證）在 SAT 表現極佳。這說明**格式與啟發式的選擇**往往比演算法本身更決定成敗。

## 五、SAT 在各領域的應用

| 領域 | 應用 | 範例 |
| --- | --- | --- |
| 硬體驗證 | 證明不存在壞的狀態 | 檢查兩個訊號是否可能同時為真 |
| 軟體驗證 | 程式路徑的符號執行 | 找出使斷言失敗的輸入 |
| 排程與規劃 | 資源分配的可行性 | 是否能在期限內完成所有任務 |
| 密碼分析 | 密钥位的代數方程 | 找出滿足差分的位元組 |
| 生物資訊 | 蛋白質摺疊的約束 | 找出符合立體化學限制的結構 |

**範例（排程）**：把每個任務視為變數（開始時間），把「任務 A 必須在 B 之後」寫成子句 $(\neg s_B \lor s_A)$ ，把資源上限寫成子句組，整個排程問題即成為 SAT 實例。

## 六、與相鄰分類的關聯

- [邏輯與電腦]：形式化驗證的應用面。

## 七、容易混淆之處

- SAT 求解器**不保證**快速解決，它在 NP-完全問題上無多項式保證。
- 「SAT」在此指布蘭公式可滿足性，與其他領域的縮寫無關。
