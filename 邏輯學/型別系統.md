# 型別系統

> 隸屬：[邏輯學] › [邏輯與電腦]　·　狀態：初稿

> 對應維基百科：[中文維基百科：型別系統](https://zh.wikipedia.org/wiki/%E9%A1%9E%E5%9E%8B%E7%B3%BB%E7%B5%B1)　·　[English Wikipedia: Type system](https://en.wikipedia.org/wiki/Type_system)

型別系統（type system）是一套規則，藉由賦予程式元件「型別」來約束其組合方式。從 Curry-Howard 對應來看，型別系統就是以類型語言寫成的邏輯系統：型別檢查器正是一個證明檢查器。

它的歷史路線是：lambda 演算 → 簡單型別 →  Hindley-Milner 推論 → 依賴型別與線性型別，每一步都換來更強的靜態保證。

## 一、型別的三種保證

| 保證 | 例子 | 對應邏輯 |
| --- | --- | --- |
| 型別安全 | 不會把整數當字串用 | 命題蘊涵 |
| 資源安全 | 不會重複釋放、不會洩漏 | 線性邏輯 |
| 終止性 | 迴圈必定結束 | 量詞／下降序 |

**範例（型別決定終止性）**：

```text
while (x != 0) { x = x - 1 }
```

若 $x$ 為整數，迴圈必定終止；若 $x$ 為實數，則可能無限逼近 0 而不終止。**型別資訊直接決定了可判定性**，這是用邏輯處理計算行為的典型例子。

## 二、簡單型別與 lambda 演算

**範例**：以簡單型別 $\lambda$ 演算表達的函式 $(\lambda x. x + 1)$ 只能接受整數。這類型別系統的基本性質：

- **型別保持**：若 $t : T$ 且 $T$ 為良型，則求值結果仍為 $T$ 。
- **型別安全**：良型程式的求值不會陷入型別錯誤。

**範例（不可定型式）**：在未加型別的 lambda 演算中， $(\lambda x.\ x\ x)$ 無法求值——把 $x$ 套用到自身會無限展開。加上型別後，此式因無法推導出合法型別而被拒絕。

## 三、多型與 Hindley-Milner

**範例（多型）**：恆等函式 $\lambda x.\ x$ 在多型系統中可推導出 $\forall a.\, a \to a$ ，同一份碼同時適用於整數與字串。

Hindley-Milner 系統提供**型別推論**：不需要標註型別，檢查器自行推導，並能證明類型安全。

**範例**：程式 `let id = fun x -> x in ...` 不需任何型別標註；推論器會給出最一般化的型別 $\forall a.\, a \to a$ 。

## 四、線性型別與資源

線性型別（linear type）規定每個值恰被使用一次，源自線性邏輯（每個前提與結論恰用一次）。

| 保證 | 機制 |
| --- | --- |
| 不會洩漏資源 | 資源必須被釋放 |
| 不會重複使用 | 使用即消耗 |
| 不會資料競爭 | 所有權唯一 |

**範例（Rust 的所有權）**：Rust 的借用檢查器實踐線性型別的資源觀念——每個值有唯一擁有者，轉移所有權即轉移資源，借用則有期限限制。這使「use after free」與「data race」在編譯期被排除。

## 五、依賴型別

**範例（依賴型別的威力）**：型別可依賴項的值，使得「向量長度等於索引」這類不變量成為型別的一部分：

```text
Vector : Nat -> Type
index : (n : Nat) -> Vector a n -> a
```

在此系統中，取出超出長度的元素不是執行期錯誤，而是**無法通過型別檢查**。這正是 [邏輯與電腦] 中 Curry-Howard 對應的深層應用：把命題寫成型別。

## 六、與相鄰分類的關聯

- [程式驗證]：型別是最自動化的驗證手段。
- [定理證明器]：型別系統的理論極致是依賴型別。
- [形式化驗證]：型別檢查是其中一環。
- [直覺邏輯]：依賴型別的理論基礎是直覺式邏輯。
- [模型語意]：型別語意即模型語意。

## 七、容易混淆之處

- 型別檢查通過**不等於**程式符合規格，只保證型別系統表達的性質。
- 「動態型別」與「靜態型別」是**檢查時機**的差異，不是強弱差異。
