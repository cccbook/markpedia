# 貪心與分治

> 隸屬：[演算法]　·　狀態：初稿

> 對應維基百科：[中文維基百科：貪心算法](https://zh.wikipedia.org/wiki/%E8%B4%AA%E5%BF%83%E7%AE%97%E6%B3%95)　·　[English Wikipedia: Greedy algorithm](https://en.wikipedia.org/wiki/Greedy_algorithm)

貪心與分治是兩種最常見的演算法設計典範。**貪心法**每一步都做當下看起來最好的選擇，永不回頭；**分治法**把問題分解成同類型的子問題分別解決，再把結果合併。兩者都源於「局部結構決定全域結果」的直覺，但成立條件完全不同。

貪心法的危險正在於它的直覺常常很誘人：局部最優往往不等於全域最優，因此每一個貪心演算法都必須附上交換論證或貪心選擇性質的證明，否則它只是「看起來能跑」。分治法則相對穩健：只要子問題獨立且合併正確，結果即可遞迴地保證。

## 技術與理論的關聯

- **貪心選擇性質**：存在一個最優解以貪心選擇為其第一步選擇，這是貪心法可證明性的核心。
- **交換論證**：把最優解中的某個元素換成貪心選擇，證明不變差，是多數貪心演算法（如 [最小生成樹] 的 Prim 演算法）的證明方式。
- **分治的遞迴式**： $T(n) = aT(n/b) + f(n)$ 描述「分成 a 份、每份規模 n/b」，Master 定理直接給出複雜度。
- **合併階段是關鍵**：分治的效率不只在分解，更在合併；合併排序的合併是線性的，套用合併排序的遞迴式即得 $O(n \log n)$ 。
- **近似演算法的位置**：當貪心法沒有可證明的最優性時，可用它構造近似解，並用 [近似比] 量化保證。
- **適用邊界**：區間排程、活動選擇、部分背包等具備貪心選擇性質的問題適合貪心法；0/1 背包與最短路徑等則不適合，必須用 [動態規劃] 或 [圖演算法]。

## 範例

**問題**：以分治法求兩個排序陣列的中位數，並比較兩種常見寫法的成本。

```
def median_of_two_sorted(a, b):
    # a、b 皆為已排序陣列
    if not a or not b:
        raise ValueError("empty input")
    m, n = len(a), len(b)
    half = (m + n) // 2
    # 以 partition 概念決定切割點
    ...
```

1. **核心想法**：不實際合併兩個陣列（那是 $O(m + n)$ ），而是找出「切割點」，使左半邊的總數恰為 `half` 且左邊所有元素不大於右邊所有元素。
2. **切割點的求解**：在 `a` 中取一個候選分割點，對 `b` 用二分搜尋找出對應位置，判斷是否恰好平衡；這把每次求解的時間壓到 $O(\log \min(m, n))$ 。
3. **遞迴或迭代**：若不平衡，調整候選分割點再試；實務上常用迭代避免遞迴深度。
4. **整體複雜度**： $O(\log \min(m, n))$ 的時間、 $O(1)$ 的額外空間；相較合併後取中位數的 $O(m + n)$ ，在兩陣列皆極大時差距顯著。
5. **貪心的對照**：類似的「先合併再處理」直覺若用貪心逐段挑選，會得到錯誤結果；分治之所以有效，是因為它把「切割」問題縮小到可在對數步驟內確定。

**貪心法的對照例子**：給定硬幣面額 1、3、4 與金額 6，貪心地每次取最大的面額會得到 4 + 1 + 1 = 6（3 枚），而最佳解是 3 + 3（2 枚）。貪心法在此失敗，因為面額集合不滿足貪心選擇性質。

## 前因後果

- **前因**：分治的思想可追溯至 [高斯] 對快速排序的開創性工作（排序演算法中的分治典範）與古老的「以大化小」算術技巧；貪心法的系統化則來自 1950 至 1970 年代排程與網路路由的實務需求。
- **後果**：分治法成為資料結構（平衡樹、堆）、排序（快速排序、合併排序）與並行計算（MapReduce 式分塊）的基本骨架；貪心法則在資源配置、排程與近似解中持續發揮作用。

## 與相鄰分類的關聯

- 與 [基本演算法] 的關聯：快速排序與二分搜尋是分治法的代表；分治也常用來改進基本演算法的複雜度。
- 與 [演算法基礎] 的關聯：遞迴式與 Master 定理是分治法複雜度分析的直接工具。
- 與 [演算法的可證明性] 的關聯：貪心法的正確性靠交換論證與不變量，NP 完全理論則說明了何時必須放棄精確解而改用近似。
- 在上位概念 [演算法] 中，本子分類提供兩條最重要的通用設計典範，與 [圖演算法] 的領域專用解法互補。

## 容易混淆之處

- **貪心不等於「每次隨便挑一個」**：貪心要求有可證明的選擇性質，否則只是啟發式。
- **分治不等於遞迴**：分治強調「分解為獨立同類子問題並合併」，遞迴只是實作手段。
- **近似演算法不等於貪心**：近似解可以來自貪心、隨機化或元啟發式，關鍵在於有 [近似比] 保證。
- **貪心與分治可以併用**：如部分背包先用貪心求上界，再用分治或動態規劃求精確解。

## 技術要點

- 分治法要求子問題獨立；若子問題彼此重疊，應改用 [動態規劃] 以共享計算。
- 合併階段的複雜度常是瓶頸，合併排序的線性合併即是最佳化範例。
- 隨機化枢紐讓快速排序的最壞情況機率降到極低，是實務標準做法。
- 貪心演算法通常容易實作但難以證明，論證成本往往高於程式碼量。
- 近似比是近似解與最優解的比值，越接近 1 越好；2-近似在某些圖問題上已是最佳可能。
- 分治與並行天然契合：子問題之間通常無共享狀態，可同時在多核心執行。

## 常見的論爭

- **貪心法在教學中是否過度強調**：批評者指出初學者常把貪心法當萬靈藥，忽略其適用條件；支持者認為它是培養「交換論證」能力的重要訓練。
- **啟發式與近似解的界線**：工程界常混用兩者，以至於「有保證的近似」與「跑起來快的啟發式」常被混為一談。
- **分治是否被並行化趨勢取代**：雲端環境偏愛資料並行的 map-reduce 風格，但分治的遞迴結構仍是理解並行的最佳心智模型。
