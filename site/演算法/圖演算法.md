# 圖演算法

> 隸屬：[演算法]　·　狀態：初稿

> 對應維基百科：[中文維基百科：图论](https://zh.wikipedia.org/wiki/%E5%9B%BE%E8%AE%BA)　·　[English Wikipedia: List of algorithms](https://en.wikipedia.org/wiki/List_of_algorithms)

圖演算法處理的是**以頂點與邊表達的關係結構**：社群網路的人際關係、道路網的交通路徑、任務之間的先後依賴、電路元件的連接，都可以抽象成圖。圖演算法的目標，是回答這類結構上的典型問題——誰能最快到達誰？哪些邊可以刪掉仍連通？任務能否排定順序？流量最大能送多少？

與陣列上的演算法不同，圖演算法的複雜度幾乎完全取決於**圖的形狀**而非元素數量。同一個演算法在鏈狀圖與稠密圖上可能相差數個數量級，因此選擇演算法前必須先理解資料的拓樸特徵。

## 技術與理論的關聯

- **圖的表示**：鄰接矩陣佔 $O(n^2)$ 空間但查鄰居為 $O(1)$ ；鄰接清單佔 $O(n + m)$ 空間，適合稀疏圖，是實務主流。
- **遍歷是基礎**：廣度優先搜尋求最短路徑（在無權圖中）與層級，深度優先搜尋求連通分量、拓樸結構與回溯列舉。
- **帶權圖的最短路徑**：Dijkstra 演算法處理非負權，時間 $O((n + m) \log n)$ ；負權邊則需 Bellman–Ford 演算法或以 [分治策略] 觀念處理的負權變體。
- **生成樹**：最小生成樹可用 Prim（以堆）或 Kruskal（以並聯集）達成，皆為 $O(m \log n)$ ，連帶解決了「最小成本連通所有城市」的問題。
- **拓樸排序**：有向無環圖的線性排序，同時也是偵測環的演算法；循環依賴即「無合法的執行順序」。
- **最大流**：以容量限制流動的上界，與最小割對偶，最小割問題的強多項式演算法來自此領域。

## 範例

**問題**：以廣度優先搜尋求無權圖中兩點間的最短路徑。

```
from collections import deque

def shortest_path(graph, start, goal):
    prev = {start: None}
    queue = deque([start])
    while queue:
        node = queue.popleft()
        if node == goal:
            break
        for nxt in graph[node]:
            if nxt not in prev:
                prev[nxt] = node
                queue.append(nxt)
    if goal not in prev:
        return None
    path = []
    cur = goal
    while cur is not None:
        path.append(cur)
        cur = prev[cur]
    return path[::-1]
```

1. **為何有效**：廣度優先依「層數」展開，第 $k$ 層的頂點距起點恰為 $k$ 步；因此第一次被拜訪時即為最短距離，這是不變量。
2. **複雜度**：每個頂點最多入列一次、每條邊最多被檢查兩次，時間為 $O(n + m)$ 、空間為 $O(n)$ 。
3. **與 Dijkstra 的關係**：把每條邊的權重設為 1，Dijkstra 就退化成廣度優先搜尋；有權圖則必須用堆把「已確認最小距離」的節點優先取出。
4. **重建路徑**：`prev` 字典記錄每個頂點的 predecessor，回溯即得路徑；若目標未被拜訪，表示起點與目標不連通。
5. **實際用途**：社群網路的「共同朋友數」、遊戲的尋路格子、服務網路的相依解析，都建立在這類遍歷之上。

## 前因後果

- **前因**：萊布尼茲在 17 世紀就思考過七橋問題；[1959年] [狄克斯特拉] 針對交通網提出最短路徑演算法，使圖方法成為可工程化的工具。
- **後果**：圖方法如今支撐道路導航、依賴解析、編譯器的符號表處理、社交推薦、網路流量路由與知識圖譜；[拓樸排序] 更直接對應到專案排程與建置系統的相依解析。

## 容易混淆之處

- **最短路徑與最小生成樹不同**：前者最小化特定兩點間的路徑權重總和，後者最小化連通所有頂點所需的邊總權重。
- **有權圖不能用廣度優先搜尋**：帶權圖需 Dijkstra 或類演算法，否則得到的未必是最短路徑。
- **拓樸排序要求有向無環**：一般圖可能沒有合法的排序，需先偵測環。
- **最大流不處理負容量**：容量必須非負，負容量需以其他方式轉換。
- **演算法複雜度與圖的表示綁定**：稀疏圖用鄰接矩陣會浪費大量空間。

## 技術要點

- Dijkstra 演算法使用優先佇列時，時間複雜度為 $O((n + m) \log n)$ ；使用陣列則退化為 $O(n^2)$ 。
- Bellman–Ford 演算法能偵測負權環，並以 $n - 1$ 輪 relaxation 完成。
- Kruskal 演算法需要並聯集（union-find）資料結構支援近乎常數的連通性查詢。
- 拓樸排序可用 Kahn 演算法（反覆取出入度為 0 的頂點）或以深度優先搜尋的完成順序反向輸出。
- 對偶性指出最大流值等於最小割容量，這是演算法理論中少數精確的對偶定理。
- 稀疏圖的實務規模常達數十億個頂點，需依賴平行化與外部記憶體演算法。

## 常見的論爭

- **演算法實現是否應隱藏細節**：實務上「最短路徑」常被封裝成高階 API，工程師難以察覺負權邊等陷阱，掩蓋了演算法前提條件的重要性。
- **專用與通用演算法的取捨**：為特定場景客製的演算法（如時間軸索引）常遠快於通用解，但通用性與可維護性下降。
- **圖資料庫與關聯式資料庫之爭**：前者以圖為一等公民加速關聯查詢，後者以成熟的事務與工具勝出，實務上常並存。
