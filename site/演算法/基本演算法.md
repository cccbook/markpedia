# 基本演算法

> 隸屬：[演算法]　·　狀態：初稿

> 對應維基百科：[中文維基百科：算法](https://zh.wikipedia.org/wiki/%E7%AE%97%E6%B3%95)　·　[English Wikipedia: Algorithm](https://en.wikipedia.org/wiki/Algorithm)

基本演算法是**幾乎所有實務系統都會用到的核心构件**：把資料排好序以利搜尋與合併，把目標找出來以利處理，把結構化的關係以圖的演算法求解，把重疊子問題系統性地壓縮成表格。它們不是「入門用的簡單演算法」，而是像螺絲釘與鉚釘一樣被反覆組裝的零件。

這些演算法共同承擔一項工程責任：**把「看起來得逐一檢查」的問題，轉成「可以做結構化搜尋」的問題**。資料量成長時，這個轉換帶來的不是線性的改善，而是量級的改變。

## 技術與理論的關聯

- **排序的樞紐**：比較式排序的下界是 $\Omega(n \log n)$ ，由決策樹模型給出；任何排序演算法都無法突破此下界。
- **非比較式排序**：計數排序與 Radix 排序利用鍵值的結構而非比較，可達 $O(n + k)$ ，但需要鍵值落在有限範圍且可索引。
- **搜尋的兩條路**：有序資料可用二分搜尋達 $O(\log n)$ ；雜湊表則以 $O(1)$ 的期望時間換取空間與較差的最壞情況。
- **圖的兩種基本遍歷**：廣度優先搜尋求最短路徑（在無權圖中）並求層級，深度優先搜尋則適合拓樸結構、連通分量與回溯列舉。
- **動態規劃的三要素**：最佳子結構、重疊子問題與遞推關係；缺少最佳子結構時通常改用 [貪心與分治] 或啟發式方法。
- **表格法的代價**：動態規劃以空間換時間，狀態數為 $S$ 時需 $O(S)$ 空間與 $O(S)$ 時間，是典型的多項式時間演算法。

## 範例

**問題**：以動態規劃求「0/1 背包問題」：給定重量與價值的物品，在容量限制下取總價最大。

```
def knapsack(items, capacity):
    # dp[w] = 容量 w 以內能得到的最大總價
    dp = [0] * (capacity + 1)
    for weight, value in items:
        for w in range(capacity, weight - 1, -1):
            dp[w] = max(dp[w], dp[w - weight] + value)
    return dp[capacity]
```

1. **狀態定義**：`dp[w]` 表示只使用已處理物品、總重量不超過 $w$ 時的最大總價；這是動態規劃的不變量。
2. **遞推關係**：對每件物品（重量 $v$ 、價值 $p$ ），有 `dp[w] = max(dp[w], dp[w - v] + p)`，即「不拿」與「拿」兩種情形取較優。
3. **為何迴圈必須倒序**：若正序更新，`dp[w - v]` 可能已被當前物品更新過，導致同一件物品被重複計算；倒序確保狀態來自「尚未考慮本物品」的舊值，這正是 0/1 背包與完全背包的唯一差別。
4. **複雜度**：物品數 $n$ 、容量 $C$ 時，時間 $O(nC)$ 、空間 $O(C)$ ；與貪心法按價值密度排序的 $O(n \log n)$ 相比，動態規劃更慢但結果一定正確。
5. **對照搜尋**：若先用排序再搜尋，把「找最大值」化為「在有序陣列中找邊界」，複雜度從逐一檢查的 $O(nC)$ 降為 $O(n \log n)$ ——這是排序作為共用零件的價值所在。

## 前因後果

- **前因**：19 世紀的差分機需要先把對數表排序輸出，排序是演算法史上最早的實務需求；此後資料管理的規模化讓搜尋與排序成為系統性問題。
- **後果**：排序與搜尋演算法被硬編進作業系統、資料庫與資料庫索引（B 樹）、作業系統排程器與壓縮器的字典設計；動態規劃則在序列對齊、編碼理論與資源排程中成為標準手段。

## 與相鄰分類的關聯

- 與 [演算法基礎] 的關聯：所有基本演算法都必須以正確性與複雜度的語言描述，本子分類提供實例。
- 與 [貪心與分治] 的關聯：排序中的快速排序即分治法的典型；貪心法與動態規劃則是同一問題的兩種取捨。
- 與 [圖演算法] 的關聯：圖演算法中的廣度優先與深度優先搜尋，正是本子分類搜尋概念在圖結構上的延伸。
- 在上位概念 [演算法] 中，本子分類扮演工具箱角色：其餘子分類的工具多半由這裡的基本构件組合而成。

## 容易混淆之處

- **穩定排序與不穩定排序**：穩定排序保持等鍵元素的相對順序，對多重鍵排序很重要。
- **原地與非原地**：原地排序額外空間為 $O(1)$ 或 $O(\log n)$ ，非原地如合併排序需 $O(n)$ 。
- **雜湊表的 $O(1)$ 是期望值**：最壞情況退化為 $O(n)$ ，攻擊者可藉此製造碰撞。
- **動態規劃不是「動態記憶體」**：前者是演算法範式，兩者同名易造成誤解。
- **二分搜尋要求隨機存取**：陣列可以，磁碟與串流的順序存取不可以。

## 技術要點

- 內插搜尋在資料均勻分布時期望 $O(\log \log n)$ ，但最壞仍為 $O(n)$ 。
- Timsort 結合插入排序與合併排序，在部分有序的實務資料上接近 $O(n)$ ，是主流語言的預設排序。
- 快速排序的枢紐選擇影響最壞情況，隨機化或三路分割可有效對抗對手。
- 雜湊表選用質數模數並以線性同餘產生雜湊值，碰撞則以鏈式或開放定址處理。
- 動態規劃的狀態設計是關鍵：狀態數爆炸是實作時最常見的失敗原因。
- B 樹與 B+ 樹把排序與搜尋合而為一，是資料庫索引的實作基礎。

## 常見的論爭

- **何時該用排序後搜尋，何時該用雜湊**：資料庫索引普遍採有序結構以支援範圍查詢，但純等值查詢用雜湊索引可能更快，實務上兩者並存。
- **穩定性的重要性**：過去常被視為次要，但多鍵排序與合併外部檔案時，穩定性直接決定結果是否可預期。
- **實務是否應自己寫排序**：多數語言提供高度最佳化的內建排序，自行實作往往效能更差且更容易出錯。
