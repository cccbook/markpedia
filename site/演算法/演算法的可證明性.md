# 演算法的可證明性

> 隸屬：[演算法]　·　狀態：初稿

> 對應維基百科：[中文維基 wikipedia：算法](https://zh.wikipedia.org/wiki/%E7%AE%97%E6%B3%95)　·　[English Wikipedia: Algorithm](https://en.wikipedia.org/wiki/Algorithm)

演算法的可證明性研究**如何為演算法建立可信的正確性論證**，以及**在何種情況下這樣的論證不可能存在**。前者由 [迴圈不變量] 與 [終止性] 這類技術構成；後者由 [NP完全] 與 [近似比] 這類理論邊界構成。兩者共同回答一個務實問題：當我說「這個演算法是對的、夠快的」時，我到底有什麼依據？

這個子分類的存在是因為實務上「跑出來的結果正確」不等於「對所有輸入都正確」。測試只能覆蓋少數案例，而可證明性提供的是對無限多輸入的保證。當演算法被用在安全-critical系統或金融結算上時，這個區別具有決定性的意義。

## 技術與理論的關聯

- **迴圈不變量**：在迴圈體之前與之後都成立的命題，是歸納法在程式上的對應物；證明它「初始化成立、保持、被破壞」即得正確性。
- **前後置條件**：以「呼叫前必須成立」與「呼叫後保證成立」描述介面，使模組化推理成為可能。
- **終止性**：良基歸納法給出遞迴終止的判準；迴圈則以變數的整遞減或字典序遞減證明。
- **NP 完全性**：[1971年] [科布漢] 定理表明，只要能解決一個 NP 完全問題，就能解決所有 NP 問題；這解釋了為何某些問題沒有已知的多項式時間精確解。
- **近似比**：在無法精確求解時，用「解的品質保證」取代「精確解」，是工程上最務實的退路。
- **可驗證性與實作的落差**：形式化證明只覆蓋被證明的部分，實際程式與規格之間的落差仍是錯誤的主要來源。

## 範例

**問題**：證明二分搜尋（遞迴版本）的正確性與終止性。

```
def bsearch(a, key, lo, hi):
    # 前置條件：a 已排序，lo <= hi
    if lo > hi:
        return -1
    mid = (lo + hi) // 2
    if a[mid] == key:
        return mid
    if a[mid] < key:
        return bsearch(a, key, mid + 1, hi)
    return bsearch(a, key, lo, mid - 1)
```

1. **不變量**：每次遞迴進入時，區間 $[lo, hi]$ 內若存在 key，其位置必在此區間內。初始時區間為整個陣列，顯然成立。
2. **保持**：比較 `a[mid]` 後，若 `a[mid] < key`，由排序性可知 key 必在 `mid + 1` 與 `hi` 之間，新區間仍包含所有可能解；若 `a[mid] > key` 同理。故不變量被保持。
3. **後置條件**：當 `lo > hi` 時區間為空，依不變量可知 key 不在陣列中，故回傳 $-1$ 正確；當 `a[mid] == key` 時回傳 `mid` 正確。
4. **終止性**：每次遞迴的區間長度至少減半，屬於整數上的良基遞減，因此呼叫次數有限，終止性成立。
5. **複雜度**：由終止性與每次規模減半，得遞迴式 $T(n) = T(n/2) + c$ ，解為 $O(\log n)$ ；可見正確性論證與複雜度分析共用同一組結構性理由。

## 前因後果

- **前因**：19 世紀以來數學家即以歸納法論證演算法；20 世紀的形式語言與自動證明研究，把「正確性」從人工事後驗證轉為可機械檢查的對象。
- **後果**：[1971年] [科布漢] 定理確立 NP 完全性，使「哪些問題可以有效求解」有了結構性答案，直接催生密碼學的對稱與非對稱設計分野，也讓 [近似演算法] 成為獨立的研究領域。

## 容易混淆之處

- **形式化證明與測試不同**：測試是抽樣，證明是全稱命題；兩者互補而非替代。
- **NP 完全不等於不可解**：它只表示目前沒有已知的多項式時間精確解，而非證明不存在。
- **近似比不等於啟發式**：有 [近似比] 保證的解與經驗調參的解，可信度天差地別。
- **不變量不必唯一**：同一演算法可以有多個不變量，選擇容易證明的那個是技巧的一部分。
- **終止性與正確性是兩件事**：一個永遠不終止但從不給錯答案的演算法，仍是壞演算法。

## 技術要點

- 歸納法是迴圈與遞迴論證的共同骨架：不變量成立、保持、被破壞。
- 後置條件描述「做完之後世界如何」，是模組之間推理的介面語言。
- 良基關係（無窮遞降）是終止性證明的標準工具。
- NP 完全性是「可歸約性」的性質：證明一個問題屬於 NP 完全只需兩步。
- 近似比的定義需區分最大化與最小化問題，方向相反。
- 驗證與確認（verification 與 validation）不同：前者問「做得對嗎」，後者問「做的是對的東西嗎」。

## 常見的論爭

- **形式化方法的成本效益**：支持者認為驗證成本可被缺陷成本抵銷，批評者認為實務專案難以負擔形式化的前期投入。
- **平均案例複雜度的重要性**：在 NP 難問題上，實務資料往往「幾乎是容易的」，因此以最壞情況為基準的理論與實務感受落差明顯。
- **啟發式的地位**：隨機化與啟發式方法在實務中屢屢勝過可證明的方法，引發「理論應否更貼近實務資料分布」的討論。
