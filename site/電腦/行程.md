# 行程

> 隸屬：[電腦] › [作業系統]　·　狀態：初稿

> 對應維基百科：[中文維基百科：行程](https://zh.wikipedia.org/wiki/%E8%A1%8C%E7%A8%8B)　·　[English Wikipedia: Process (computing)](https://en.wikipedia.org/wiki/Process_%28computing%29)

行程是**「一個執行中的程式」在作業系統裡的化身**。程式是磁碟上的靜態檔案，行程是它被載入記憶體後的動態實例：擁有自己的位址空間、開啟的檔案、排程優先權與執行狀態。作業系統用行程實現兩件事——保護（一個行程不能讀寫另一個的記憶體）與資源分配（CPU、記憶體、檔案都記在行程帳上）。

行程的核心是**上下文**：程式計數器、暫存器、堆疊、記憶體映射的快照。排程器在行程之間切換上下文，一秒可達數百次，單一 CPU 上的「同時執行」是切換造成的錯覺。

## 技術與理論的關聯

- **行程狀態機**：就緒、執行、阻塞三態（加上新建與終止共五態）；I/O 等待時轉阻塞，讓出 CPU。
- **排程器**：從 FCFS、最短工作優先到 Linux 的 CFS（以虛擬執行時間公平分配），目標是在吞吐量、回應延遲與公平之間取平衡。
- **上下文切換的成本**：保存暫存器、切換分頁表（TLB 失效）合計約數微秒；太頻繁的切換本身成為負載。
- **行程間通訊（IPC）**：管道、訊息佇列、共享記憶體、socket；共享記憶體最快（資料零拷貝），管道最簡單。
- **執行緒與行程的對比**：執行緒共享位址空間、切換更便宜，但共用資料需要同步；行程隔離強、通訊成本高。
- **行程的生命週期**：fork（複製）+ exec（替換內容）的 UNIX 模式，或 Windows 的 CreateProcess 一體式模式。

## 範例

**問題**：shell 執行 `wc -l < report.txt` 時，作業系統做了哪些事？

1. **fork**：shell（例如 bash）呼叫系統呼叫 `fork()`，核心複製自己一份子行程——記憶體以寫時複製共享，先不真的拷貝頁面。
2. **重導向**：子行程開啟 report.txt 並複製其描述符到標準輸入。
3. **exec**：子行程呼叫 `execve("/usr/bin/wc", ...)`，位址空間被替換為 wc 程式；行程 ID 不變，這是 fork+exec 的精妙：先複製再替換，管道與重導向因此自然成立。
4. **排程執行**：排程器把 CPU 給子行程；wc 讀輸入、計數、輸出結果到標準輸出。
5. **等待與收割**：shell 以 `wait()` 阻塞自己，子行程結束時留下退出碼，shell 收割後顯示提示符。
6. **並行對照**：若是 `cmd1 | cmd2 | cmd3`，shell fork 三次並以管道連接三個行程——單核機器上它們輪流執行，多核機器上真正並行；兩者外觀一致，這正是抽象的力量。

## 前因後果

- **前因**：批次處理時代的「一次一個工作」造成 CPU 空轉；MIT CTSS（1961）首次示範分時多工，UNIX 把行程模型簡化到可用 shell 組合。
- **後果**：行程模型直接塑造了程式語言的程序與執行緒概念；容器與虛擬機是行程隔離概念的延伸（namespace 把「哪個資源屬於你」再往上抽象一層）。

## 與相鄰分類的關聯

- 與 [中斷] 的關聯：計時器中斷是排程器介入的節拍器。
- 與 [程序同步] 的關聯：行程共用資料時的競態與死結都在此處理。
- 與 [檔案系統] 的關聯：開啟檔案表是行程資源的一部分，描述符是行程與檔案系統的介面。
- 在上位概念 [作業系統] 中，行程是最核心的抽象。

## 容易混淆之處

- **行程與程式不同**：程式是檔案，行程是執行實體；一個程式可同時有十個行程。
- **行程與執行緒不同**：執行緒是排程單位、共享記憶體；行程是資源單位、記憶體隔離。
- **並行與平行不同**：單核多行程是並行（交錯），多核多行程是平行（同時）。
- **殭屍行程不是還在執行的行程**：它已終止、只待父行程收割；孤兒行程才會被 init 收養。

## 技術要點

- fork 以寫時複製讓「複製」近乎零成本，頁面在第一次寫入時才真的拷貝。
- 退出碼 0 慣例上代表成功，shell 腳本以 `$?` 檢查。
- 管道是半雙工位元組流，shell 的 `|` 就是它的語法糖。
- 訊號（SIGKILL、SIGTERM、SIGINT）是行程層的異步通知機制。
- 優先權反轉問題（低優先權持鎖、高優先權等待）以優先權繼承解法聞名（火星探路者故障）。
- cgroup 可為一組行程限定 CPU、記憶體用量，是容器的地基。

## 常見的論爭

- **fork+exec 的去留**：傳統 UNIX 模式靈活但複雜，Microsoft 與部分研究者主張 spawn 式更簡單，UNIX 陣營以組合性反駁。
- **多程序對多執行緒**：執行緒切換便宜但易出資料競態，Go、Rust 以更安全的執行緒模型改變天平，經典的「共享狀態的罪」論爭仍在。
- **排程公平的定義**：公平是指時間均分（CFS）還是指重要者先（即時系統的固定優先權），不同工作負載給不同答案。

## 實務補充：行程與執行緒

行程是資源保護的基本單位：每個行程擁有獨立的位址空間與檔案描述符表，因此崩潰時不會拖垮他人。執行緒則是排程單位，同一行程內的執行緒共享記憶體，通信便宜但需要顯式同步。

主流系統採「一個行程多執行緒」模型，並提供兩種對應關係：POSIX 執行緒與核心執行緒一一對應（1:1），Windows 的線程模型與核心執行緒是多對多（1:N）。前者效能與可預測性較好，後者在大量執行緒場景省記憶體。

排程器的目標是公平與反應性。分時系統讓每個行程在時間片輪轉；即時系統則用期限優先或速率優先排程，保證關鍵任務在截止時間前完成，寧可犧牲一般任務。
