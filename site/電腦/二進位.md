# 二進位

> 隸屬：[電腦] › [資料表示]　·　狀態：初稿

> 對應維基百科：[中文維基百科：二進位](https://zh.wikipedia.org/wiki/%E4%BA%8C%E8%BF%9B%E5%88%B6)　·　[English Wikipedia: Binary number](https://en.wikipedia.org/wiki/Binary_number)

二進位是**只使用 0 與 1 兩個符號的記數系統**。電腦選擇二進位的理由不在數學優雅，而在物理便宜：一個只有「導通與關斷」「高電位與低電位」兩種穩定狀態的元件最容易製造、最抗雜訊。所有更高進位都可以用二進位組合出來，因此「以最笨的元件組出最聰明的系統」成為整個數位工程的策略。

二進位不只是表示數值，更是表示一切的語言：布林代數的邏輯運算、位元的集合操作、狀態機的編碼，全都以 0 與 1 為原子。學會「用位元思考」是理解硬體與底層軟體的入門票。

## 技術與理論的關聯

- **位置記法**：第 $k$ 位的權值是 $2^k$ ，因此任何非負整數可唯一表示為位元串。
- **布林代數的對應**：AND、OR、NOT 與進位的「進上去」規則結合，構成加法器電路；半加器由一個 XOR（本位和）與一個 AND（進位）組成。
- **二補數**：負數表示為「取反加一」，使加法器同時承擔減法，硬體不需另造減法電路。
- **移位即乘除**：左移一位等於乘 2、右移一位等於除 2（捨去小數），編譯器把乘除以 2 的冪最佳化成移位指令。
- **位元運算當集合**：一個 32 位元字可當 32 元素集合的特徵向量，`x & (1<<i)` 測試、`x | (1<<i)` 加入，是權限與旗標管理的標準手法。
- **十六進位是二進位的速記**：每 4 位元對應一個十六進位數字，程式設計師閱讀 `0xFF` 比閱讀 11111111 快得多。

## 範例

**問題**：把十進位 45 轉成二進位、做一次二進位加法、並用移位求 45×4。

1. **轉換（連除法）**：45÷2=22 餘 1；22÷2=11 餘 0；11÷2=5 餘 1；5÷2=2 餘 1；2÷2=1 餘 0；1÷2=0 餘 1。餘數由下往上讀：`101101`。
2. **驗證**： $32 + 8 + 4 + 1 = 45$ ，對應第 5、3、2、0 位為 1。
3. **二進位加法**：45 + 7：`0101101` + `0000111`。從低位起：1+1=0 進 1；0+1+進1=0 進 1；1+1+進1=1 進 1；1+0+進1=0 進 1；0+0+進1=1；1+0=1；0+0=0。結果 `1011100` = 52 = 45+7，正確。
4. **移位乘法**：45×4 = `101101` 左移兩位 = `10110100` = 180；右移兩位則得 11（45÷4=11.25 捨去小數）。
5. **位元集合法**：以位元組表示「星期一、三、五可用」：`00101010`；查詢星期三是否可用：`x & 0b00001000` 非 0 即真——一行程式完成集合查詢。
6. **十六進位速記**：`101101` 補成 `0010 1101` = `0x2D`，四位一組一目了然。

## 前因後果

- **前因**：萊布尼茲在 1679 年就研究過二進位算術並注意到《易經》卦象的對應；19 世紀 [布爾] 把邏輯代數化，為二進位提供運算規則；香農 1937 年的碩士論文證明開關電路可實現布林代數，二進位從此有了電子身體。
- **後果**：二進位成為所有數位系統的底層；錯誤偵測（同位元）、糾錯碼、密碼學與資料壓縮全部建立在位元操作之上。

## 容易混淆之處

- **二進位與二補數不同**：前者是記數系統，後者是帶符號整數的表示法。
- **位元與位元組不同**：8 位元 = 1 位元組；網速常用位元、檔案大小常用位元組，差 8 倍常造成誤會。
- **十進位下的「整數」在二進位下未必精確**：0.1 在二進位是無限循環小數，浮點誤差由此而來。
- **移位與除法不同**：對負數右移是算術移位（補符號位），結果向下取整，與一般除法方向不同。

## 技術要點

- n 位元可表示 $2^n$ 個不同的狀態；8 位元 256 個，16 位元 65536 個。
- 快速判斷 2 的冪：`x & (x-1) == 0` 且 x 非 0。
- 二進位補碼的範圍是 $-2^{n-1}$ 至 $2^{n-1}-1$ ，負數比正數多一個。
- 十六進位每位元對應 4 位元，故 32 位元整數恰好 8 個十六進位數字。
- 二進位的前 10 個 2 的冪：1、2、4、8、16、32、64、128、256、512、1024——KiB 之所以是 1024 而非 1000。
- XOR 有「自我抵消」性質： $a \oplus b \oplus b = a$ ，是雜湊、校驗與（歷史上的）臨時交換變數的基礎。

## 常見的論爭

- **二進位、十進位還是三進位**：蘇聯的 Setun 曾造過三進位電腦（正零負三態），理論上更省元件，但工業界仍選了二進位。
- **KiB 還是 KB**：硬碟廠以 1000 進位算容量、作業系統以 1024 進位顯示，容量「縮水」之爭促使 IEC 推出 KiB、MiB 新字頭。
- **位元表示的教學**：先教十進位轉換還是直接以十六進位思考，程式教育界各有立場。

## 實務補充：位元的實際操作

在實務中，位元運算最常見的用途不是算術，而是「取位元組」。以 C 語言為例，`flags & (1u << n)` 用來測試第 n 個旗標是否被設定，`flags |= (1u << n)` 設定它，`flags &= ~(1u << n)` 清除它。這三個運算子把一個整數當成旗標集合使用，是驅動程式、網路協定堆疊與壓縮器內核的日常工具。

位元組順序（endianness）也源自這裡。`0x01020304` 在小端機器上依序存為 `04 03 02 01`，在大端機器上則是 `01 02 03 04`。位元組順序是二進位表示加上存取順序的約定，網路協定一律採大端（網路位元組順序），而 x86 與多數行動平台採小端，跨平台讀取二進位檔案時必須注意位元組交換。

另一個常被忽略的面向是位元計數（population count）：統計一個字中 1 的個數是雜湊、錯誤偵測與機器學習特徵工程的常見操作，现代 CPU 常提供 `popcnt` 指令讓它只需一個週期。

### 位元組與十六進位的對照

一個位元組有 256 種取值，寫成十六進位時以兩位表示，因此除以 16 的倍數在除法指令中特別划算：編譯器常把常數除以 4 或 16 最佳化成移位。十六進位因此成為位元組級資料（位元組串、雜湊值、記憶體位址）最自然的呈現方式。

在除錯與逆向工程中，位元組串常以十六進位配合 ASCII 表對照閱讀：0x20 至 0x7E 對應可列印字元，其他數值則可能是指標、浮點數片段或壓縮資料。學會看位元組流是理解協定封包與檔案格式的第一步。

### 位元與其他進位

二進位與八進位、十六進位互為倍數關係，因此位元組級的資料轉換是無損的位元搬移；但二進位與十進位之間的轉換並非如此——十進位 0.1 在二進位下是無限循環小數，這正是浮點表示誤差與通用設備 decimal 運算存在的理由。
