# 作業系統

> 隸屬：[電腦]　·　狀態：初稿

> 對應維基百科：[中文維基百科：作業系統](https://zh.wikipedia.org/wiki/%E6%93%8D%E4%BD%9C%E7%B3%BB%E7%BB%9F)　·　[English Wikipedia: Operating system](https://en.wikipedia.org/wiki/Operating_system)

作業系統是**管理電腦資源、並為應用程式提供抽象介面的常駐軟體**。它同時扮演兩個角色：裁判（多個程式搶用 CPU、記憶體與磁碟時決定誰先誰後、誰拿多少）與造橋人（把「按鍵盤的哪個鍵」「磁碟的第幾個磁區」包裝成「讀一行輸入」「開一個檔案」這樣的抽象）。

沒有作業系統的機器，每個程式必須自帶硬體操作碼、自己處理錯誤，且一次只能跑一個程式。作業系統的存在讓「寫一個程式」與「管理一部機器」徹底分離，這是 [1950年] 之後軟體產業得以分工的技術前提。UNIX、Windows 與 Linux 的競爭史，本質上是「如何分配資源、如何呈現抽象」兩個設計問題的不同答案。

## 技術與理論的關聯

- **行程抽象**：作業系統把「一個執行中的程式」包裝成行程，附帶自己的位址空間、開啟檔案表與排程優先權；排程器在行程之間快速切換，造成並行的錯覺。
- **中斷驅動**：硬體事件以 [中斷] 打斷 CPU，作業系統的處理函式接手處理；沒有中斷，CPU 只能輪詢浪費時間。
- **虛擬記憶體**：每個行程以為自己獨占整個位址空間，MMU 進行虛實轉換，隔離、保護與置換一次解決。
- **檔案抽象**：磁碟的磁區、快閃記憶體的頁、網路上的遠端檔案，都被統一成「可開啟、可讀寫、可關閉的位元組序列」。
- **同步問題**：多個行程共用資料時，交錯執行會產生競態；互斥鎖、號誌與條件變數是教科書級的解法，經典難題包括哲學家就餐與生產者—消費者。
- **死結的理論**：互斥、持有並等待、不可剝奪、循環等待四條件同時成立才會死結，破壞任一條件即可預防；銀行家演算法是最著名的避免策略。

## 範例

**問題**：兩個行程同時對同一銀行帳戶存款 100 元，帳戶初值 1000，最終應為 1200。展示無同步與有同步的差異。

1. **共享變數**：`balance` 存在共享記憶體；兩個行程都執行 `balance = balance + 100`。
2. **競態發生**：這行程式在機器層是三步——讀入暫存器、加 100、寫回。若行程 A 執行完「讀入 1000」被切換，行程 B 完成「1000+100 → 1100」後 A 恢復，A 寫回「1000+100 → 1100」：兩次存款只入帳一次，帳戶 1100 而非 1200。
3. **互斥鎖解法**：把三步包在 `lock(mutex); balance += 100; unlock(mutex);` 之中；第二個行程搶鎖失敗會阻塞，直到第一個行程解鎖。
4. **代價**：鎖會把並行退回序列；因此真實系統用更細的鎖（每帳戶一鎖）、無鎖結構（比較並交換指令 CAS）或交易記憶體來折衷。
5. **排程對照**：兩個行程誰先執行由排程器決定；Linux 的 CFS 排程器以虛擬執行時間公平分配 CPU，互動式行程（如繪圖）優先權較高。
6. **檔案對照**：若帳戶資料在磁碟上，寫入要經過檔案系統的日誌（journal）機制，當機後可恢復一致狀態——同步問題在不同層反覆出現。

## 前因後果

- **前因**：早期機器以人工操作、一次一個程式，昂貴的主機大量時間在等操作員換磁帶；批次監督程式先解決排隊，多工程式再解決 CPU 空轉。
- **後果**：作業系統的抽象直接塑造了 [程式設計] 的形態——程序、檔案、執行緒與 socket 都是作業系統概念的直接投影；虛擬機器與容器則是「作業系統的作業系統」，把資源抽象再往上推一層。

## 與相鄰分類的關聯

- 與 [電腦架構] 的關聯：中斷、特權等級與 MMU 是架構交給作業系統的鑰匙。
- 與 [儲存與記憶體] 的關聯：記憶體管理的演算法（分頁、置換）與快取層次共同決定效能。
- 與 [資訊安全] 的關聯：行程隔離與權限位元是存取控制的硬體基礎，越獄與提權攻擊都以突破這層隔離為目標。
- 在上位概念 [電腦] 中，本子分類是管理層：把一部機器變成許多虛擬機器，讓通用性可以被安全地共享。

## 容易混淆之處

- **行程與執行緒不同**：行程是資源分配單位（有自己的位址空間），執行緒是排程單位（共享所屬行程的資源）。
- **並行與平行不同**：並行是交替執行造成同時的錯覺，平行是真正同時執行於多核。
- **虛擬記憶體不等於交換空間**：虛擬化是位址轉換與保護機制，交換只是它的延伸用法。
- **檔案系統與檔案格式不同**：前者管磁碟上的組織，後者管檔案內的內容結構。
- **鎖不等於萬靈藥**：過度加鎖造成死結與效能瓶頸，設計上應優先縮小共享狀態。

## 技術要點

- 系統呼叫是應用程式進入核心的唯一正門，x86-64 以 `syscall` 指令實現。
- 排程演算法從 FCFS、最短工作優先、輪轉到 CFS，核心目標是吞吐量、延遲與公平的三角平衡。
- 分頁置換策略（LRU、時鐘演算法）決定該淘汰哪一頁，Belady 異象說明 FIFO 可能越換越糟。
- 檔案系統的一致性靠日誌（ext4、NTFS）或寫時複製（Btrfs、ZFS）保證。
- 號誌的 P/V 操作由硬體原子指令支撐，使用者層的 mutex 底層是同一套機制。
- 容器（如 Docker）以 namespace 隔離視野、以 cgroup 限制用量，本質是作業系統級虛擬化。

## 常見的論爭

- **巨核心與微核心**：Linux 把驅動程式全塞進核心（效能好、故障連坐），MINIX 與 QNX 把服務移出核心（可靠、通訊開銷大）；學界與業界立場長期分歧。
- **鎖的粒度**：粗鎖簡單但扼殺並行，細鎖高效但易死結，工程界對「先做對、再做快」有不同排序。
- **作業系統該不該收費**：開源的 Linux 與商業的 Windows 之爭，其實是「支援費」與「授權費」兩種商業模式的對比。

## 實務補充：抽象的邊界

作業系統提供的抽象（行程、檔案、虛擬記憶體、訊號）都是「合約」：它們讓上層程式假設機器比實際簡單。抽象的代價是每一步都有開銷，系統呼叫一次可能涉及數百到數千個指令的排程與位址轉換路徑，因此高性能系統會盡量減少跨越抽象邊界的頻率。

抽象也會失敗。`fork` 複製整個位址空間在大型行程上代價高昂，Linux 以「寫時複製」延遲實際複製；虛擬記憶體讓每個行程都看到連續位址，卻在換頁時暴露延遲；中斷延遲讓即時性難以保證。理解抽象何時被穿透，是效能除錯的第一課。
