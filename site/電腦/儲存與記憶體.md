# 儲存與記憶體

> 隸屬：[電腦]　·　狀態：初稿

> 對應維基百科：[中文維基百科：電腦記憶體](https://zh.wikipedia.org/wiki/%E9%9B%BB%E8%85%A6%E8%A8%98%E6%86%B6%E9%AB%94)　·　[English Wikipedia: Computer data storage](https://en.wikipedia.org/wiki/Computer_data_storage)

儲存與記憶體研究**資訊以什麼速度、什麼容量、什麼持久性存在於機器的哪一層**。這個子分類的出發點是一個殘酷的物理現實：存取速度與容量成反比、與能耗成正比。暫存器快而小、DRAM 大而需持續充電、快閃記憶體持久但寫入慢、磁碟廉價而機械。沒有任何單一媒體能同時滿足「快、大、持久、便宜」，因此工程師把它們疊成階層，用軟體與硬體讓資料在層間自動流動。

理解這個子分類等於理解現代程式效能的真相：演算法的漸近複雜度相同時，誰的資料佈局對快取友善，誰就快得多。矩陣按列還是按行走訪可以有數十倍差距，這些差距全部來自記憶體階層。

## 技術與理論的關聯

- **階層式儲存**：暫存器 → L1/L2/L3 快取 → 主記憶體 → SSD → 磁碟 → 遠端儲存，每往下一層容量大一個數量級、速度慢一至兩個數量級。
- **區域性原理**：程式傾向重複使用剛用過的資料（時間區域性）與鄰近的資料（空間區域性）；快取之所以有效，全靠這兩個經驗定律。
- **快取行與佈局**：資料以 64 位元組的快取行為單位搬移；把一起使用的資料放在一起（如以結構陣列代替陣列結構）可大幅提升命中率。
- **虛擬記憶體的分頁**：以 4 KiB 為單位把虛擬位址映射到實體頁框；TLB 快取映射結果，缺頁中斷觸發磁碟載入。
- **固態硬碟的磨損**：快閃記憶體每個儲存格有寫入次數上限（MLC 約 3000 次、TLC 約 1000 次），控制器以磨損平均延長壽命。
- **持久性記憶體的變局**：NVDIMM、3D XPoint 等技術試圖填補「DRAM 快但易失、快閃持久但慢」之間的缺口，可能改寫階層設計。

## 範例

**問題**：以 C 語言遍訪一個 10000×10000 的 int 矩陣（約 400 MB），按行與按列走訪的效能差多少？為什麼？

1. **兩種寫法**：按行（`for i: for j: s += a[i][j]`）與按列（`for j: for i: s += a[i][j]`），漸近複雜度同為 $O(n^2)$ 。
2. **記憶體佈局**：C 的二維陣列按行連續存放；按行走訪時，下一個元素與當前元素相鄰，幾乎每次都命中快取。
3. **按列的代價**：按列走訪每次跳 10000×4 = 40000 位元組，遠超 64 位元組的快取行；每一個元素都造成一次快取不命中，且一次搬入的 64 位元組只用掉 4。
4. **量級估計**：主記憶體隨機存取約 60 至 100 奈秒，L1 命中約 1 奈秒；按列走訪的每次存取都要付主記憶體延遲，實測常見 5 至 20 倍差距。
5. **改善手法**：把矩陣切成快取行大小的磚塊（blocking）、用結構陣列排列熱資料、預取指令提前搬資料，都能縮小差距。
6. **啟示**：演算法課本只算比較次數，工程效能卻由記憶體佈局決定；這正是 [階層式儲存] 值得獨立成章的原因。

## 前因後果

- **前因**：早期機器的儲存是延遲線與磁鼓，速度與 CPU 同量級；當 CPU 變快而 DRAM 跟不上（1970 至 1980 年代的「記憶體牆」），階層設計被迫誕生。
- **後果**：快取技術催生了快取一致性協定與多核架構；虛擬記憶體成為所有現代作業系統的基礎；固態硬碟則重塑了資料庫與檔案系統的設計假設（不必再為旋轉延遲最佳化）。

## 容易混淆之處

- **記憶體與儲存不同**：記憶體（RAM）揮發、以 GiB 計；儲存（磁碟、SSD）持久、以 TiB 計；日常語言常混用。
- **快取不等於虛擬記憶體**：前者隱藏速度差，後者提供位址抽象與保護，兩者都靠「頁/行」分割但機制不同。
- **容量大不等於性能好**：選購記憶體的頻寬、延遲與通道數常比容量更影響體感。
- **SSD 隨機寫不等於隨機讀**：寫入以「頁」為單位、抹除以「區塊」為單位，小檔案密集寫入會放大寫入量。
- **命中率 99% 不代表沒問題**：尾延遲（長尾）常由偶發不命中造成，平均值會掩蓋它。

## 技術要點

- DRAM 以電容充放電儲存位元，需每數十毫秒刷新一次。
- 快取映射有直接映射、組相聯與全相聯三種，組相聯（如 8 路）是主流折衷。
- 寫策略分寫回與寫通，前者快但當機可能丟資料，需搭配電池或日誌。
- TLB 常只有數十至上千個項目，大型資料庫的查詢設計要考慮 TLB 命中率。
- 分層儲存策略（如 HSM）讓冷資料自動降級到慢速媒體，是企業儲存的成本武器。
- 資料庫的索引選擇（B+ 樹對 LSM 樹）本質上是對快取與寫入放大特性的應答。

## 常見的論爭

- **DRAM 會不會被取代**：持久性記憶體曾被视为候選，但其成本與耐久性問題讓 DRAM 至今仍是主角。
- **快取透明性的極限**：硬體快取對程式設計師透明是優點也是黑箱，要不要讓軟體直接管理快取（如 scratchpad）在嵌入式領域持續爭論。
- **分頁大小**：4 KiB 的傳統值在巨型記憶體時代偏小，大分頁（2 MiB、1 GiB）能減少 TLB 壓力但增加碎片問題。

## 實務補充：容量與延遲的取捨

在儲存裝置的選用上，容量、延遲與每單位成本三者互相拉扯。快閃記憶體的寫入有壽命限制，固態硬碟的控制器需要耗損均衡（wear leveling）來平均寫入各個區塊，否則熱區會先失效。

另一個容易被忽略的面向是持久性語意：當作業系統宣稱「資料已寫入檔案」時，這個承諾的強度取決於裝置是否繞過快取、是否在控制器端有緩衝，以及儲存堆疊何時送出 flush 命令。這個差異在資料庫與金融系統中是可靠性設計的核心。
