# 排序

> 隸屬：[基本演算法]　·　狀態：初稿

> 對應維基百科：[中文維基百科：排序演算法](https://zh.wikipedia.org/wiki/%E6%8E%92%E5%BA%8F%E7%AE%97%E6%B3%95)　·　[English Wikipedia: Sorting algorithm](https://en.wikipedia.org/wiki/Sorting_algorithm)

**排序**是把一組元素依某個鍵值重新排列成非遞減（或非遞增）順序的過程。白話說，它是所有資料處理的第一步：搜尋、二分、合併、分組、統計都預設資料已處於某種次序。排序也是演算法學最完整的教學案例——同一個目標有許多解法，各自的取捨可以被精確比較。

排序演算法的分類有兩條主軸：**比較式**（只靠元素間的大小比較決定次序）與**非比較式**（利用鍵值的結構，如整數位數或桶的位置）。這條分界直接導致複雜度的分野。

## 比較式排序的常見家族

- **插入排序**：逐個把元素插入已排序區；最壞 $O(n^2)$ ，但幾乎有序時接近 $O(n)$ ，且天然穩定。
- **合併排序**：分成兩半各自排序再合併；穩定，最壞 $O(n \log n)$ ，需要 $O(n)$ 額外空間。
- **快速排序**：以樞紐分割；平均 $O(n \log n)$ ，最壞 $O(n^2)$ ，原地且對快取友好。
- **堆排序**：用完全二叉堆維持最大元素在頂端；最壞 $O(n \log n)$ ，原地，但常數較大。

實務上常是混合體：Timsort 以插入排序處理短區段、以合併排序處理長區段，因而兼顧穩定與 $O(n \log n)$ ，Python 的內建排序即採此法。

## 下界：比較式排序無法快過 $n \log n$

若演算法只透過比較得知元素的相對次序，則它其實在做決策樹：每個比較是二元分支，要分辨 $n$ 個元素的所有 $n!$ 種排列，決策樹至少需要 $n!$ 個葉節點，高度至少為

$$
\log_2 n! \approx n \log_2 n - 1.44 n
$$

因此任何比較式排序的最壞情況都至少需要 $\Omega(n \log n)$ 次比較。合併排序與快速排序（平均）恰好達到這個下界，稱為**漸近最優**。

## 非比較式排序

若鍵值是範圍有限、可用位元組表示的整數，就可能跳過比較限制：

- **計數排序**： $O(n + k)$ ， $k$ 為鍵值範圍大小。
- **桶排序**：依鍵值範圍分桶，平均 $O(n)$ ，但要求資料分佈均勻。
- **基數排序**：從最低位數逐位穩定分配， $O(d(n + b))$ 。

以 $n = 10^6$ 、鍵值為 0 到 999999 的整數為例，計數排序約需 $2 \times 10^6$ 次操作，合併排序約需 $2 \times 10^7$ 次比較加搬移，量級差異明顯。

## 穩定性

**穩定排序**是指相等元素的相對次序在排序後保持不變。這個性質在「先按科目、再按人名排序」等多鍵排序情境中不可或缺：若兩趟排序各自穩定，就能把多個鍵合成單一趟次。插入排序與合併排序穩定，快速排序與堆排序不穩定。

## 範例：合併排序

```
function merge_sort(A, lo, hi):
    if lo >= hi: return
    mid = (lo + hi) // 2
    merge_sort(A, lo, mid)
    merge_sort(A, mid + 1, hi)
    merge(A, lo, mid, hi)
```

**合併步驟**（遞迴式 $T(n) = 2T(n/2) + O(n)$ ，解得 $T(n) = O(n \log n)$ ）：

```
function merge(A, lo, mid, hi):
    L = A[lo..mid]; R = A[mid+1..hi]
    i = 0; j = 0; k = lo
    while i < len(L) and j < len(R):
        if L[i] <= R[j]: A[k] = L[i]; i = i + 1
        else:            A[k] = R[j]; j = j + 1
        k = k + 1
    while i < len(L): A[k] = L[i]; i = i + 1; k = k + 1
    while j < len(R): A[k] = R[j]; j = j + 1; k = k + 1
```

**數值實例**：對 `[5, 2, 8, 1]` 排序，分為 `[5,2]` 與 `[8,1]` ，各排序後為 `[2,5]` 與 `[1,8]` ，合併得到 `[1,2,5,8]` ，共經過 4 層遞迴、3 次合併。合併的比較次數最多為 $n - 1 = 3$ 次。

**正確性關鍵**：合併時比較採用 `<=`，因此相等元素取左半者，保持原有次序——這正是合併排序穩定的來源。

## 前因後果

- **前因**：19 世紀打孔卡排序機已能依打孔位置分類卡片，證明「排序」是最早被工程化的演算法任務。
- **後果**：[1960年] 前後 Hoare 提出快速排序，開啟實用排序的時代；Knuth 於 1960 年代出版《電腦程式設計的藝術》第一卷，把排序演算法整理成系統的學術領域，見 [演算法基礎]。

## 與相鄰分類的關聯

- 與 [搜尋] 的關聯：排序是二分搜尋的前提，二者共同構成最常見的資料存取組合。
- 與 [分治策略] 的關聯：合併排序與快速排序都是分治法的典型實例。
- 與 [正確性] 的關聯：排序演算法的正確性需證明「輸出是輸入的排列且非遞減」。
- 與 [複雜度] 的關聯：排序是比較式演算法複雜度的教科書範本，其 $O(n \log n)$ 下界與達成途徑都在此說明。
- 與 [動態規劃] 的關聯：某些排序問題（如最佳化排序）可視為動態規劃。

## 容易混淆之處

- **排序不是搜尋**：排序是把所有元素就位，搜尋是找出一個特定元素。
- ** $O(n \log n)$ 有前提**：只適用於比較式排序，整數鍵值可能更快。
- **原地不等於無空間**：原地排序只用常數額外空間，但合併排序需 $O(n)$ 緩衝。
- **穩定是額外需求**：若業務不需要保持相等元素的次序，選擇不穩定但更快的演算法是合理的。
