# 正確性

> 隸屬：[演算法基礎]　·　狀態：初稿

> 對應維基百科：[English Wikipedia: Correctness (computer science)](https://en.wikipedia.org/wiki/Correctness_(computer_science))

演算法的**正確性**是「對每一個合法輸入，輸出都滿足規格」這個命題。白話說，它不是「跑出來結果看起來對」，而是「不管餵什麼合法資料進去，都保證得到規格允許的答案」。用 [命題邏輯] 的語言說，正確性是一個對所有輸入成立的全稱命題，因此可以用歸納、反證、迴圈不變量等證明方法逐步拆解。

正確性與 [複雜度] 是演算法研究的兩條主軸，且互相牽制：把邏輯寫得繞，往往是為了掩蓋複雜度太糟；而把速度做快，最容易在不覺中破壞邊界條件。兩者都不能犧牲。

## 三種強弱不同的正確性

1. **部分正確性（partial correctness）**：只要求「若程序停止，則輸出正確」。這是較容易證明的部分。
2. **完全正確性（total correctness）**：同時要求「對每個合法輸入都會停止，且輸出正確」。也就是把 [終止性] 也納入。
3. **機率性正確性（probabilistic correctness）**：對隨機演算法，指「輸出正確的機率至少為 $1 - \epsilon$ 」，而不是必然正確。

區分這三者很重要：只證得部分正確性的演算法，可能在某些輸入上永遠跑不完。經典的驗證系統 [形式化驗證] 也遵循同一區分。

## 前置條件與後置條件

把規格拆成兩半是最實用的做法：

- **前置條件（precondition）**：呼叫者必須保證的事，例如「陣列已排序且長度至少為 1」。
- **後置條件（postcondition）**：程式返回後必須成立的事，例如「回傳值是目標元素的索引」。

有了這組區分，演算法就能被**組合**：把 $A$ 的後置條件寫成 $B$ 的前置條件，串接起來的整體正確性由兩個局部正確性推出。這正是模組化與 [程式驗證] 的基本手法，也是 [謂詞演算] 與 Hoare 邏輯的出發點。

## 證明方法

- **數學歸納法**：對結構化的輸入（例如樹的節點數）歸納，是遞迴演算法正確性的標準證法。
- **迴圈不變量**：把「每輪結束時都成立」的那個命題寫出來，證明初始化、保持與終止三段，細節見 [迴圈不變量]。
- **反證法**：假設存在錯誤輸出，再導出矛盾。
- **交換論證**：把演算法的某個步驟與另一個演算法的步驟交換，證明不變差，適用於貪心法與排序演算法。
- **資料流論證**：在演算法內部標記「資料從何而來、經過什麼轉換」，用於直覺較強的程式。

## 範例：二分搜尋的正確性

**規格**：給定已遞增排列的陣列 $a[0 \dots n-1]$ 與目標值 $x$ ，若 $x$ 存在則回傳其索引，否則回傳 $-1$ 。

**演算法**：

```
lo = 0; hi = n - 1
while lo <= hi:
    mid = (lo + hi) // 2
    if a[mid] == x: return mid
    if a[mid] < x: lo = mid + 1
    else: hi = mid - 1
return -1
```

**迴圈不變量**：每次迴圈開始時， $x$ 若存在，其索引必落在 $[lo, hi]$ 區間內。

- **初始化**： $lo = 0$ 、 $hi = n - 1$ 涵蓋整個陣列，不變量成立。
- **保持**：若 $a[mid] < x$ ，由於陣列遞增， $x$ 只能在 $mid$ 右側，故令 $lo = mid + 1$ 後不變量仍成立； $a[mid] > x$ 的情況對稱。
- **終止**：當 $lo > hi$ 時區間為空，說明 $x$ 不存在，回傳 $-1$ 正確；當 $a[mid] = x$ 時直接命中。

**終止性**：每輪迭代使區間長度至少減半， $hi - lo$ 每次下降，故必在有限步內結束；合併兩者即得完全正確性。

**複雜度**：區間長度從 $n$ 降到 1 需 $\lceil \log_2 n \rceil$ 輪，故時間為 $O(\log n)$ 。

這個例子顯示正確性與複雜度共用同一段推理：區間減半既是終止性的依據，也是複雜度的依據。

## 正確性為何難

- **輸入組合太多**：陣列內容、邊界、極端值都是可能的失敗點，人工測試難以窮盡。
- **規格本身可能寫錯**：若後置條件寫得不嚴謹，「正確」就沒有定義。
- **狀態空間爆炸**：狀態數隨變數數量指數成長，窮舉驗證不可行；這正是 [形式化驗證] 與模型檢查要處理的核心困難。
- **可判定性的界線**：一般程式的終止問題不可判定，這意味著不存在對所有程式的全自動證明工具。

## 前因後果

- **前因**：[1936年] [圖靈] 的計算模型確立了「可計算」與「不可判定」的邊界，讓正確性問題有了明確的理論對象。
- **後果**：[1969年] 前後 Hoare 邏輯與 Dijkstra 的結構化程式設計，把「證明程式正確」從數學家的手藝變成工程方法；演算法的形式化描述與機器輔助驗證自此發展。

## 與相鄰分類的關聯

- 與 [迴圈不變量] 的關聯：不變量是證明迴圈型演算法正確性的主力工具。
- 與 [終止性] 的關聯：完全正確性等於部分正確性加上終止性，兩者常用不同技術處理。
- 與 [複雜度] 的關聯：兩者分別回答「對不對」與「快不快」，缺一無法評價演算法。
- 與 [貪心與分治] 的關聯：貪心法需要交換論證，分治法需要對子問題歸納。

## 容易混淆之處

- **測試通過不等於正確**：測試只能證明存在反例，不能證明不存在反例。
- **邊界條件常是錯點**：空陣列、單元素、全部相同等情形往往未被測到。
- **部分正確性被誤當完全正確性**：不少證明只做到「停下來時結果對」。
- **浮點運算需要額外條件**：數值誤差使等號判斷失效，需改用容差或精確有理數。
