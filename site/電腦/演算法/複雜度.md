# 複雜度

> 隸屬：[演算法基礎]　·　狀態：初稿

> 對應維基百科：[中文維基百科：複雜度](https://zh.wikipedia.org/wiki/%E8%A4%87%E9%9B%9C%E5%BA%A6)　·　[English Wikipedia: Computational complexity](https://en.wikipedia.org/wiki/Computational_complexity)

演算法的**複雜度**是「執行時間（或空間）隨輸入規模如何增長」這個量。白話說，它不管你的程式在這台機器上跑了 3 秒還是 30 毫秒，只問：當資料量放大十倍時，它會慢多少倍。因為具體秒數會隨硬體、語言與常數因子改變，而增長階不會。

複雜度是把「快」變成可比較對象的工具。當兩種做法的時間分別是 2.8 秒與 3.2 秒，工程判斷會因機器而異；但當它們分別是 $O(n \log n)$ 與 $O(n^2)$ ，在 $n$ 放大到千倍時，差距就是結構性的。

## 三種漸近notation

- **大 $O$ **：給出上界， $T(n) = O(f(n))$ 表示存在常數 $c, n_0$ 使得 $n \ge n_0$ 時 $T(n) \le c f(n)$ 。
- **大 $\Omega$ **：給出下界，描述「至少需要多少」。
- **大 $\Theta$ **：同階界，同時是上界與下界，只有兩者相同才能宣稱「此演算法正是這個量級」。

實務上常只寫 $O$ ，但那其實是上界而非精確複雜度。一個 $O(n^2)$ 的演算法可能實際只有 $\Omega(n \log n)$ ，兩者必須分清楚。

## 時間複雜度與空間複雜度

- **時間複雜度**：基本運算的執行次數隨 $n$ 的增長。
- **空間複雜度**：執行過程中同時需要的儲存量，包含輸入以外的部分（額外空間）與資料結構佔用的空間。

兩者可以互相轉換：多趟掃描常用空間換時間（快取排序），單趟演算法則常用時間換空間。取捨方向取決於哪一項是瓶頸。

## 遞迴式與求解

演算法的複雜度常先寫成遞迴式再求解：

$$
T(n) = a T(n/b) + f(n)
$$

其中 $a$ 為子問題數量， $b$ 為子問題規模比例， $f(n)$ 為合併成本。Master 定理給出此形式的封閉解，分三種情形比較 $f(n)$ 與 $n^{\log_b a}$ 的快慢：

- 若 $f(n) = O(n^{\log_b a})$ ，則 $T(n) = \Theta(n^{\log_b a})$ 。
- 若 $f(n) = \Omega(n^{\log_b a + \epsilon})$ ，則 $T(n) = \Theta(f(n))$ 。
- 若兩者同階，則 $T(n) = \Theta(n^{\log_b a} \log n)$ 。

## 範例：兩種搜尋的數值對照

以 $n = 10^6$ 的陣列為例，逐一比較一次尋找需 $10^6$ 次比較；二分搜尋只需約 $20$ 次，差距 $5 \times 10^4$ 倍。

再看排序：插入排序在最壞情況下需 $n(n-1)/2 = 5 \times 10^{11}$ 次比較，快速排序平均需約 $n \log_2 n \approx 2 \times 10^7$ 次，差距同樣是五個數量級。

把輸入放大到 $n = 10^9$ 時，二分搜尋仍只需約 $30$ 步，而線性搜尋需要十億步。這個差距不是靠最佳化得來的，而是複雜度階不同所決定。

以遞迴式驗證二分搜尋： $T(n) = T(n/2) + c$ ，其中 $c$ 為一次比較成本。令 $n = 2^k$ ，反覆代入得 $T(n) = T(1) + ck = c \log_2 n + c$ ，故時間複雜度為 $O(\log n)$ ；遞迴版本的空間複雜度為 $O(\log n)$ （呼叫堆疊深度），改寫成迴圈則降為 $O(1)$ 。

## 平均情況、最壞情況與最佳情況

同一演算法在不同資料分佈下表現差距可能極大。快速排序平均 $O(n \log n)$ 、最壞 $O(n^2)$ （已排序輸入加壞樁選擇時觸發）。分析平均情況必須說明假設，例如假設所有排列等可能。

## 實務提醒

- 先寫出遞迴式，再套用定理，比直接猜複雜度可靠。
- 參數有兩個時（頂點數與邊數），要寫成 $O(m + n)$ 之類的雙參數形式。

## 前因後果

- **前因**：硬體不斷加速，單靠「跑幾秒」已無法區分演算法優劣，人們轉而比較增長階。
- **後果**：Knuth 等人於 1960 年代建立的演算法分析成為大學課程；[1971年] 提出的 NP 完全性把複雜度從「排序有多快」提升到「哪些問題在原理上無法快速求解」，見 [NP完全]。

## 與相鄰分類的關聯

- 與 [正確性] 的關聯：複雜度分析必須建立在已確認正確的演算法上，否則分析的是錯誤行為的耗時。
- 與 [遞迴] 的關聯：遞迴式是複雜度求解的主要對象。
- 與 [NP完全] 的關聯：複雜度理論的頂點是問題的計算複雜度分類。
- 與 [近似演算法] 的關聯：當精確解的複雜度不可接受時，改以近似比換取可接受的執行時間。

## 容易混淆之處

- **大 $O$ 不是「恰好的複雜度」**： $O(n^2)$ 也可能是 $\Omega(n \log n)$ 。
- **漸近分析忽略常數**：兩種同階演算法的實際差距往往來自常數因子與實作細節。
- **只適用於大輸入**： $n$ 小時平方級可能反而較快。
- **模型會影響結論**：在帶快取或平行架構下，部分結論會改變。
