# 搜尋

> 隸屬：[基本演算法]　·　狀態：初稿

> 對應維基百科：[中文維基百科：搜尋演算法](https://zh.wikipedia.org/wiki/%E6%90%9C%E7%B4%A2%E7%AE%97%E6%B3%95)　·　[English Wikipedia: Search algorithm](https://en.wikipedia.org/wiki/Search_algorithm)

**搜尋**是在資料集合中找出滿足某個條件的元素（或其位置）的過程。白話說，它回答「我要的那筆在哪裡」。搜尋是所有查詢型系統的核心：資料庫索引、字典查找、檔案系統定位，最後都歸結為「在給定鍵值空間中定位目標」。

搜尋演算法的選擇，取決於三個條件：資料是否已排序、資料是存在於記憶體還是磁碟、以及查詢是「找一個」還是「找全部」。

## 線性搜尋

從頭逐一比較，直到命中或走完。時間複雜度 $O(n)$ ，空間 $O(1)$ ，對任何資料型態都適用。當資料無序、規模小、或查詢只佔極小比例時，它仍是最划算的選擇。

## 二分搜尋

前提是資料已排序且支援隨機存取。每次比較後把搜尋區間砍半：

```
lo = 0; hi = n - 1
while lo <= hi:
    mid = (lo + hi) // 2
    if a[mid] == x: return mid
    if a[mid] < x: lo = mid + 1
    else: hi = mid - 1
return -1
```

- **時間**： $O(\log n)$ 。 $n = 10^6$ 時約 20 步， $n = 10^9$ 時約 30 步。
- **空間**：遞迴寫法 $O(\log n)$ ，迭代寫法 $O(1)$ 。
- **前提**：必須已排序；若資料未排序，先排序需 $O(n \log n)$ ，若只查一次則不划算。

二分搜尋的正確性與複雜度由同一個理由決定：每次迭代把不變的搜尋區間減半，詳見 [正確性] 與 [迴圈不變量]。

## 插值搜尋與雜湊搜尋

- **插值搜尋**：依目標值在值域中的比例猜測位置。資料均勻分佈時可達 $O(\log \log n)$ ，但分佈不均時退化為 $O(n)$ 。
- **雜湊搜尋**：以雜湊函數把鍵值映射到桶中，平均 $O(1)$ ，最壞 $O(n)$ 。代價是失去有序性，因此無法做範圍查詢。

## 範例：兩種搜尋的實際差距

在一個長度 $10^6$ 的已排序陣列中尋找最後一個元素：

- **線性搜尋**：需 $10^6$ 次比較。
- **二分搜尋**：需 $\lceil \log_2 10^6 \rceil = 20$ 次比較。

差距是 $5 \times 10^4$ 倍，且隨 $n$ 持續擴大： $n = 10^{12}$ 時，線性搜尋要一兆次，二分搜尋仍只要 40 次。

若資料必須先排序才能二分搜尋，排序成本 $O(n \log n)$ 約 $2 \times 10^7$ 次比較，此後每次查詢只要 20 次。這就是「一次排序、多次查詢」的資料庫索引能成立的算術根據。

**二分搜尋的實作陷阱**：常見錯誤是用 `mid = (lo + hi) // 2` 在語言整數溢位時出錯，標準寫法為 `mid = lo + (hi - lo) // 2` ；另一個常錯是迴圈條件寫成 `lo < hi` 而未處理 `hi` 的含義，導致漏掉最後一個元素。

## 搜尋的常見變體

- **找區間**：找滿足某個範圍條件的所有元素；在已排序資料上可用二分找上下界。
- **找最接近值**：在已排序資料上二分後比較左右兩個候選。
- **多模式搜尋**：在同一資料中同時找多個字串（如文字編輯器的尋找功能），可用 Rabin–Karp 等演算法。
- **近似搜尋**：允許少量差異的模糊比對，常需先建立雜湊索引或索引結構。

## 前因後果

- **前因**：19 世紀的索引與卡片目錄已把「查找」當成獨立技能；1940 至 1950 年代，資訊檢索領域的發展讓詞典式查找被形式化。
- **後果**：二分搜尋與雜湊表成為資料結構的基礎設施，衍生出平衡樹、B 樹等結構，直接支撐了資料庫與檔案系統的效能，見 [圖演算法] 中的相關演算法與 [基本演算法] 的其他工具。

## 與相鄰分類的關聯

- 與 [排序] 的關聯：排序是二分搜尋的前提，也是「一次排序、多次查詢」策略的第一步。
- 與 [複雜度] 的關聯：搜尋的效率差異最直接地以對數與線性的差距呈現。
- 與 [圖演算法] 的關聯：圖上的搜尋（如廣度優先搜尋）是把線性搜尋推廣到有結構的空間。
- 與 [正確性] 的關聯：搜尋需證明「命中時回傳的元素確實等於目標」與「未命中時目標確實不存在」。

## 容易混淆之處

- **搜尋與遍歷不同**：遍歷走遍所有節點，搜尋可提前結束。
- **二分搜尋要求有序**：對未排序資料使用會得到錯誤答案。
- **雜湊查詢不保險**：碰撞會讓最壞情況退化。
- **平均 $O(1)$ 不等於最壞 $O(1)$ 對**：雜湊搜尋是前者。
