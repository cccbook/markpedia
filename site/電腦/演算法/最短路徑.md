# 最短路徑

> 隸屬：[圖演算法]　·　狀態：初稿

> 對應維基百科：[中文維基百科：最短路徑樹](https://zh.wikipedia.org/wiki/%E6%9C%80%E7%9F%AD%E8%B7%AF%E5%BE%91%E6%A8%B9)　·　[English Wikipedia: Shortest path problem](https://en.wikipedia.org/wiki/Shortest_path_problem)

**最短路徑問題**是「在帶權圖中，找出兩點之間權重總和最小的一條路徑」。白話說，它回答「從這裡走到那裡，最少要花多少」。它是圖演算法中最常被求解的問題，也是交通規劃、路由協定與排程系統的共同核心。

最短路徑問題有許多變體：單一來源、單一目標、所有對、以及帶負權的情形；它們的解法與複雜度差異很大，選擇演算法前必須先確定權重是否可能為負。

## 主要演算法

- **Dijkstra 演算法**：適用於權重非負的單源最短路徑；用最小堆維護候選距離，時間 $O((m + n)\log n)$ 。[1959年] [狄克斯特拉] 發表此法。
- **Bellman–Ford 演算法**：允許負權（但不能有負環），時間 $O(nm)$ ，並可藉由偵測第 $n$ 輪仍可鬆弛來判定負環。
- **Floyd–Warshall 演算法**：以動態規劃求所有對最短路徑，時間 $O(n^3)$ ，適合稠密圖。
- **Johnson 演算法**：先用 Bellman–Ford 重標權，再以 Dijkstra 求所有對，時間 $O(nm + n^2 \log n)$ 。
- **A\* 搜尋**：帶啟發函數的最佳優先搜尋，用於地圖導航，詳見 [搜尋] 的搜尋家族。

## 範例：Dijkstra 演算法逐步執行

**圖**：五個頂點 $A, B, C, D, E$ ，無向邊與權重為 $A\text{–}B: 4$ 、 $A\text{–}C: 1$ 、 $C\text{–}B: 2$ 、 $B\text{–}D: 5$ 、 $C\text{–}D: 8$ 、 $D\text{–}E: 3$ 。

**演算法**：

```
function dijkstra(G, source):
    dist = infinity for all vertices
    dist[source] = 0
    heap = [(0, source)]
    while heap not empty:
        (d, u) = pop_min(heap)
        if d > dist[u]: continue
        for each (u, v, w) in G[u]:
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                push(heap, (dist[v], v))
    return dist
```

**逐步執行**（初始 $dist[A]=0$ ，其餘為無窮）：

1. 取出 $A$ （距離 0），經由 $A$ 更新： $dist[B] = 4$ ， $dist[C] = 1$ 。堆中為 $(1,C),(4,B)$ 。
2. 取出 $C$ （距離 1），經由 $C$ 更新： $dist[B] = \min(4, 1+2) = 3$ ， $dist[D] = 1+8 = 9$ 。
3. 取出 $B$ （距離 3），經由 $B$ 更新： $dist[D] = \min(9, 3+5) = 8$ 。
4. 取出 $D$ （距離 8），經由 $D$ 更新： $dist[E] = 8+3 = 11$ 。
5. 取出 $E$ （距離 11），無更新，結束。

**結果**： $dist[A]=0$ 、 $dist[C]=1$ 、 $dist[B]=3$ 、 $dist[D]=8$ 、 $dist[E]=11$ 。其中 $A$ 到 $D$ 的最短路徑為 $A \to C \to B \to D$ ，總權重 $1 + 2 + 5 = 8$ ，比直走 $A \to C \to D$ 的 9 還短——這正是「貪心地挑目前最便宜的邊」在非負權圖上安全的原因。

**複雜度**：以最小堆實作，時間 $O((m + n) \log n)$ ；若使用陣列線性找最小值，則退化為 $O(n^2)$ ，在稠密圖上反而更實用。

## 負權與負環

若圖中允許負權，Dijkstra 的「一旦取出即定案」就失效了：某條後續的負權路徑可能讓已定案的距離變得更小。Bellman–Ford 以「所有邊反覆鬆弛 $n-1$ 輪」處理這件事，並在第 $n$ 輪若仍能鬆弛，就判定存在負環，最短路徑問題在該情況下無解。

## 前因後果

- **前因**：19 世紀的鐵路與電報網路建設，使「最小成本路徑」成為工程問題；地圖學中的最短路研究亦源於此。
- **後果**：[1959年] [狄克斯特拉] 的演算法把這類問題系統化，1960 年代起被納入演算法教科書，並直接支撐了網際網路的路由協定設計，見 [圖演算法] 的其他演算法。

## 與相鄰分類的關聯

- 與 [貪心選擇] 的關聯：Dijkstra 演算法是非負權圖上的典型貪心法，其正確性依賴貪心選擇性質。
- 與 [正確性] 的關聯：Dijkstra 的正確性來自「非負權下目前最短的前綴不再變差」這一命題。
- 與 [複雜度] 的關聯：堆的實作選擇直接決定 $O((m + n)\log n)$ 與 $O(n^2)$ 的取捨。
- 與 [動態規劃] 的關聯：Floyd–Warshall 是經典的動態規劃應用。
- 與 [最小生成樹] 的關聯：兩者同為帶權圖上的最佳化問題，權重語意不同（路徑權重可加、生成樹權重須總和）。
- 與 [搜尋] 的關聯：A\* 把最短路徑與啟發式搜尋結合。

## 容易混淆之處

- **最短路徑樹不是最短路徑本身**：前者是以某頂點為根、記錄所有最短路徑的結構。
- **權重非負是前提**：負權會讓 Dijkstra 給出錯誤答案。
- **路徑與迴路**：路徑通常指不重複頂點的序列；負環存在時問題無界。
- **實作選擇影響效能**：堆的選擇在稠密圖與稀疏圖上的最優策略不同。
