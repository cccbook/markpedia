# 拓樸排序

> 隸屬：[圖演算法]　·　狀態：初稿

> 對應維基百科：[中文維基百科：拓樸排序](https://zh.wikipedia.org/wiki/%E6%8B%93%E6%89%91%E6%8E%92%E5%BA%8F)　·　[English Wikipedia: Topological sorting](https://en.wikipedia.org/wiki/Topological_sorting)

**拓樸排序**是把有向無環圖的頂點排成一個線性順序，使每條邊都從前面的頂點指向後面的頂點。白話說，它回答「先做哪個、後做哪個」：若 $A$ 必須在 $B$ 之前完成，就讓 $A$ 排在前面。這是排程、編譯依賴解析與建置系統的基礎。

拓樸排序的適用前提是**有向無環**：若圖中存在有向環（ $A \to B \to C \to A$ ），就沒有任何順序能滿足所有約束，此時演算法會偵測到環並回報失敗。

## 兩種演算法

- **Kahn 演算法**（拓樸排序）：反覆取出所有入度為 0 的頂點，加入結果佇列，並把其鄰點的入度減一；若最後輸出的頂點數少於 $n$ ，表示圖中有環。時間 $O(n + m)$ 。
- **深度優先搜尋法**：對每個頂點做 DFS，在回溯時把頂點加入清單，最後把清單反轉。時間同為 $O(n + m)$ 。

Kahn 演算法的優點是**天然偵測環**：佇列清空後若仍有剩餘頂點，它們必定都在環上。

## 範例：Kahn 演算法逐步執行

**圖**：六個任務與先後關係 $A \to B$ 、 $A \to C$ 、 $B \to D$ 、 $C \to D$ 、 $C \to E$ 、 $D \to F$ 、 $E \to F$ 。

**初始入度**： $A:0$ 、 $B:1$ 、 $C:1$ 、 $D:2$ 、 $E:1$ 、 $F:2$ 。只有 $A$ 的入度為 0。

1. 取出 $A$ ，輸出佇列為 `[A]` 。移除邊 $A \to B$ 與 $A \to C$ ， $B$ 入度降為 0 ， $C$ 入度降為 0 。
2. 取出 $B$ ，佇列為 `[A, B]` 。移除 $B \to D$ ， $D$ 入度降為 1 。
3. 取出 $C$ ，佇列為 `[A, B, C]` 。移除 $C \to D$ 與 $C \to E$ ， $D$ 入度降為 0 ， $E$ 入度降為 0 。
4. 取出 $D$ ，佇列為 `[A, B, C, D]` 。移除 $D \to F$ ， $F$ 入度降為 1 。
5. 取出 $E$ ，佇列為 `[A, B, C, D, E]` 。移除 $E \to F$ ， $F$ 入度降為 0 。
6. 取出 $F$ ，佇列為 `[A, B, C, D, E, F]` 。

**結果**：順序 $A, B, C, D, E, F$ 滿足所有約束。佇列取出順序不必唯一：第 3 步若先取 $E$ 再取 $C$ 也合法，得到 $A, B, E, C, D, F$ ，同樣滿足所有邊的方向。

**複雜度**：每個頂點入佇列一次，每條邊處理一次，時間 $O(n + m)$ ，空間 $O(n)$ 。

**環的偵測**：若改為 $A \to B \to C \to A$ ，則三個頂點入度皆為 1，佇列一開始就是空的，輸出頂點數 0 小於 3，據此判定有環。

## 實作要點

- **用佇列而非堆**：Kahn 演算法每次取入度為 0 的頂點，用一般佇列即可，順序無關緊要。
- **入度表要事先算好**：先掃描所有邊累加入度，再在移除頂點時更新鄰點。
- **DFS 版的實作細節**：頂點分為未拜訪、進行中、已完成三色；回溯時加入清單，最後反轉清單即得拓樸序。
- **多起點處理**：若圖不連通，應對每個連通分量分別執行，或以一個超級源點連到所有入度為 0 的頂點。

## 常見的實作錯誤

- 忘記在移除頂點時遞減鄰點入度，會導致佇列提前清空而誤判無環。
- 在有向環存在時仍輸出部分順序，卻沒有向使用者回報失敗。
- 對同一個圖反覆執行拓樸排序卻不做記憶化，浪費時間。
- 混淆「有向無環」與「無向無環」：無向圖的每條邊都是雙向的，沒有可用的偏序關係。


- **建置系統**：模組之間的相依關係構成有向無環圖，拓樸排序決定編譯順序；若發現環，表示相依設計有誤。
- **編譯器**：依語法結構決定先後分析順序。
- **課程先修要求**：把選課相依關係排成可修課順序。
- **專案排程**：在部分相依的條件下安排工作順序。

## 前因後果

- **前因**：19 世紀的工程排程與 20 世紀初的編譯器設計，需要把相依工作排成合法順序。
- **後果**：1960 年代，作業系統與建置工具普遍採用拓樸排序處理相依性；它是圖演算法中最簡單卻最實用的一個，與 [排序] 的通用排序在用途上完全不同——拓樸排序只處理有向無環圖，且不比較大小。

## 與相鄰分類的關聯

- 與 [搜尋] 的關聯：DFS 版的拓樸排序以 [搜尋] 中的深度優先搜尋為基礎。
- 與 [排序] 的關聯：拓樸排序是排序的一個特例化應用，但依據是邊的方向而非元素大小。
- 與 [圖演算法] 的關聯：是最基本的圖演算法之一。
- 與 [動態規劃] 的關聯：某些以拓樸順序為基礎的動態規劃應用，建議依序計算狀態。

## 容易混淆之處

- **拓樸排序不是一般排序**：它不比較大小，輸出順序不唯一。
- **只適用於有向無環圖**：無向圖的「拓樸序」無意義。
- **存在多個解**：若有多個入度為 0 的頂點，取捨順序會影響結果。
- **偵測到環是特性不是缺陷**：這正是相依性錯誤診斷的依據。
