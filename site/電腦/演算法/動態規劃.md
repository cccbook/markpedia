# 動態規劃

> 隸屬：[基本演算法]　·　狀態：初稿

> 對應維基百科：[中文維基百科：動態規劃](https://zh.wikipedia.org/wiki/%E5%8A%A8%E6%80%81%E8%A7%84%E5%88%92)　·　[English Wikipedia: Dynamic programming](https://en.wikipedia.org/wiki/Dynamic_programming)

**動態規劃**是「把問題拆成互相重疊的子問題，把子問題的答案記下來重複使用」的方法。白話說，它適合那些**同時有兩個麻煩**的問題：規模大到不能暴力求解，而且解法天然會重複計算同一批子問題。暴力法每次都重算，動態規劃則把算過的結果存起來。

動態規劃與分治的差別在「重疊」：分治的子問題互不重疊，可以各自獨立求解；動態規劃的子問題彼此重疊，因此必須快取。

## 三個判別條件

一個問題適合用動態規劃，通常同時滿足：

1. **最優子結構**：一個整體解的最優解，必然由子問題的最優解組成；若某子問題的解不優，整體也不會優。
2. **重疊子問題**：遞迴求解時會反覆遇到同一批子問題。
3. **無後效性**：狀態一旦確定，之後的選擇與過去的歷史無關。

三者缺一，動態規劃往往退化成帶快取的暴力搜尋，收益有限。

## 兩種實作方式

- **自頂向下（記憶化遞迴）**：先寫遞迴式，再用雜湊表記錄已算過的狀態；直觀，但可能呼叫大量非必要的狀態。
- **自底向上（表格法）**：依序填表格，實作較省記憶體，執行順序可預測。

兩者的時間複雜度相同，差異在於常數與記憶體用量。

## 狀態設計是關鍵

動態規劃的難點通常不在寫程式，而在**定義狀態**。狀態必須足以決定後續所有選擇，且個數不能太多。典型失誤是狀態少了某個維度，導致記錄的結果其實不完整，答案因此出錯。

## 範例：費波那契與最長共同子序列

**問題一（最長共同子序列）**：給定兩串 $A$ 、 $B$ ，求兩者最長的共同子序列長度。

狀態定義： $dp[i][j]$ 為 $A$ 的前 $i$ 個字元與 $B$ 的前 $j$ 個字元的最長共同子序列長度。

```
for i = 0 to len(A):
    for j = 0 to len(B):
        if i == 0 or j == 0:
            dp[i][j] = 0
        else if A[i-1] == B[j-1]:
            dp[i][j] = dp[i-1][j-1] + 1
        else:
            dp[i][j] = max(dp[i-1][j], dp[i][j-1])
return dp[len(A)][len(B)]
```

**數值實例**： $A = "ABCBDAB"$ ， $B = "BDCABA"$ ，表格計算得最長共同子序列長度為 $4$ ，例如 "BCBA" 或 "BDAB" 。字串長度各為 7，暴力列舉所有子序列共 $2^7 = 128$ 個，比對成本高；動態規劃只需填 $8 \times 8 = 64$ 個格。

**時間與空間**：時間 $O(mn)$ ，其中 $m, n$ 為兩串長度；空間 $O(mn)$ ，若只需長度可壓縮為 $O(\min(m,n))$ 。

**問題二（費波那契）**：遞迴式 $F(n) = F(n-1) + F(n-2)$ 若直接實作，呼叫次數是斐波那契數， $n = 40$ 時約 $2.7 \times 10^8$ 次，約需數十秒；改用動態規劃後只需 $O(n)$ 時間與 $O(n)$ 空間， $n = 40$ 瞬間完成。這個對比正是「重疊子問題」價值的最佳演示。

## 與分治、貪心的取捨

- **分治**：子問題互不重疊，不需快取，但要求合併方式能由子解重建整解。
- **動態規劃**：子問題重疊且互相依賴，需要狀態與轉移的嚴格定義。
- **貪心選擇**：不作比較，直接取當下最優；見 [貪心選擇]，只有具備貪心選擇性質的問題才能用它。

三者是求解最佳化問題的三種典範，選錯典範往往導致錯誤答案，而不只是變慢。

## 前因後果

- **前因**：19 世紀末至 20 世紀初，重力學的逐步積分法與工程上的最短路徑問題，已隱含「把大問題拆成階段、逐階段求解」的想法。
- **後果**：1950 年代 Bellman 的動態規劃工作把這套想法系統化，用於控制理論與資源配置；此後它成為演算法教科書的固定章節，與 [分治策略] 並列為兩大求解典範。

## 與相鄰分類的關聯

- 與 [複雜度] 的關聯：動態規劃的本質是用空間與時間的投入，換取對指數級重複計算的消除。
- 與 [遞迴] 的關聯：兩種實作方式都以遞迴式為起點。
- 與 [正確性] 的關聯：狀態轉移的正確性需要歸納證明。
- 與 [近似演算法] 的關聯：當狀態數過大而無法完整列出時，可改用近似或啟發式。

## 容易混淆之處

- **動態規劃不等於動態記憶體分配**：後者是作業系統的概念。
- **狀態定義錯誤是常見錯誤來源**：少一維、多一維都會導致錯誤。
- **表格法與記憶化等價但常數不同**：實測前需依資料特性選擇。
- **有時暴力更划算**：狀態數大、答案少時， $O(n^2)$ 的直接列舉可能比建立表格便宜。
