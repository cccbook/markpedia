# 遞迴

> 隸屬：[演算法基礎]　·　狀態：初稿

> 對應維基百科：[中文維基百科：遞迴](https://zh.wikipedia.org/wiki/%E9%80%92%E5%BD%92)　·　[English Wikipedia: Recursion](https://en.wikipedia.org/wiki/Recursion)

**遞迴**是「函式呼叫自己來完成工作」的寫法。白話說，當問題可以拆成「形狀相同但規模更小」的子問題時，就讓函式去處理那個小一號的版本，直到小到可以直接回答為止。遞迴把「自我相似」的結構直接映射到程式結構，是演算法中少數能讓複雜度與正確性同時變得容易表達的工具。

遞迴的代價是執行成本：每次呼叫都要建立新的堆疊框架（保存區域變數與返回位址），因此遞迴版本的時間與空間通常都高於等價的迭代版本。它的價值不在速度，而在**可讀性與可證明性**。

## 三個必備要素

任何正確的遞迴都需要三樣東西：

1. **基準情形（base case）**：某個可以直接回傳答案的最小輸入，讓遞迴有出口。
2. **遞迴步驟（recursive step）**：呼叫自身處理更小的子問題，並把結果組合起來。
3. **趨近基準的保證**：每次呼叫的輸入必須嚴格「更靠近」基準情形，否則會無限遞迴。

第三點最常被忽略。若忘記遞迴式在「已排序陣列」這種情形下有縮小規模，程式會在遞迴深處才爆堆疊，錯誤訊息往往與真正原因無關。

## 遞迴的三種形式

- **直接遞迴**：函式呼叫自己，例如階乘 $n!$ 。
- **間接遞迴**：透過其他函式間接呼叫自己，例如偶數與奇數的判定互相呼叫。
- **尾遞迴**：呼叫是最後一個動作，某些語言的編譯器可將其最佳化為迴圈，消除額外堆疊開銷。

遞迴式（如 $T(n) = T(n/2) + c$ ）是分析遞迴演算法複雜度的標準起點，詳見 [複雜度] 與 [演算法基礎]。

## 範例：遞迴求最大公因數

**規格**：給定非負整數 $a, b$ ，回傳它們的最大公因數。

**演算法**：

```
function gcd(a, b):
    if b == 0:
        return a
    return gcd(b, a mod b)
```

**逐步推理**：

1. **基準情形**： $b = 0$ 時， $\gcd(a, 0) = a$ ，直接回傳。
2. **遞迴步驟**：利用歐幾里得恆等式 $\gcd(a, b) = \gcd(b, a \bmod b)$ ，把問題化為規模更小的同一型問題。
3. **規模遞減**：每次呼叫後第二個參數變成餘數，嚴格小於原來的 $b$ ，因此必定在有限步內到達 $b = 0$ 。
4. **數值實例**： $\gcd(1071, 462)$ 的呼叫序列為 $(1071,462) \to (462,147) \to (147,21) \to (21,0)$ ，最後回傳 $21$ 。共 4 次呼叫。
5. **複雜度**：每次呼叫的 $b$ 至少減半（更壞情形為斐波那契遞減），最壞呼叫次數為 $O(\log a)$ ；每次呼叫的堆疊深度同為 $O(\log a)$ 。相較之下，逐一枚舉因數的版本是 $O(\sqrt{a})$ 。

**迭代改寫**：若把「 $b$ 為 0」改為 while 迴圈，便可把空間複雜度由 $O(\log a)$ 降為 $O(1)$ ，這是「遞迴換可讀、迭代換效能」的典型取捨。

## 遞迴與分治、動態規劃的關係

遞迴是**表達**手段，分治與動態規劃是**設計**策略：分治法以遞迴表達「分解—解決—合併」，動態規劃以遞迴表達「狀態—轉移」，並加上記憶化避免重複計算。兩者都依賴遞迴的呼叫堆疊來記住中間狀態，因此理解遞迴是理解這兩種典範的前提。

## 容易出錯的地方

- **無基準情形**：遞迴無限展開，最終出現堆疊溢位而非明確的錯誤。
- **規模不減**：例如對已經排序的陣列仍做同樣範圍的遞迴。
- **指數級重複**：費曼遞迴式 $F(n) = F(n-1) + F(n-2)$ 若直接遞迴實作，呼叫次數是斐波那契數，對 $n = 40$ 時已達 $2.7 \times 10^8$ 次，加入記憶化後降為 $O(n)$ 。
- **深遞迴耗盡堆疊**：在受限環境（如某些嵌入式系統）中，即使深度只有數千也可能失敗。

## 前因後果

- **前因**：數學上自 17 世紀起，遞迴式就是描述數列與方程式的自然語言；電腦的堆疊結構則讓「自我呼叫」在機器上有了直接對應。
- **後果**：遞迴與 [終止性] 分析在 1960 年代一起成為計算理論的核心課題；[圖靈] 對可計算性的刻劃也建立在類似的自我呼叫直覺之上。

## 與相鄰分類的關聯

- 與 [複雜度] 的關聯：遞迴式是複雜度求解的起點。
- 與 [分治策略] 的關聯：分治的遞迴結構是遞迴最典型的應用。
- 與 [動態規劃] 的關聯：記憶化的遞迴即動態規劃。
- 與 [終止性] 的關聯：遞迴的終止性需要良基的度量。

## 容易混淆之處

- **遞迴不等於更好**：遞迴易讀但常帶來額外呼叫成本。
- **遞迴不等於迴圈**：兩者可以互相改寫，但改寫方向決定了可讀性的歸屬。
- **遞迴深度不是輸入大小**：是子問題的深度，而不是 $n$ 的大小。
- **基準情形可能多個**：不同資料型態可能需要不同出口。
