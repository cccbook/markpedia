# 虛擬記憶體

> 隸屬：[電腦] › [儲存與記憶體]　·　狀態：初稿

> 對應維基百科：[中文維基百科：虛擬記憶體](https://zh.wikipedia.org/wiki/%E8%99%9A%E6%8B%9F%E5%86%85%E5%AD%98)　·　[English Wikipedia: Virtual memory](https://en.wikipedia.org/wiki/Virtual_memory)

虛擬記憶體是**為每個行程創造「獨占一整台機器記憶體」錯覺的位址轉換機制**。程式使用的位址是虛擬的，MMU 硬體在每次記憶體存取時把它翻譯成實體位址。這層翻譯一次解決三個問題：保護（行程 A 看不到 B 的記憶）、靈活分配（物理上不連續的頁可拼出連續的虛擬空間）、以及擴容（用磁碟補足 RAM 的不足）。

它的日常運作以分頁為單位：4 KiB 的頁、四級頁表、TLB 加速。程式的每次記憶體存取都在無聲地走過這套機器——這也是它值得單獨成章的原因：看不見，卻無所不在。

## 技術與理論的關聯

- **兩個位址空間**：虛擬位址（程式所見）與實體位址（記憶體晶片所見），由頁表映射；映射單位是頁（4 KiB 標準）。
- **多級頁表**：x86-64 用 PML4 → PDPT → PD → PT 四級，只在有內容的區段填表，稀疏的位址空間因此不浪費頁表記憶體。
- **TLB**：轉換旁視緩衝器快取最近的虛實映射，命中則零額外成本；不命中需多級頁表走訪（數十週期），大頁（2 MiB、1 GiB）正是為降低 TLB 壓力而生。
- **按需分頁**：頁表項標記「不在記憶體」，首次觸碰引發缺頁例外，核心才分配實體頁或從檔案載入——mmap 檔案 I/O 就是把讀檔變成缺頁。
- **置換與抖動**：RAM 不足時核心以近似 LRU（時鐘演算法）挑頁寫入 swap；若工作集大於 RAM，系統不斷換頁，CPU 大半時間等 I/O，此謂抖動。
- **權限與安全**：每頁可設唯讀/可寫、可執行/不可執行（NX）、使用者/核心；ASLR 隨機化區段位址，讓攻擊者難以預測布局。

## 範例

**問題**：追蹤一次跨行程的記憶體存取，看轉換的全部環節。

1. **指令**：行程 A 執行 `mov eax, [rsp+8]`，虛擬位址 0x7ffd1234。
2. **TLB 查找**：MMU 以虛擬頁號查 TLB——假設命中，得到實體頁框 0x3A000，加上頁內位移直接存取，全程 1 奈秒。
3. **TLB 不命中的情況**：走四級頁表：PML4 條目 → PDPT 條目 → PD 條目 → PT 條目，四次記憶體存取；核心預先為每行程在實體記憶體放好頁表。
4. **頁表項內容**：存在位、讀寫位、使用者/管理者位、髒位、存取位與頁框號；若存在位為 0，CPU 產生缺頁例外。
5. **缺頁例外**：核心查 VMA（虛擬記憶體區域）判斷這位址合法嗎——合法則分配頁框（必要時先淘汰冷頁）；非法則送 SIGSEGV 殺行程，這就是段錯誤的真面目。
6. **行程切換時**：核心把 CR3 暫存器指向另一行程的頁表根，整個位址空間瞬間切換；ASLR 與 NX 位保證 A 無論如何不能讀 B——保護不是軟體檢查，是硬體在每筆存取上執法。

## 前因後果

- **前因**：1959 年曼徹斯特 Atlas 首創「一級儲存」自動分頁；PDP-10 與 VAX 把保護位元完善化，x86 以四級頁表把它推向普及。
- **後果**：虛擬記憶體使行程隔離、共享庫、mmap I/O、寫時複製與記憶體映射資料庫成為可能；容器與虛擬機器則在其上再疊抽象層。

## 與相鄰分類的關聯

- 與 [記憶體管理] 的關聯：記憶體管理是政策（分給誰、淘汰誰），虛擬記憶體是機制（位址轉換），兩者相輔相成。
- 與 [快取] 的關聯：TLB 是頁表項的快取；另外實體頁也可能正被 CPU 快取行持有，兩套快取並行。
- 與 [作業系統] 的關聯：缺頁例外是核心最重要的事件來源之一，置換策略是核心最複雜的政策之一。
- 在上位概念 [儲存與記憶體] 中，虛擬記憶體是「位址層」的代表。

## 容易混淆之處

- **虛擬記憶體不等於 swap**：swap 只是「把頁寫到磁碟」的用法之一；沒有 swap 的系統同樣有完整虛擬記憶體。
- **虛擬位址空間大不等於實體記憶體多**：64 位元程式可許諾海量虛擬空間，實體頁仍按需分配。
- **缺頁有三種**：硬缺頁（要從磁碟載）、軟缺頁（頁在快取只需映射）、非法存取（SIGSEGV）——只有第三種是錯誤。
- **物理記憶體碎片與虛擬碎片是兩回事**：虛擬空間的空洞不浪費實體頁。

## 技術要點

- CR3（x86）或 TTBR（ARM）指向當前頁表根，切換行程即切 CR3。
- TLB 是 per-core 的，切頁表必須 flush 或用 PCID 標籤區分。
- copy-on-write 頁面初始為唯讀共享，寫入觸發缺頁才複製。
- 大頁可把 TLB 覆蓋範圍放大 512 倍，資料庫與 JVM 的啟動參數常見。
- mmap(PROT_READ|MAP_SHARED) 讓多行程共享同一實體頁，是零拷貝共享的標準做法。
- Linux 的 overcommit 策略允許許諾超過實體總量，代價是 OOM killer 的出現。

## 常見的論爭

- **overcommit 該不該開**：慷慨許諾提昇記憶體利用率，但 OOM 殺行程不可預測；穩定派與效率派長期爭執。
- **頁大小**：4 KiB 沿用半世紀，大頁派與碎片派各持己見，硬體同時支援兩種大小作為妥協。
- **MMU 型虛擬化**：兩級位址轉換（EPT/NPT）是否會拖慢虛擬機，實務顯示 TLB 壓力上升，因此出現巨大頁與快取 TLB 的設計。

## 實務補充：分頁、置換與抖動

虛擬記憶體把每個行程的位址空間切成固定大小的頁，映射到實體記憶體的頁框；當頁不在記憶體中，就產生頁錯誤，由作業系統從磁碟載入並可能把另一頁換出。取捨在於：位址空間可以遠大於實體記憶體，但頁錯誤的延遲高達數十至數百微秒。

若工作集超出可用實體記憶體，系統會反覆載入同一批頁面，效能崩潰，這就是「抖動」（thrashing）。作業系統用工作集模型或頁錯誤率監測來避免這件事。

虛擬記憶體也提供隔離與共享：每個行程看到自己的連續位址空間，共享記憶體則讓行程間以同一頁框交換資料。容器技術則進一步用命名空間與 cgroup 在同一核心之上建立更輕量的隔離層。

### 連續位址的好處

虛擬記憶體讓每個行程都從位址 0 開始看到一塊連續的位址空間，程式設計師不必關心實體記憶體的碎裂情形，編譯器也不必處理複雜的位址重新定位。位址轉換由硬體的 MMU 加上作業系統維護的頁表完成，TLB 快取近期使用的轉換結果以降低延遲。

這項機制同時是隔離的基礎：每個行程的頁表把它的位址映射到獨立的頁框，跨行程存取會觸發保護例外，由作業系統的訊號機制轉為訊號或共程序，構成使用者空間與核心空間的安全邊界。

### 透明大頁與缺頁成本

現代系統提供透明大頁，讓作業系統以 2 MiB 為單位配置連續頁框，減少頁表項數與 TLB 缺失，對資料庫這類大工作集有明顯效益；代價是記憶體內部碎片與較難回收。

缺頁成本也會隨儲存裝置而變：以 SSD 為後端時頁錯誤延遲大幅下降，使虛擬記憶體的換頁策略可以更積極地以效能而非容量為考量。
