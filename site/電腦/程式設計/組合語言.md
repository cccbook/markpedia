# 組合語言

> 隸屬：[程式設計]　·　狀態：初稿

> 對應維基百科：[中文維基百科：汇编语言](https://zh.wikipedia.org/wiki/%E6%B1%87%E7%BC%96%E8%AF%AD%E8%A8%80)　·　[English Wikipedia: Assembly language](https://en.wikipedia.org/wiki/Assembly_language)

組合語言是**用助記符寫成的機器語言**：每一條陳述對應一條機器指令，`MOV`、`ADD`、`JMP` 之類的符號取代位元組編碼，讓人至少不必在紙上排列 0 與 1。它與 [機器語言] 一一對應，因此又被稱為「符號機器碼」；組譯器（assembler）負責把助記符換回位元組。

## 技術與理論的關聯

- **一比一的抽象**：組合語言與其對應的指令集是一對一映射，沒有隱藏的 runtime、沒有垃圾回收、沒有例外機制；程式行為完全取決於硬體。
- **暫存器即工作台**：組合語言程式的思考單位是「值在暫存器之間如何流動」，這與 [高階語言] 的「值綁定到變數」是兩種不同的心智模型。
- **程序同步與中斷**：低階程式必須自行保存與還原暫存器，這就是作業系統與 [中斷] 處理程式大量撰寫於組合語言的原因。
- **形式驗證與教學**：像 [圖靈] 的 [1945年] 機、以及早期電腦教材，都以組合語言作為論證「計算可被形式化」的舞台。
- **抽象漏隙的樣板**：組合語言把硬體的時序、對齊、管線與快取完全暴露，寫出高效能系統的人稱之為「真相」，其他人稱之為「痛苦」。

## 指令與偽指令

- **真正指令**：由 ISA 定義，例如 x86 的 `mov eax, [rbx+8]`、`add eax, ebx`。
- **偽指令（pseudo-instruction）**：組譯器提供的便利寫法，例如 `mov eax, 5` 其實被展開為「把 5 載入暫存器」再「存入 eax」兩條真指令；擴充功能（extensions）是 Intel 後來把這些偽指令納入正式 ISA 的結果。
- **段與偏移**：x86 的邏輯位址由段選擇器加偏移組成，早期 DOS 與部分驅動程式大量利用這個特性做記憶體存取。
- **標籤與重定位**：組合語言中的符號（label）在組譯期換成相對位移或絕對位址，讓程式可以被載入任何位置。

## 範例：同一段邏輯的三種寫法

需求：把記憶體中陣列的十個元素加總。

**組合語言（x86-64）**：

```
sum:    xor eax, eax          ; 累加器歸零
        mov ecx, 10           ; 計數器設為 10
        mov rdx, [rbx]        ; 取第一個元素
loop1:  add rax, rdx          ; 累加
        add rdx, 8            ; 前進到下一個 64 位元元素
        dec ecx               ; 計數減一
        jnz loop1             ; 不為零則繼續
        ; rax 即為總和
```

**C 語言**：

```
long sum(long *a) {
    long s = 0;
    for (int i = 0; i < 10; i++) s += a[i];
    return s;
}
```

**Python 腳本**：

```
def total(a):
    return sum(a)
```

三段程式邏輯等價，但抽象層不同：組合語言要自己管位址、計數與迴圈；C 讓編譯器決定用哪些暫存器與迴圈形式；Python 則連計數器都不必出現。抽象每升高一層，程式碼行數下降，但對硬體的控制力也同步下降。

## 範例：組譯流程與「為什麼需要高階語言」

組譯器的工作流程極為機械：

```
組合語言原始碼
   │  1. 詞法與語法分析：辨識助記符、運算元
   │  2. 符號解析：把標籤換成位址（可能需二次掃描）
   │  3. 機器碼產生：依指令格式填入 opcode 與運算元
   │  4. 巨集展開（可多次）
   ▼
目的檔（.o）
```

因為是一比一翻譯，組譯器**無法**做全域最佳化：它不知道整個程式的意圖，也就無法決定「這個變數從未改變，應提升到暫存器」或「這個函式從未被呼叫，可刪除」。這正是 [高階語言] 與編譯器存在的理由——把語意資訊交給前端，讓最佳化器能跨函式、跨迴圈地最佳化。

## 前因後果

- **前因**：早期電腦以真空管與打孔卡操作，程式撰寫本身就是一場機器碼手工勞動；人腦讀十六進位的速度遠低於讀助記符，於是助記符方案自然勝出。
- **後果**：1950 年代起，組合語言成為大型系統（作業系統、編譯器、資料庫）的主力語言；直到今日，它仍在 boot code、韌體、效能關鍵路徑與驅動程式中不可或缺，也因此持續是 [資訊安全] 研究者關注的緩衝區溢出熱點。

## 與相鄰分類的關聯

- 與 [機器語言] 的關係：一比一的符號化；兩者是同一件事的兩種視角。
- 與 [高階語言] 的關係：編譯器的最終輸出層；高階語言程式最終都會被還原成組合語言與機器碼。
- 與 [控制結構] 的關聯：分支與迴圈在組合語言中就是標籤與跳躍指令組合。
- 與 [作業系統] 的關聯：系統核心與中斷處理多半直接寫在組合語言裡。

## 容易混淆之處

- **組合語言不等於低階語言**：低階語言是泛稱，組合語言是最常見的實例。
- **巨集語言與組合語言不同**：巨集語言是給 CPU 的文字格式（如 Intel HEX），組合語言是給人寫、由組譯器處理的。
- **反向工程不等於能還原原始碼**：反組譯得到的是組合語言，可能與原作者寫的完全不同。
- **行內組語言不是組合語言**：在 C 裡嵌入的組合片段，仍受宿主語言的抽象與約束。

## 技術要點

- 組譯是比對與查表的工作，速度快但最佳化空間小。
- 常見最佳化：立即數摺疊、跳躍重排、無用指令移除、位元組碼大小最佳化。
- 呼叫慣例（calling convention）決定參數傳遞、暫存器保存與清堆疊責任，是 ABI 的核心。
- 除錯需要理解暫存器、旗標暫存器與堆疊內容，因此需要特殊工具支援。
- 現代編譯器內聯-assembly 功能，讓開發者能在高階語言中插入少量低階指令以微調熱路徑。

## 常見的論爭

- **高階語言是否已「足夠快」**：多數程式瓶頸在演算法與 I/O 而非指令選擇；但在熱迴圈、加密、訊號處理等領域，低階仍具不可替代性。
- **可重定位碼是否值得放棄位置無關性**：位置相關程式碼可用更短的相對跳躍換取效能，代價是無法被載入器任意放置。
- **安全與效能的取捨**：停用可執行堆疊會讓某些漏洞無法利用，但會打斷慣例並增加開發摩擦。
