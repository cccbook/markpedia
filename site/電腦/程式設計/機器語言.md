# 機器語言

> 隸屬：[程式設計]　·　狀態：初稿

> 對應維基百科：[中文維基百科：机器语言](https://zh.wikipedia.org/wiki/%E6%9C%BA%E5%99%A8%E8%AF%AD%E8%A8%80)　·　[English Wikipedia: Machine code](https://en.wikipedia.org/wiki/Machine_code)

機器語言是**處理器真正能執行的指令位元組序列**：由 0 與 1 組成，每一組位元依處理器手册（instruction set manual）的定義，解碼成一條具體動作——把某個值搬進暫存器、做一次加法、跳到某個位址。它是程式與硬體之間唯一的共同語言，所有更抽象的語言最終都必須被還原成它才能執行。

## 技術與理論的關聯

- **指令集架構（ISA）是硬體的合約**：ISA 決定哪些位元組組合合法、每條指令多長、位址怎麼算；[微處理器] 的世代更替，本質上是 ISA 世代更替。
- **程式碼就是資料**：在 [馮·諾伊曼] 架構下，指令與資料同樣存放在記憶體裡，這讓「把程式當資料改寫」成為可能——這是 [作業系統] 自我修改、也是病毒能感染程式的技術根源。
- **編譯器的最終目標**：任何語言的編譯流程，最後一步都是產生機器語言；因此機器語言的格式決定了 linker、載入器、除錯器與反組譯工具的設計。
- **抽象漏隙在此最淺**：寫 [高階語言] 的人若要追求極致效能，就必須重新理解機器語言層級的暫存器、快取與分支預測。
- **韋爾納不完備性與可計算性**：哥德爾不完備定理說明不存在能判定所有程式的通用驗證器；這背後的直覺是「對一台機器而言，任意機器語言程式都是圖靈完备的」，因此沒有機械的捷徑。

## 指令集架構與編碼

- **定長與變長**：早期機器（如 [ENIAC] 的時代）多為定長指令；x86 早期為變長，換取更緊密的程式碼密度，代價是解碼複雜。
- **位元組碼（bytecode）**：JVM 與 WebAssembly 使用虛擬指令集——一種假想的機器語言，由執行期環境解譯或即時編譯，形成「一次編譯、處處執行」的跨平台模型。
- **RISC 與 CISC**：精簡指令集計算機減少指令種類以簡化流水線；複雜指令集計算機提供單指令完成複雜工作的能力。兩條路線在 1980–1990 年代收斂。
- **立即數、暫存器、記憶體**：指令的運算元可以取自指令內 immediates、暫存器，或記憶體位址；機器語言的複雜度大半來自如何編碼這三者的組合。
- **相對與絕對跳躍**：跳躍指令的目標位址若以相對位移表示，程式才能被載入任意位置——這是位置無關程式碼與共享函式庫的基礎。

## 範例：一次加法的機器碼

以 x86-64 為例，把暫存器 `eax` 的值加上 5：

```
83 C0 05
```

三個位元組逐段解讀：

```
83         opcode：帶 8 位元立即數的加法
C0        ModR/M：目的暫存器為 eax（編碼 000），無記憶體操作
05        立即數 5
```

若改寫成等價的組合語言，就是 `add eax, 5`；若再往上寫成 C，就是 `x = x + 5;`。三者的關係是「同一個動作的三種抽象高度」，詳見 [組合語言] 與 [高階語言]。

## 範例：從原始碼到可執行檔的完整流程

一個 C 程式要變成 CPU 能吃的位元組，中間要經過四步：

```
原始碼（.c）
   │  1. 前處理：展開 #include、#define 巨集
   ▼
組譯輸出（.s）        仍與組合語言一一對應
   │  2. 組譯：把每條指令翻成機器碼
   ▼
目標檔（.o）        含重定位資訊的機器碼區塊
   │  3. 連結：合併目標檔，解決符號位址
   ▼
可執行檔（.exe / ELF）  含程式碼、資料表與中繼資料
   │  4. 載入：作業系統映射到記憶體並交給 CPU
   ▼
執行中的機器碼
```

關鍵在於：**每一步都只是把語法糖剝掉一層**。編譯器做的是「整體翻譯」，把高階結構最佳化後再產生機器碼；組合語言則是「一一對應」，翻譯難度低，但無法做全域最佳化——這是 [高階語言] 存在的根本原因：單靠人寫的組合語言，幾乎不可能做出好的全域排程與快取行為。

## 前因後果

- **前因**：1940 年代的真空管機器沒有編譯器，程式透過plugboard接線或以機器碼直接輸入；[1945年] 存程式概念的提出，讓「程式是存在記憶體裡的一串指令」成為可能，機器語言才第一次成為可攜、可複製的東西。
- **後果**：機器語言的笨拙直接催生了整條 [程式語言的演進] 線——先是便於書寫的 [組合語言]，再是讓人描述意圖的 [高階語言]，最後是讓執行環境代勞一切 [腳本語言]。

## 與相鄰分類的關聯

- 與 [組合語言] 的關係：兩者一一對應；組合語言是機器語言的人類可讀投影。
- 與 [語言典範] 的關係：典範決定產生什麼樣的機器碼——[命令式] 幾乎一比一映射為指令序列，而 [函式式] 與 [宣告式] 需要編譯器做更激進的轉換。
- 與 [控制結構] 的關係：分支、迴圈、遞迴在機器層都是「條件跳躍」與「無條件跳躍」的組合。
- 與上位概念 [程式設計] 的關係：機器語言是程式設計最底層的硬體邊界。

## 容易混淆之處

- **機器語言不等於二進位檔案**：二進位檔案還包含資料表、符號、資源等；機器語言只是其中可執行的指令部分。
- **反組譯不等於還原原始碼**：機器碼資訊量有限，原始碼中的註解、區塊結構與高階抽象在編譯時已大量流失。
- **位元組碼不是「壞掉的機器碼」**：它刻意設計成可移植與可驗證，安全性與可攜性優先於直接效率。
- **速度差異不是數量級差異**：多數現代語言的差距來自是否繞過直譯、是否善用快取，而非指令集本身的差距。

## 技術要點

- 指令由 opcode 加運算元編碼而成，長度與格式由 ISA 固定。
- 機器碼與作業系統緊耦合：系統呼叫、位址模型、暫存器保存規則都由 ISA 與 ABI 共同決定。
- 位元組序（大小端）決定多位元組資料在記憶體中的排列方式，跨平台傳輸時必須轉換。
- 反組譯與反編譯是逆向工程的基礎工具，也是安全審查的常規手段。
- 效能分析工具（計數器、效能分析器）最終都在採樣機器碼層級的執行狀態。

## 常見的論爭

- **是否應該直接寫機器碼**：在資源極受限的場合（bootloader、韌體、嵌入式）仍有其地位，但除錯與維護成本極高。
- **韌體與作業系統的邊界**：兩者都直接操作機器碼，誰該承擔硬體抽象層的責任，至今仍是設計取捨。
- **指令集擴充的代價**：新的向量或加密指令可大幅提升特定負載效能，卻也讓舊硬體無法執行新程式碼。
