# 腳本語言

> 隸屬：[程式設計]　·　狀態：初稿

> 對應維基百科：[中文維基百科：脚本语言](https://zh.wikipedia.org/wiki/%E8%84%9A%E6%9C%AC%E8%AF%AD%E8%A8%80)　·　[English Wikipedia: Scripting language](https://en.wikipedia.org/wiki/Scripting_language)

腳本語言是**為了「快速完成一件小事」而設計的解譯型語言**：它通常沒有獨立編譯步驟，由解譯器讀取原始碼逐句或逐段執行，並且內建大量與系統操作、檔案處理、文字處理、資料擷取直接相關的高階功能。腳本程式多半是短的、一次性的、與其他程式協作的 automating 工具，而不是完整的應用程式本體。

## 技術與理論的關聯

- **膠著語言的角色**：腳本語言常被用來「黏合」既有的元件——呼叫命令列工具、串接資料管線、調用另一門語言寫的函式庫。它們的價值在於生態系與便利性，而非語言本身的理論優雅。
- **互動式開發的傳統**：shell、Lisp、REPL 讓程式碼被立即執行與檢視，這種「求值—回饋」循環深刻影響了 [資料科學] 與 [人工智慧] 的工作流。
- **直譯與即時編譯的折衷**：早期腳本語言以直譯換取啟動速度，現代引擎（如 JavaScript 引擎）大量使用即時編譯，把熱點函式編譯成機器碼，使腳本語言效能逼近編譯語言。
- **動態型別的典型棲地**：腳本語言多採 [動態型別]，因為「先跑起來再說」符合其快速原型與自動化的用途；型別錯誤被推遲到執行期，代價是較晚發現。
- **可內嵌性**：腳本語言常被嵌入大型應用程式作為擴充機制，例如在 [作業系統] 或應用程式中提供可編輯的自動化層。

## 腳本語言的常見特徵

- **內建文字處理**：正則表達式、字串格式化、編碼轉換幾乎是標配。
- **互動式直譯器（REPL）**：一行輸入立即得到結果，縮短「想法—驗證」距離。
- **動態載入與元程式設計**：執行期決定要載入哪些模組，plug-in 架構因此容易實作。
- **跨平台**：以系統呼叫的抽象層加上各平台特定擴充，兼具通用與專用。
- **程式碼即資料**：把程式碼當作字串或資料結構處理，讓 meta 程式設計、程式碼生成與測試框架得以建立。

## 範例：一段真正有用的腳本

需求：把某個目錄下所有文字檔案的行尾統一為換行，並統計總行數。

```
#!/usr/bin/env python3
"""統計並正規化文字檔案的行尾。"""
import pathlib
import sys

def normalize(path):
    """讀取檔案、正規化行尾、回寫，回傳行數。"""
    text = path.read_text(encoding="utf-8")
    lines = text.replace("\r\n", "\n").replace("\r", "\n").split("\n")
    if lines and lines[-1] == "":
        lines.pop()
    path.write_text("\n".join(lines) + "\n", encoding="utf-8")
    return len(lines)

def main(root):
    """走訪目錄、逐檔處理並印出統計。"""
    total = 0
    for path in sorted(pathlib.Path(root).rglob("*.txt")):
        count = normalize(path)
        total += count
        print(f"{path}: {count} 行")
    print(f"合計 {total} 行", file=sys.stderr)

if __name__ == "__main__":
    main(sys.argv[1] if len(sys.argv) > 1 else ".")
```

這段腳本的特徵正是腳本語言的定義：以標準函式庫的少量高階功能（路徑走訪、文字讀寫、串流輸出）組出完整功能；不到三十行就完成了一件在低階語言需要大量样板程式碼的工作；同時以 `__name__ == "__main__"` 守住「可被匯入也可直接執行」的雙重身份。

## 範例：腳本與應用程式在工程上的分工

```
┌──────────────┐   呼叫    ┌──────────────┐   載入    ┌──────────────┐
│   腳本層      │ ────────▶ │   應用程式    │ ────────▶ │   函式庫      │
│  自動化工序    │           │  長駐服務    │           │  核心演算法    │
└──────────────┘           └──────────────┘           └──────────────┘
     短、易改、負責串接            穩定、負責狀態              重、負責正確性
```

分工原則是：把會變動、對錯誤容忍度較高、頻率不高的部分寫成腳本；把核心正確性與效能敏感的路徑寫成函式庫與長期服務。現代 [軟體工程] 的 DevOps 實踐大量採用這個組合——用腳本做部署、監控與資料處理流水線。

## 前因後果

- **前因**：作業系統誕生時就自帶命令 shell，本質上就是最早的腳本語言；1980 年代的 Perl 把腳本從「處理檔案」擴展到「處理文字」，成為系統管理員的標準工具。
- **後果**：Web 動態網站、資料探勘、DevOps 自動化、科學研究與 [人工智慧] 模型的訓練腳本，絕大多數以腳本語言撰寫。腳本語言是把非工程背景的人員拉進程式設計世界的門票。

## 與相鄰分類的關聯

- 與 [高階語言] 的關係：同屬高階抽象，但執行模型與設計意圖不同。
- 與 [控制結構] 的關聯：腳本大量依賴迴圈、條件與例外處理來處理不可預期的輸入。
- 與 [物件導向] 的關聯：現代腳本語言多半是物件導向的，這讓大型腳本仍能維持結構。
- 與 [軟體工程] 的關聯：腳本是自動化流水線的主力，也是不斷變動的環境中最需要嚴謹測試的部分。

## 容易混淆之處

- **腳本語言不等於「不正式的語言」**：Python 同時是腳本語言、也是教學語言與後端語言。
- **直譯不等於慢**：現代即時編譯讓 JavaScript 與 Python 的熱迴圈效能大幅提升。
- **shell 指令不等於腳本語言**：shell 是組合語言與執行環境的混合體，歷史包袱重且跨平台性差。
- **動態型別不是腳本語言的必然**：TypeScript 就是在 JavaScript 上加上 [靜態型別] 的例子。

## 技術要點

- 執行模型：直譯、混合模式、即時編譯三種。
- 啟動時間往往是腳本在伺服器端工作負載中的真實瓶頸。
- 套件管理與依賴版本解析（PyPI、npm）是腳本生態的核心工程問題。
- 沙箱與權限模型是腳本被用於擴充機制時的安全關鍵。
- 互動式直譯器是腳本語言保有開發者黏著度的重要原因。

## 常見的論爭

- **腳本是否「不算真正的程式」**：一派認為缺少靜態型別與編譯期保證者難以維護；實務上腳本承擔的關鍵流程越來越多。
- **依賴樹的複雜度**：方便但難以審計的第三方套件，是供應鏈攻擊的主要入口。
- **效能與可攜性的取捨**：使用 C 擴充可大幅提升速度，卻降低可攜性並增加建置複雜度。
