# 高階語言

> 隸屬：[程式設計]　·　狀態：初稿

> 對應維基百科：[中文維基百科：高级语言](https://zh.wikipedia.org/wiki/%E9%AB%98%E7%BA%A7%E8%AF%AD%E8%A8%80)　·　[English Wikipedia: High-level programming language](https://en.wikipedia.org/wiki/High-level_programming_language)

高階語言是**用接近人類表達方式的記號來描述計算的語言**：它把「把值搬到暫存器」這類硬體步驟，改寫成「宣告變數、呼叫函式、返回結果」等與問題領域相關的敘述。相對 [機器語言] 與 [組合語言]，高階語言把「怎麼做」交給編譯器，讓程式師專注於「做什麼」。

## 技術與理論的關聯

- **抽象的代價與回報**：高階語言用可攜性（同一份原始碼可在多種處理器上編譯）與生產力（程式碼行數大幅減少）換取對硬體的直接控制；這筆交易是整個軟體產業得以成立的前提。
- **形式語言與語意學**：每種高階語言背後都有一套抽象語意（operational semantics、denotational semantics），語言的行為由語意而非實作決定。
- **編譯理論**：自動機理論、可判定性、SSA 形式、資料流分析等數學工具，直接支撐了編譯器的最佳化能力——這是 [數學] 與工程交會最密集的領域之一。
- **型別理論的落地**：高階語言是第一個能把型別註記變成「機器可查的規格」的層級；[型別系統語法] 中的靜態與動態之爭，幾乎完全是高階語言的內部問題。
- **範式承載**：同一種高階語言可以承載多種典範——Python 既能寫 [命令式] 也能寫 [函式式]；語言提供能力，典範決定用法。

## 高階語言的共同特徵

- **抽象的資料型別**：整數、浮點數、文字、陣列、記錄，取代裸位元組操作。
- **記憶體管理自動化**：從手動配置到垃圾回收，讓程式碼行數減少，但也帶來不可預期的暫停時間。
- **表達式與陳述式**：運算式可回傳值，陳述式產生副作用；兩者的比例是衡量語言風格的重要指標。
- **模組與命名空間**：把大型程式拆成可獨立編譯、可重用的單元。
- **內建高階資料結構**：串列、字典、集合，讓演算法實作不必重寫佇列與雜湊表。

## 範例：加總函式的抽象層遞減

**C（靜態型別、命令式）**：

```
int sum(int *a, int n) {
    int s = 0;
    for (int i = 0; i < n; i++)
        s += a[i];
    return s;
}
```

**Python（動態型別、命令式）**：

```
def total(a):
    s = 0
    for x in a:
        s += x
    return s
```

**Haskell（函式式）**：

```
total :: [Int] -> Int
total = sum
```

**SQL（宣告式）**：

```
SELECT SUM(amount) FROM orders;
```

四段程式做的事情完全一樣，但表達的重心逐步右移：從「怎麼迴圈」到「什麼是資料」再到「想要什麼結果」。[宣告式] 把「怎麼算」交給查詢最佳化器；[函式式] 把狀態變更交給代數規則；命令式則保留最直接的控制權。

## 範例：從原始碼到高效能機器碼

高階語言的編譯流程比 [組合語言] 複雜得多，也正是它能產生更好程式碼的原因：

```
原始碼（.py / .java / .rs）
   │  1. 詞法分析：字元流 → 詞法單元
   │  2. 語法分析：詞法單元 → 抽象語法樹（AST）
   │  3. 語意分析：名稱解析、型別檢查、作用域檢查
   │  4. 中間表示（IR）：AST → SSA 形式的中間表示
   │  5. 最佳化：常數摺疊、內聯、向量化、快取優化
   │  6. 目標代碼產生：IR → 機器碼
   │  7. 連結：合併目標檔
   ▼
可執行檔
```

關鍵在第 5 步：因為前端保留了高階語意（型別、別名關係、迴圈不變量），最佳化器可以做出超越人力的重寫，例如把迴圈向量化為向量指令、把不常走的分支移出熱路徑。單靠一比一的組譯永遠做不到這一點。

## 前因後果

- **前因**：早期寫 [作業系統] 需要直接操作 [暫存器] 與記憶體位址，撰寫成本高、可攜性差；FORTRAN（[1956年]）首次讓「寫數學公式」成為可行的高階寫法，隨後 COBOL 與 ALGOL 把它推廣到商業與教學場合。
- **後果**：高階語言讓軟體從少數專家的工作變成整個產業的生產活動；它同時催生了 [物件導向]（以抽象與封裝管理複雜度）、[靜態型別] 與 [動態型別] 的路線之爭，以及現代軟體工程方法論的基礎。

## 與相鄰分類的關聯

- 與 [機器語言]、[組合語言] 的關係：抽象層最高的兩者，是高階語言的下游。
- 與 [腳本語言] 的關係：同樣高階，但執行模型不同——腳本語言以「快速取得結果」為優先。
- 與 [語言典範] 的關係：語言提供能力集合，典範提供思考方式。
- 與 [軟體工程] 的關係：高階語言的可讀性直接決定大型專案的可維護性。

## 容易混淆之處

- **高階不代表執行效率差**：多數高階語言的編譯器最佳化水準已足以讓其在大多數工作負載上接近手寫組合語言。
- **高階不等於完全脫離硬體**：記憶體模型、快取、GC 暫停仍是高階程式效能的主要變數。
- **直譯的高階語言仍是高階語言**：執行方式與抽象層級是兩個正交的問題。
- **高階語言與腳本語言邊界模糊**：Python、JavaScript 同時被兩類使用者使用，分類依據是設計意圖與慣例，而非語法。

## 技術要點

- 高階語言的共同特徵是抽象的資料型別、自動記憶體管理、模組化與內建資料結構。
- 編譯流程的前端（解析、型別檢查）與後端（最佳化、機器碼產生）可獨立演進，這是語言實作多元化的技術基礎。
- 靜態型別語言把檢查成本前移，[動態型別] 把成本後移；漸進型別試圖兩者兼得。
- 執行模型分為預先編譯、即時編譯與直譯三種主軸。
- 跨平台策略分為「同一份原始碼各自編譯」與「同一份位元組碼由虛擬機器執行」。

## 常見的論爭

- **靜態型別是否必然更安全**：型別能擋下形狀錯誤，卻擋不住邏輯錯誤；反之，動態語言靠測試與型別提示補足。
- **抽象是否過度**：框架與樣板語言讓簡單任務變冗長，是對高階抽象的常見批評。
- **新語言的壽命**：語言興衰往往取決於生態系而非語言設計本身。
