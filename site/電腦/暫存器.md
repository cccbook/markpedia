# 暫存器

> 隸屬：[電腦] › [電腦架構]　·　狀態：初稿

> 對應維基百科：[中文維基百科：暫存器](https://zh.wikipedia.org/wiki/%E5%AF%84%E5%AD%98%E5%99%A8)　·　[English Wikipedia: Processor register](https://en.wikipedia.org/wiki/Processor_register)

暫存器是**CPU 內部速度最快、容量最小的資料保存單元**。它以正反器電路直接存在於處理器核心之中，存取延遲不到一奈秒，容量以「個」計而非以「GB」計。程式中絕大多數的實際計算——加法、比較、移位——都發生在暫存器之間，記憶體只是暫存器的倉庫。

暫存器可分為兩類：**通用暫存器**（程式設計師可自由使用，如 x86-64 的 rax、rbx…共 16 個）與**專用暫存器**（程式計數器 PC、堆疊指標 SP、旗標暫存器 FLAGS、MMU 的控制暫存器等）。後者決定機器的行為，前者承載資料。

## 技術與理論的關聯

- **數量與編譯器**：通用暫存器越多，編譯器越能把常用變數留在 CPU 內，減少記憶體存取；x86 的 8 個（32 位元時代）是編譯器長期做「暫存器分配」小動作的原因。
- **指令編碼的取捨**：每條指令要指出來源與目的暫存器，RISC-V 用 5 位元表示 32 個暫存器；數量增加會加大指令長度。
- **旗標暫存器**：零、符號、溢位、進位旗標由算術運算自動更新，分支指令靠它們判斷條件。
- **專用暫存器即機器狀態**：程式計數器決定執行到哪，堆疊指標決定函式呼叫的框架，中斷發生時保存這些狀態才能切換行程。
- **浮點與向量暫存器**：x87 的 st(0..7)、SSE 的 xmm（128 位元）、AVX 的 ymm/zmm（256/512 位元），一個暫存器可裝多個資料做 SIMD。
- **亂序執行下的物理暫存器**：現代 CPU 以「暫存器重命名」把架構暫存器映射到數百個物理暫存器，讓不相干的指令互不阻塞。

## 範例

**問題**：計算 3+5 與其平方，觀察暫存器如何在指令之間搬運資料。

```asm
mov eax, 3      ; eax ← 3
add eax, 5      ; eax ← 8
imul eax, eax   ; eax ← 64
```

1. **載入**：立即數 3 直接編碼在指令裡，載入通用暫存器 eax。
2. **運算**：`add` 讀 eax（3）與立即數 5，ALU 輸出 8 寫回 eax；零旗標清為 0。
3. **自乘**：`imul eax, eax` 同時以 eax 為來源與目的地，得 64；若結果超出 32 位元會升起溢位旗標。
4. **對照記憶體版本**：若變數存在記憶體，每次運算前要 `mov eax, [x]`、運算後 `mov [x], eax`，每來回約 1 至 4 奈秒；暫存器版本省下這些往返，這是編譯器最佳化「暫存器分配」省下的實際時間。
5. **重命名視角**：在亂序 CPU 上，上述三條指令的 eax 其實對應三個不同的物理暫存器，硬體用記分板消除假相依（WAR、WAW 冒險）。
6. **狀態保存**：若第三條指令前發生 [中斷]，作業系統要保存 eax、旗標與 PC，回來時原樣恢復——暫存器是行程上下文的最小核心。

## 前因後果

- **前因**：繼電器與真空管時代就有累加器概念（ENIAC 的累加器），積體電路把數十個暫存器放進核心變得廉價。
- **後果**：暫存器數目直接影響指令集設計（RISC 的 32 個對 CISC 的 8 個），亂序重命名技術進而催生了超純量架構；SIMD 暫存器則成為多媒體與 AI 加速的硬體基礎。

## 與相鄰分類的關聯

- 與 [馮諾依曼] 的關聯：PC、IR、ACC 三個暫存器是馮氏循環的骨架。
- 與 [匯流排] 的關聯：暫存器與記憶體之間的所有搬運都要經匯流排。
- 與 [階層式儲存] 的關聯：暫存器是階層的最頂層，向下每一層都更慢更大。
- 在上位概念 [電腦架構] 中，暫存器是「CPU 的口袋」。

## 容易混淆之處

- **暫存器與快取不同**：暫存器由指令顯式指定，快取由硬體自動管理。
- **架構暫存器與物理暫存器不同**：前者是程式看得見的名字，後者是硬體實際擁有的資源。
- **通用暫存器與 I/O 埠不同**：早期 x86 用 `in`/`out` 指令讀寫設備暫存器，現代多改用記憶體映射。
- **堆疊不是暫存器**：堆疊在記憶體中，SP 暫存器只是它的指標。

## 技術要點

- x86-64 有 16 個 64 位元通用暫存器；ARM64 與 RISC-V 各有 31 至 32 個。
- 呼叫慣例（caller-saved 與 callee-saved）決定哪些暫存器在函式呼叫時需保存。
- 旗標暫存器的零旗標是條件分支（`jz`、`jnz`）的唯一依據。
- 暫存器重命名讓「寫後寫」的假相依消失，是亂序執行的第一道工序。
- 向量暫存器一次可載 8 個 32 位元整數，SIMD 運算把它們同時處理。
- 上下文切換的成本主要就是保存與恢復一組暫存器（約百奈秒等級）。

## 常見的論爭

- **暫存器該有多少**：RISC 陣營主張 32 個以降低記憶體流量，CISC 陣營以編碼緊湊反駁；x86-64 的 16 個是妥協。
- **堆疊機與暫存器機**：Java 位元碼以堆疊為中心，理論簡潔；JIT 編譯回暫存器機器執行，效率之爭早已分出高下。
- **暴露還是隱藏硬體細節**：把物理暫存器直接暴露給程式（RISC 哲學）還是經過重命名隱藏（亂序哲學），關乎架構的壽命與複雜度。

## 實務補充：暫存器的分配策略

暫存器數量稀少，因此編譯器在「把常用值留在暫存器」與「把結果存入記憶體」之間做取捨。少數暫存器被指定用途：指令指標 PC、堆疊指標 SP、旗標暫存器與通用暫存器分離，確保中斷時能保存必要狀態。

暫存器的讀寫延遲通常為 0 到 1 個時脈，但要注意相依性（dependency）：若一條指令的來源是前一條指令的目的，即使兩者都在暫存器，流水線也要等待，這是現代處理器頻率難以再提升的主因之一。編譯器因此大量使用指令重排來填補延遲空隙。
