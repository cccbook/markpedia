# 電腦架構

> 隸屬：[電腦]　·　狀態：初稿

> 對應維基百科：[中文維基百科：計算機系統結構](https://zh.wikipedia.org/wiki/%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%B3%BB%E7%BB%9F%E7%BB%93%E6%9E%84)　·　[English Wikipedia: Computer architecture](https://en.wikipedia.org/wiki/Computer_architecture)

電腦架構研究**計算機的功能組織與其對軟體呈現的介面**。它回答的問題是：一部機器要有哪些部件（運算器、控制器、暫存器、匯流排）、部件之間如何連接、指令以什麼格式呈現給程式。架構是硬體工程師與軟體工程師之間的合約——同一份架構規格（如 x86 或 ARM）可以由不同廠商、不同電路技術實現，軟體不必改寫。

現代架構的起點是 1945 年 [馮·諾伊曼] 的 EDVAC 報告。它把指令與資料放進同一個記憶體，用取指—解碼—執行的循環統一了一切計算的形狀。此後的進展幾乎都在這個循環內做文章：把循環拆成流水線、在循環中同時發射多條指令、用快取隱藏記憶體延遲、用多核複製整個循環。

## 技術與理論的關聯

- **儲存程式原則**：指令是資料，因此程式可以載入、修改與生成；這是所有高階語言、編譯器與作業系統的前提。
- **取指—解碼—執行循環**：程式計數器指向下一條指令，控制單元按操作碼分派到算術單元、記憶體或分支邏輯。
- **匯流排分層**：位址匯流排決定可定址空間（32 位元可定址 4 GiB），資料匯流排寬度決定一次搬多少位元，控制匯流排協調時序。
- **中斷機制**：外部事件（按鍵、計時器、磁碟完成）以中斷訊號打斷當前執行，作業系統靠它實現事件驅動與多工。
- **指令集的兩大流派**：CISC（x86，指令多而長，硬體複雜）與 RISC（ARM、RISC-V，指令少而等長，易於流水線化）；兩者近年互相趨同。
- **效能公式**：CPU 時間 ≈ 指令數 × 每指令時脈數（CPI）× 時脈週期，三個因子分別由演算法、架構與電路決定。

## 範例

**問題**：一個簡單的累加程式在架構層如何執行？

```
sum = 0
for i in 1..4:
    sum = sum + i
```

1. 編譯成類組合語言：`mov eax,0`、`mov ecx,1`、`loop: add eax,ecx`、`inc ecx`、`cmp ecx,5`、`jle loop`。
2. **取指**：程式計數器指向第一條指令，從指令快取讀入；PC 自動指向下一條。
3. **解碼**：`add eax,ecx` 被解碼為「ALU 做加法，來源暫存器 ecx，目的暫存器 eax」。
4. **執行**：ALU 計算 0+1=1，寫回 eax；旗標暫存器更新零值與符號位。
5. **分支**：`jle` 檢查旗標，若條件成立把 PC 改寫回 `loop` 標號位址——分支指令讓短短幾條指令構成無限長的執行。
6. **結果**：迴圈四輪後 eax = 10，共執行 4×4+2 = 18 條指令；若每條 CPI 為 1，在 1 GHz 的機器上耗時 18 微秒。

這個例子也顯示流水線的必要性：若每條指令要等前條完成，18 條指令佔 18 週期；五級流水線可讓理想情況壓到約 6 週期——架構設計對效能的影響一目了然。

## 前因後果

- **前因**：機械計算器的「專用性」瓶頸——改用途等於改機器——催生了儲存程式的通用設計。
- **後果**：架構概念直接孕育了作業系統（中斷驅動的多工）、編譯器（把高階語言翻成架構指令）與效能工程（以 CPI 與快取命中率為目標）；RISC 思潮反過來簡化硬體，促成 ARM 生態。

- 與 [資料表示] 的關聯：架構的一切運算都以二進位編碼為前提，二補數加減法與移位是指令集的基本操作。
- 與 [作業系統] 的關聯：中斷、特權等級與記憶體保護是架構提供給作業系統的三大支柱。
- 與 [電子工程] 的關聯：架構是抽象合約，電子工程負責把合約落實為邏輯閘與晶片。
- 在上位概念 [電腦] 中，本子分類扮演骨架的角色，其效能極限驅動了 [儲存與記憶體] 的階層設計。

## 容易混淆之處

- **架構與微架構不同**：x86 是架構（指令集合約），Intel 的 Skylake 是微架構（具體實現）；同架構可有許多微架構。
- **馮諾依曼與哈佛架構不同**：後者把指令與資料記憶體分開，常見於微控制器；現代 x86 在快取層面採哈佛式、主記憶體層面採馮式。
- **暫存器與記憶體不同**：前者在 CPU 內、以位元組數計，後者在 CPU 外、以 GiB 計。
- **中斷與例外不同**：中斷來自外部且異步，例外來自當前指令（如除以零）且同步。
- **CPI 低不等於程式快**：總時間還取決於指令數與時脈，編譯器最佳化可能用更多指令換更低 CPI。

## 技術要點

- 程式計數器是唯一決定「下一條執行什麼」的狀態；分支就是把 PC 改寫。
- 通用暫存器通常 16 個（x86-64）到 32 個（ARM64、RISC-V），數目越多可減少記憶體存取。
- 特權等級（ring 0 至 ring 3）把作業系統與使用者程式分開，是保護的基礎。
- 流水線冒險分為結構、資料與控制三類，分別以資源複製、轉送與分支預測解決。
- 一致性快取協定（如 MESI）讓多核各自快取同一主記憶體而不出錯。
- 異構架構把 GPU、加速器接入同一系統，PCIe 匯流排是主要的互連通道。

## 常見的論爭

- **CISC 與 RISC 誰勝**：理論上 RISC 較優，實務上 x86 靠譯碼層把 CISC 指令拆成微操作，兩派已合流。
- **多核與單核的取捨**：增加核心需要軟體並行化配合，否則「免費的效能午餐」在 2005 年後結束的論斷是否成立仍受爭論。
- **自訂指令集的價值**：RISC-V 開源模式是否會分裂生態，或像 Linux 一樣統一，尚無定論。
