# 匯流排

> 隸屬：[電腦] › [電腦架構]　·　狀態：初稿

> 對應維基百科：[中文維基百科：匯流排](https://zh.wikipedia.org/wiki/Bus)　·　[English Wikipedia: Bus (computing)](https://en.wikipedia.org/wiki/Bus_%28computing%29)

匯流排是**電腦內部各部件之間傳送資訊的公共通道**。它把多個設備接在同一組訊號線上，用位址指定「說給誰聽」、用控制訊號約定「何時能說」，一次只有一個發話者。沒有匯流排，每對部件都要專線相連，接線數量會隨設備數平方增長；有了匯流排，加一個設備只是多一個接頭。

匯流排的三個基本組成：**位址匯流排**（單向，指定目標位址，寬度決定可定址空間）、**資料匯流排**（雙向，搬運資料，寬度決定一次搬多少位元）、**控制匯流排**（傳送讀寫命令、時脈、中斷與就緒訊號）。理解匯流排等於理解電腦內「誰在什麼時候能把資料送到哪里」的全部規則。

## 技術與理論的關聯

- **匯流排仲裁**：多個主控設備（CPU、DMA 控制器、GPU）都想發話時，由仲裁器按優先權或輪轉授權；沒有仲裁就會訊號衝突。
- **匯流排寬度與定址**：32 位元位址匯流排可定址 $2^{32}$ 位元組（4 GiB）；x86-64 實際用 48 位元定址，可達 256 TiB。
- **時脈與同步**：同步匯流排以共享時脈決定取樣時刻，簡單但受傳播延遲限制；PCIe 這類高速匯流排改用各設備自帶時脈的內嵌時鐘。
- **匯流排的演化**：ISA（8/16 位元）→ PCI（32/64 位元）→ PCIe（串列分通道）；方向是從「多條線並行」走向「差動串列 + 高頻率」，因為線越多、越快，訊號完整性越難。
- **DMA 直達**：DMA 控制器不經 CPU 直接在記憶體與設備之間搬資料，佔用匯流排時 CPU 可以做別的事。
- **中斷匯流排**：中斷請求也是匯流排服務的一部分，現代系統以 MSI（訊息式中斷）把中斷寫成一次記憶體寫入。

## 範例

**問題**：CPU 從記憶體位址 0x1234 讀取一個 32 位元整數，匯流排上發生什麼？

1. **位址階段**：CPU 把 0x1234 放上位址匯流排，控制線升起「記憶體讀」訊號。
2. **仲裁**：假設此時 GPU 也想寫顯示記憶體，仲裁器讓 CPU 優先（或按輪轉次序）。
3. **等待**：記憶體控制器把位址解碼、送到 DRAM，約 60 奈秒後資料就緒；匯流排以「就緒」訊號完成握手。
4. **資料階段**：4 個位元組放上資料匯流排，CPU 採樣後鎖入暫存器。
5. **量化**：若匯流排每週期傳 8 位元組、頻率 1 GHz，頻寬為每秒 8 GB；DDR4 實際以 64 位元匯流排 × 2400 MT/s 達到約 19.2 GB/s，兩個通道接近 38 GB/s。
6. **升級意義**：當頻率升不動時，設計者改用多通道（加寬）或串列多通道（PCIe 每通道每方向約 1 GB/s，x16 即 16 GB/s）——匯流排設計是頻寬工程。

## 前因後果

- **前因**：早期計算機（如 EDVAC）內部以單線逐位傳送，速度受限；把多條訊號線並行化成「匯流排」是第一代規模化手段。
- **後果**：匯流排標準化讓外設產業成為可能——任何廠商的卡插進 PCI/PCIe 槽就能工作；串列化的 PCIe 又反過來促成 NVMe 這類把協定搬到匯流排上的新標準。

## 容易混淆之處

- **匯流排與匯流排寬度不同**：匯流排是通道本身，寬度是每次傳送的位元數。
- **內部匯流排與外部匯流排不同**：前者連接 CPU 與記憶體，後者（USB、SATA）連接外設，速度與規範完全不同。
- **並行匯流排不等於更快**：訊號之間的干擾（串音）與時脈偏斜使高速並行反而不可行，PCIe 轉向串列就是證明。
- **頻寬與延遲不同**：頻寬是每秒可搬多少，延遲是單次往返多久；兩者常被混為一談。

## 技術要點

- 三態閘使設備在不發話時呈高阻抗，這是匯流排共享的電路基礎。
- 匯流排上的「握手」協定保證收發雙方步調一致，慢設備以等待訊號拉長週期。
- PCIe 以通道（lane）為單位，x1、x4、x8、x16 代表通道數，頻寬線性放大。
- 匯流排頻寬估算公式：頻寬 = 頻率 × 寬度 × 每週期傳送次數。
- NUMA 系統中，遠端節點的記憶體要跨匯流排互連，延遲可多出五成。
- 晶片組時代結束後，匯流排控制器被整合進 CPU 的「平台控制器」（PCH）。

## 常見的論爭

- **並行與串列之爭**：PCI 轉 PCIe 被視為串列勝利，但記憶體匯流排至今仍是並行，兩者的最佳點仍在移動。
- **匯流排開放性**：專利與授權費讓部分廠商推開放標準（如 RISC-V 的開放互連），與封閉高效路線競爭。
- **光匯流排的時機**：以光互連取代銅線在資料中心已現雛形，何時進入晶片內部尚無定論。

## 實務補充：匯流排的現代變形

傳統的共享匯流排在多核時代成為瓶頸：多個核心同時請求記憶體時，仲裁邏輯會讓所有請求排隊，頻寬利用率隨核心數增加而下降。主流處理器因此改用点到點互連：每個核心有專屬記憶體控制器與多條通道，記憶體以交錯方式分布在多個通道，頻寬得以線性擴展。

PCI Express 是另一個現代匯流排的例子。它由多條串行通道組成，每條通道獨立傳輸並以封包交換為單位，能在相同插槽上提供不同速率——這是「匯流排」從共享匯流排演化成協定套件的縮影。

匯流排設計還要處理時間一致性問題。當匯流排仲裁讓不同裝置看到彼此操作的不同順序時，IOMMU 等機制被用來維持裝置側的記憶體視圖一致。

### 匯流排協定的基本要素

一條匯流排要定義的要素包括：位址與資料的寬度、時序（誰在何時發出訊號）、仲裁（多個master同時請求時如何決定）、以及傳輸模式（單次、塊傳輸、連續傳輸）。不同匯流排在這四項上的取捨不同，也決定了它們能承載的裝置類型。

匯流排的頻寬計算很單純：資料寬度乘以傳輸頻率再乘以每次傳輸的數量，但實際可用頻寬往往低於理論值，因為仲裁、等待、協定開銷與快取一致性流量都會佔用通道。

### 設計取捨

頻寬、延遲與成本三者互相牽動：加寬匯流排可以提高頻寬但拉長佈線與功耗；提高時脈頻率可以拉低延遲，但訊號完整性與同步成本隨之上升。因此現代系統普遍採分層與分組的匯流排結構，把高頻通道限制在晶片內，把低速外設集中到較慢的控制器上。
