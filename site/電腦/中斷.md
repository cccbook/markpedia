# 中斷

> 隸屬：[電腦] › [電腦架構]　·　狀態：初稿

> 對應維基百科：[中文維基百科：中斷](https://zh.wikipedia.org/wiki/%E4%B8%AD%E6%96%B7)　·　[English Wikipedia: Interrupt](https://en.wikipedia.org/wiki/Interrupt)

中斷是**外部或異常事件要求 CPU 暫停當前程式、轉去處理緊急事務的機制**。它的本質是一條硬體訊號線：磁碟完成讀取、網路卡收到封包、計時器到期時，設備把中斷請求線拉起，CPU 在指令邊界暫停、保存現場、跳到預定的處理函式，處理完再恢復現場繼續。

中斷與輪詢（polling）是一對對照方案：輪詢要 CPU 反覆詢問「好了嗎」，浪費時間；中斷讓 CPU 專心工作、事件發生時才被打擾。沒有中斷就沒有高效的多工——作業系統的「同時」錯覺完全建立在計時器中斷的規律打斷之上。

## 技術與理論的關聯

- **兩大類別**：硬體中斷（外部設備發起，異步）與例外（當前指令引發，同步，如除零、缺頁、除錯陷阱）。
- **中斷向量表**：每個中斷號對應一個處理函式位址；x86 的 IDT、ARM 的向量表都是這張表。
- **現場保存與優先權**：中斷發生時硬體自動保存 PC 與旗標，其餘暫存器由處理函式保存；高優先權中斷可以打斷低優先權處理函式，形成巢狀。
- **遮罩與臨界區**：程式可以用關中斷指令保護一小段不可分割的程式碼，但關太久會丟事件、增延遲。
- **訊息式中斷（MSI）**：PCIe 世代不再用專用訊號線，而是讓設備「寫一次記憶體」來通知，數量不再受限於線數。
- **中斷負載與緩解**：每秒數百萬次中斷會耗盡 CPU；技術對策包括中斷合併、NAPI 式輪詢切換與把處理下放到專用核。

## 範例

**問題**：一個網路伺服器同時服務千個連線，中斷機制如何讓它不必輪詢？

1. **無中斷的世界**：伺服器要反覆執行「網卡有封包嗎？」——千個連線的輪詢耗掉全部 CPU，實際處理封包的時間反而不足。
2. **中斷登場**：每個封包到達，網卡經 MSI 寫入通知，CPU 暫停用戶程式，跳到驅動程式的中斷處理函式。
3. **現場保存**：硬體保存 PC 與旗標；函式把通用暫存器壓入堆疊，切換到核心態。
4. **上半部與下半部**：處理函式只做最少的事（把封包指標放進佇列），把耗時的解析交給軟中斷（下半部），避免關中斷時間過長。
5. **負載尖峰**：每秒百萬封包時，一次一封包的中斷反而比輪詢慢；Linux NAPI 在高負載時關中斷改用輪詢，直到佇列清空再重開中斷——中斷與輪詢不是敵對而是互補。
6. **計時器中斷**：每 4 毫秒一次的計時器中斷是排程器的節拍器，作業系統借此在行程之間切換，這就是「多工」的物理基礎。

## 前因後果

- **前因**：早期電腦以 I/O 指令反覆測試設備狀態，CPU 大量時間空轉；1950 年代 MIT Whirlwind 與 IBM 系統引入中斷概念，讓 I/O 與計算重疊。
- **後果**：中斷驅動的多工直接催生作業系統的排程器與驅動程式模型；例外機制成為虛擬記憶體（缺頁）、記憶體保護（越權存取）與除錯器的地基。

## 容易混淆之處

- **中斷與例外不同**：前者異步、與當前指令無關；後者同步、由指令本身觸發。
- **關中斷不等於原子操作**：關中斷只防本地核被打擾，多核系統要用原子指令或鎖。
- **軟中斷不是軟體中斷**：Linux 的 softirq 是延後處理的機制；「軟體中斷」則是陷阱指令（如系統呼叫）。
- **中斷頻率高不等於反應快**：過頻的中斷會拖垮系統，合併與節流才是好設計。

## 技術要點

- 中斷處理的黃金律：越短越好，把工作推遲給下半部。
- 優先權架構（如 ARM 的 GIC）決定誰能搶先，巢狀中斷需要正確的優先權堆疊。
- x86 的 APIC 把中斷送到指定核心，支援親和性設定以提升快取命中。
- 時脈中斷頻率從 100 Hz 到 1000 Hz 可調，即時系統要求更細的節拍。
- 缺頁例外是虛擬記憶體的核心機制，屬於「同步例外」。
- 遮罩位元暫存器控制哪些中斷可被忽略，臨界區用它實現輕量互斥。

## 常見的論爭

- **中斷與輪詢的取捨**：高頻小封包場景輪詢更佳（DPDK、NAPI），低負載中斷省電，工程上以動態切換為主流。
- **中斷該不該上核**：把中斷固定在專用核心可減少干擾，但犧牲彈性；「中斷親和性」策略在低延遲系統是熱門話題。
- **即時性的度量**：中斷延遲的最壞情況（不平均）才是即時系統的指標，RTOS 與 Linux 即時補丁的設計哲學因此不同。

## 實務補充：中斷的代價

中斷並非免費。上下文切換要保存所有暫存器狀態、可能要刷新或失效快取管線，這段固定成本讓「一次中斷」在數微秒量級。對即時系統而言，中斷延遲的抖动比平均吞吐量更關鍵，因此常見的設計是把中斷處理程式寫得極短，只做「讀取裝置狀態、把工作丟進佇列」就返回，heavy work 交給延遲處理的執行緒。

可中斷性（interruptibility）與可重入性是可中斷函式的兩個基本要求：函式在被打斷後必須能被安全地再次進入，否則巢狀中斷會破壞全域狀態。硬體提供巢狀中斷計數器與遮罩暫存器，作業系統則把它們封裝成「關中斷區段」或延遲中斷（deferred interrupt）機制。

實務上常見的除錯技巧是：在驅動程式中暫時禁止某個 IRQ，並觀察逾時是否消失。這能把問題二分為「裝置硬體/驅動程式」或「純軟體邏輯」，是排查間歇性當機最有效的手法之一。
