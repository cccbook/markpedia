# 程式語言的演進

> 隸屬：[程式設計]　·　狀態：初稿

> 對應維基百科：[中文維基百科：程式語言歷史](https://zh.wikipedia.org/wiki/%E7%A8%8B%E5%BC%8F%E8%AA%9E%E8%A8%80%E6%AD%B7%E5%8F%B2)　·　[English Wikipedia: History of programming languages](https://en.wikipedia.org/wiki/History_of_programming_languages)

程式語言的演進是**抽象層逐級墊高的歷史**：每一代語言都把上一代需要人工處理的細節交給機器，讓程式師的每小時產出放大一個數量級。機器語言是硬體的直接介面，組合語言為它加上符號，高階語言把演算法直接寫成近人類語言的敘述，腳本語言再把「編譯—連結—執行」的流程壓縮成即寫即跑。理解這條演進線，就理解了今天所有語言的設計折衷從何而來。

## 技術與理論的關聯

- **抽象漏隙（leaky abstraction）**：每一層抽象都會在某些情境「漏出」下層細節——高階語言的程式師仍需理解快取與記憶體模型才能寫出高效程式；演進不是取代，而是疊加。
- **編譯與直譯的取捨**：高階語言多走「先編譯成機器碼」路線，追求執行效率；腳本語言多走直譯或即時編譯（JIT），追求開發速度；現代語言常兩者混合。
- **硬體共演化**：語言能力受限於也塑造硬體——馮·諾伊曼架構催生了命令式語言的變數與賦值模型（見 [馮·諾伊曼] 與 [電腦]）。
- **理論先行**：λ 演算（1930 年代）先於 Lisp，型別理論先於 ML 與 Haskell；語言設計一直是 [數學] 與工程的反覆對話。
- **標準化與可攜性**：C 標準、Java 虛擬機、WebAssembly 都在解決同一個問題——讓同一份程式在不同機器上有一致的行為。
- **生態系是第二生命**：函式庫、套件管理與社群規模決定語言的實際壽命，語言本身的優劣只占一部分。

## 範例：同一行程式在四個抽象層的樣貌

把數值 5 加到暫存器，四個層級的寫法：

```
機器語言（x86-64 片段，十六進位）：  83 C0 05
組合語言：                        add eax, 5
高階語言（C）：                   x = x + 5;
腳本語言（Python）：              x += 5
```

- 機器語言版本是 CPU 真正讀到的位元組，直接由 ISA 手冊定義。
- 組合語言版本經組譯器一一對應成上面的位元組，人類可讀但每步仍繫於特定處理器。
- C 版本由編譯器決定用哪些暫存器與指令，在 x86 與 ARM 上都能編譯；[丹尼斯·里奇] 設計 C 時的目標正是「夠低階以寫作業系統，夠高階以可攜」。
- Python 版本連型別都不必宣告，直譯器在執行期決定一切；寫起來最快，但效能與錯誤發現時機都後移。

從上到下，書寫成本遞減、控制力遞減、錯誤發現時機遞晚——這個三角就是演進史的座標系。

## 前因後果

- **前因**：[電腦] 的硬體只接受二進位指令，而人腦不擅長二進位；缺口催生了符號化與自動翻譯的構想，[葛麗斯·霍普] 的 A-0（1952）是第一個編譯器，[愛達] 則在一個多世紀前就寫下第一份程式。
- **後果**：高階語言使軟體產業成立——沒有可攜的語言，就沒有跨機器的軟體市場；腳本語言進一步讓非專業工程師（科學家、分析師、營運人員）也能自動化工作，間接催生了資料科學與 [人工智慧] 的應用浪潮。

## 與相鄰分類的關聯

- 與 [語言典範] 的關係：演進提供「載體」，典範決定「寫法」；C 之於命令式、Java 之於物件導向、Haskell 之於函式式，都是載體與典範互相成就的例子。
- 與上位概念 [程式設計] 的關係：本條目解釋「為什麼今天的語言長這樣」，是理解其餘子分類的歷史地基。
- 與 [電腦] 的關係：指令集架構是語言演進的硬體邊界。

## 容易混淆之處

- **「代」不是嚴格分期**：第一代到第五代的說法是教學簡化；腳本語言（1960 年代起）與物件導向（1967 年 Simula 起）在時間上高度重疊。
- **組合語言不等於機器語言**：兩者一一對應，但組合語言是給人看的符號形式，機器語言是位元組本身。
- **直譯不等於慢**：現代 JIT（如 JavaScript 引擎）可使腳本語言達到接近編譯語言的效能。
- **新語言不是憑空創造**：Rust 借自 ML 的型別系統與 C++ 的零成本抽象；Go 借自 Oberon 與 CSP；語言演進是重組而非重來。

## 技術要點

- 抽象層級：機器語言 → 組合語言 → 高階語言 → 腳本語言，控制力遞減、生產力遞增。
- 翻譯時機：組譯（一一對應）、編譯（整體翻譯）、直譯（逐句執行）、JIT（執行中編譯熱點）。
- 可攜性的三個層次：原始碼可攜（C 標準）、位元組碼可攜（JVM）、二進位可攜（WebAssembly）。
- 語言與硬體共演化：RISC 指令集簡化了編譯器，向量指令催生了自動向量化。
- 生態因素：標準函式庫、套件管理器（npm、PyPI、Cargo）與 ABI 穩定性，決定語言的實務可用性。
- 演進的檢驗標準：同一問題在新語言下的程式碼行數、錯誤率與執行效能，三者難以同時最優。

## 常見的論爭

- **編譯 vs 直譯孰優**：效率陣營強調預先編譯的可預測性，開發速度陣營強調即寫即跑的迭代優勢；JIT 技術使界線模糊但未終結爭論。
- **新語言是否值得學**：一派認為語言塑造思考（維根斯坦式論證），一派認為底層概念不變、語言只是語法糖；實務上兩者皆對。
- **向後相容的代價**：C++ 為相容性背負數十年歷史包袱，Python 3 為清理設計而犧牲相容性；沒有免費的選擇。
