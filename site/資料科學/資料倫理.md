# 資料倫理

> 隸屬：[資料科學]　·　狀態：初稿

> 對應維基百科：中文維基百科無對應條目　·　[English Wikipedia: Big data ethics](https://en.wikipedia.org/wiki/Big_data_ethics)

資料倫理研究**資料的蒐集、使用與推論應該遵循什麼道德界線，以及違反界線時誰該負責**。它處在技術與法律之間，處理的是那些法律尚未明文規定、卻在實務中必須立即決定的問題。

這門領域的出現直接來自資料規模的膨脹。過去收集一份問卷需要紙本與人力，因此研究者在設計上會謹慎篩選題目；當行為日誌可以在使用者不知情下完整記錄每一次點擊與停留時間時，**「可取得」與「可使用」之間的落差**就浮現出來。歐洲在 2018 年生效的《一般資料保護規則》（GDPR）把這類道德要求部分轉為法律條文，使資料倫理從學界討論進入企業法務與工程團隊的日常。

另一方面，機器學習模型的應用也帶來新的倫理面向：[人工智慧] 模型在招聘、貸款或醫療診斷上的應用，可能重現甚至放大資料中既有的社會偏見。這使得「資料倫理」不再只是隱私問題，而是**公平性、透明性與可問責性**的整體問題。

因此資料倫理的實質內容可以分為三塊：對個人的尊重（[隱私]）、對群體的公平（[偏差]），以及對整體制度的 accountability（[可解釋性] 與 [資料治理]）。

## 技術與理論的關聯

- **知情同意是資料使用的授權前提**：沒有同意的資料蒐集在多數法域皆屬侵權，即使資料本身已公開。
- **目的限制原則**：資料蒐集須為特定目的，使用時不得超出該目的；「先蒐集再想用途」在倫理上不可接受。
- **最小必要原則**：只蒐集達成目的所必需的欄位，可降低洩漏面與法律責任。
- **匿名化與假名化的差別**：假名化資料仍可透過其他欄位重新識別個人，因此與匿名化資料適用不同的法規要求。
- **偏差不是資料的必然，而是流程的產物**：若樣本取得方式本身不具代表性，模型必然學到偏見，這是 [樣本偏差] 的倫理面。
- **可解釋性支撐問責**：當決策者無法說明「為何拒絕這位申請者」，受影響者便無從申訴，問責因此不可能。

## 範例：一個特徵應該被允許使用嗎

**情境**：某保險公司要建立車險理賠金額的預測模型，候選特徵包含：駕駛年齡、駕駛人數、車種與等級、上次出險距今月數、駕駛員的信箱地址 zip code。

1. **隱私檢查**：駕駛年齡與車型屬契約必要資訊；zip code 雖為公開資料，但結合車型與出險紀錄後可重新識別到個人，屬於需要額外保護的欄位。
2. **偏差檢查**：以過往理賠資料檢視平均索賠金額，若某年齡層的模型殘差顯著偏離，須檢查該群體是否因歷史保費設定而較少申報——這是資料中的社會結構被模型吸收的典型情形。
3. **可解釋性檢查**：模型若只輸出預測金額而無法說明主要因子，客服在面對客戶質疑時無法給出合理理由；因此要求模型提供因子貢獻與可讀的規則摘要。
4. **資料治理檢查**：定稿後，這個模型的特徵清單、訓練資料期間、評估結果與核准人必須被記錄，並設定定期重審（模型漂移與法規變更皆可能使當初的授權失效）。
5. **結論**：保留年齡、車型與出險間隔；zip code 改用粗化的區級地理特徵並去除可識別的罕見組合；模型需附帶說明；整體在治理登錄表中定期複審。

這個例子顯示：資料倫理不是「要不要做」的開關，而是**把每一個欄位與每一個用途逐一檢查**的工作流程。

## 前因後果

- **因為**：資料蒐集能力遠超社會規範調整的速度，技術便利性壓倒了同意與目的限制的傳統原則。
- **所以**：學界提出最小必要、目的限制與知情同意等規範，並逐步被立法吸收。
- **因而推動**：資料保護官、去識別化技術、隱私增強的資料分析成為專門職位與研究領域。
- **反過來**：法規要求把「隱私」從附加考量變成資料管線的必要步驟，例如保留期限與刪除流程。
- **再推動**：可解釋性與模型稽核要求，進一步改變了 [人工智慧] 模型的開發方式。

## 與相鄰分類的關聯

- 與 [資料流程] 的關係：管線中的每個欄位都是潛在的倫理決策點，保留期限與刪除都必須在管線中實作。
- 與 [實驗設計] 的關係：實驗以人為對象，知情同意與風險告知是實驗合法性的前提。
- 與 [探索性分析] 的關聯：探索會暴露群體差異，這常是偏見最初被看見的地方，也可能是最容易被選擇性呈現的地方。
- 在上位概念 [資料科學] 中，本概念扮演什麼角色：它是資料科學的邊界層，為其他四層設定不可跨越的紅線，並在紅線與商業目標衝突時提供判斷依據。

## 容易混淆之處

- **隱私與保密不同**：隱私關乎個人對自身資訊的控制權，保密關乎他人不得得知；公開但難以被重新識別的資料仍涉及隱私。
- **匿名化與去識別不同**：可重新識別的假名化資料在多數法域仍受個資法規範。
- **偏差與不公平不等於單一模型問題**：偏差常來自制度與歷史，模型只是放大器。
- **透明不等於公開所有細節**：透明是「足以問責」的程度，過度公開反而製造新的隱私風險。
- **合規不等於合乎倫理**：法規是最低線，許多倫理問題在法律尚未定案時就已存在。

## 技術要點

- 建立欄位等級分類（公開／內部／機密／受限），並讓管線依此自動套用遮蔽與加密。
- 為每個資料集記錄蒐集目的、同意狀態、保留期限與到期處理方式。
- 在模型開發前進行偏差評估，分群檢視各類別的誤差率與拒絕率。
- 為自動決策保留人工覆核與申訴管道，並記錄覆核結果。
- 對外發布模型卡或資料說明，記載用途、限制、已知弱群體與評估方式。
- 將倫理檢查嵌入流程節點（發布前關卡），而非只在專案末端補文件。

## 常見的論爭

- **隱私與效用的取捨**：匿名化與差分隱私等技術能保留部分效用，但實務證明資料分群再識別風險仍高。
- **公平性指標彼此衝突**：不同公平定義（機會均等 vs 預測值均等）在基準率不同時無法同時滿足。
- **監管的力度與創新的節奏**：過度嚴格可能阻礙資料研究，過度寬鬆則把風險轉嫁給無知情能力的個人。
