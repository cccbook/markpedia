# TCP/IP

> 隸屬：[計算機網路] › [網路架構]　·　狀態：初稿

> 對應維基百科：[中文維基百科：網際網路協議套組](https://zh.wikipedia.org/wiki/%E7%B6%B2%E9%9A%9B%E7%B6%B2%E8%B7%AF%E5%8D%94%E8%AD%B0%E5%A5%97%E7%B5%84)　·　[English Wikipedia: Internet protocol suite](https://en.wikipedia.org/wiki/Internet_protocol_suite)

TCP/IP 是網際網路所使用的**協定套組**，由一組規定不同功能層通訊方式的協定組成。它的核心成員是 IP（網際網路協定）、TCP（傳輸控制協定）、UDP 與 ICMP。

它的歷史意義在於解決了一個極難的問題：**如何讓使用完全不同硬體與作業系統的電腦彼此通訊**。[倫納德] 與 [克恩] 在 1970 年代中期提出的設計放棄了「網路核心必須可靠」的傳統想法，改採端對端原則：核心只做盡力交付的轉送，可靠性由端點的 [TCP] 負責。這個選擇換來了巨大的可擴充性，也留下了直到今日仍在處理的安全與可觀測性問題。

## 技術與理論的關聯

- **盡力交付的哲學**：核心不保證交付、不保證順序、不保證不重複；這三項保證全部推給端點，是端對端原則的直接推論。
- **分組與路由**：IP 把資料切成固定長度的分組並加上標頭，逐跳由 [路由] 轉送；分組的獨立性使網路核心保持簡單且可擴充。
- **位址與路由的雙重性**：IP 位址同時是主機的識別與路由的依據，其階層結構讓路由表可以聚合，這是網際網路能容納數十億位址的技術前提。
- **連線語意在端點**：TCP 在端點維護連線狀態（序號、視窗、重傳計時器），核心只轉送，這使得核心可以用簡單的硬體實作並以線速轉發。
- **與 [演算法] 的關聯**：路由的最低成本路徑選擇、位址聚合的位元運算、重傳的逾時推估，都是演算法問題；IP 的設計把這些問題分布到網路各處求解。
- **與 [離散數學] 的關聯**：分組排序、重複消除與序號空間的回繞處理，構成組合與狀態機的理論骨架。

## 範例

**範例：一次封包從寄件端到收件端的旅程。**

1. **應用交給傳輸層**：應用程式呼叫 socket 送出資料，TCP 為其加上控制資訊（來源與目的埠、序號、確認號、視窗大小與旗標），形成 TCP 區段。
2. **交給網路層**：TCP 將區段交給 IP，IP 加上 IP 標頭（含來源與目的 IP 位址、存活時間、協議識別與分割欄位），形成 IP 封包。
3. **路由決定**：本機的 IP 層查路由表，決定下一跳；若是本機位址則直接交給上層（此處即目的端），否則交給鏈路層。
4. **鏈路層封裝**：資料被封裝成 [乙太網] 幀，加上本機的實體位址與目的實體位址（或以位址解析協定查出），並附上檢查碼。
5. **實體層送出**：驅動程式將幀轉為線上訊號；若是無線鏈路則交給無線網卡的媒介存取控制排程。
6. **逐跳轉送**：每一台轉送器收到幀後，檢查目的實體位址是否為自己——是則剝除鏈路層標頭、把 IP 封包往上送；否則依 [路由] 表決定下一跳並重新封裝新的鏈路層標頭。
6. **IP 處理**：若目的 IP 位址是自己，剝除 IP 標頭並依協定識別欄位把 TCP 區段交給 TCP；否則依存活時間遞減並轉送。
7. **TCP 處理**：目的端的 TCP 依序號重組位元組流，送出確認，並依視窗大小進行流量控制；遺失的分組由重傳計時器觸發補送。
8. **交付應用**：資料經完整性檢查後交給應用程式，整個過程對應用程式而言是「一條可靠的位元組流」。

## 設計原則的實踐

TCP/IP 套組最值得學習的一點，是它的每一項設計都服從同一個判準：把複雜性放在可以受益於複雜性的地方。位址的階層性讓路由表得以聚合；分組的獨立性讓核心得以簡化；序號與確認號讓端點得以自行處理可靠性。這些機制並非為了理論上的純潔，而是針對具體的規模問題。

反過來說，這個判準也解釋了它的侷限。當加密普及，核心無法觀察內容，某些在核心執行的功能（過濾、計費、異常偵測）便失去了作用對象；當多路徑與策略路由普及，路徑的可預測性下降，故障排除變得更難。理解這些侷限的來源，比記住協定的欄位更能讓人預判下一輪演進的方向。

## 實務觀察

從維運者的角度來看 TCP/IP 套組最常見的困擾，是「問題出在哪一層」的判定。以症狀分類：名稱解析緩慢屬於名稱解析與應用層；連線建立緩慢屬於傳輸層交握與路由路徑；單一連線吞吐低屬於鏈路層容量或壅塞；所有連線同時變慢則通常是實體層或核心設備。

另一個常見困擾是**重複的逾時層級**。應用層逾時、傳輸層重傳計時器與路由收斂時間若未協調，會出現重試放大：一次慢反應觸發多次重試，進一步加重系統負擔，使復原時間反而延長。合理的做法是讓上層的總逾時涵蓋下層可能的多次重傳，並在重試時加入退避與隨機抖動。

## 前因後果

- **前因**：1969 年 ARPANET 的成功顯示分組交換可行，但不同網路之間無法互通；DARPA 與國際合作者需要一套共通的互連協定。
- **後果**：TCP/IP 於 1983 年成為 ARPANET 的正式協定，其後隨網際網路的擴張成為全球事實標準；同時促成路由資訊交換、網域名稱系統與全球路由表等配套體系的成形。
- **互相驅動**：[傳輸協定] 中的 TCP 成為多數應用的基礎；[應用層協定] 中的 HTTP、DNS 等則使 TCP/IP 從「研究社群網路」變成「公共基礎設施」；[無線網路] 的普及也把 TCP/IP 帶入行動環境並催生了對其侷限的改造需求。

## 容易混淆之處

- **TCP/IP 不只是 TCP 與 IP**：它是整個協定家族，包含 ARP、ICMP、DHCP 等數十項。
- **TCP/IP 與 OSI 模型不是對應關係**：實務上是五層對七層的粗略對應，且界線並不嚴格。
- **IP 不保證可靠性**：把「IP 會把資料送到」當成前提是常見誤解，遺失與重排是常態。
- **TCP/IP 版本與「IP 版本 4、6」不同**：套組版本與 IP 封包版本是兩件事。
- **位址不等於身分**：IP 位址可被偽造，也可透過位址轉換共享，因此不能作為身分憑證。
- **端對端原則不是「核心無用」**：它主張核心只做必要工作，而非否定核心的價值。

## 技術要點

- 核心轉送只依目的位址與路由表，不記錄連線狀態，以保持可擴充性。
- IP 存活時間防止分組在路由環路中無限迴圈。
- 介面的最大傳輸單位決定分片行為，分片會增加開銷並影響中間設備的處理。
- 標頭的校驗和讓節點能丟棄損壞封包，避免錯誤資料被往上送。
- 協定識別欄位讓接收端能把封包分派給正確的傳輸層協定。
- 設計新功能時優先考慮在端點實作，以維持核心的簡單與可擴充。

## 常見的論爭

- **端對端原則的侷限**：加密普及使核心無法觀測內容，防火牆與中間盒難以發揮作用，引發「核心應更了解內容」的討論。
- **位址過載與過渡機制**：位址轉換延長了舊位址空間的壽命，卻也讓端到端連線與安全追溯變複雜。
- **多路徑與策略路由的取捨**：更靈活的路由可改善韌性，卻增加路徑預測的難度，讓故障排除更困難。
