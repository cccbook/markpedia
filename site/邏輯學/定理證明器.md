# 定理證明器

> 隸屬：[邏輯學] › [邏輯與電腦]　·　狀態：初稿

> 對應維基百科：[English Wikipedia: Theorem prover](https://en.wikipedia.org/wiki/Theorem_prover)

定理證明器（theorem prover）是讓機器檢查形式化數學證明的軟體系統。它的核心是一個**極小的可信核心**：核心只包含最簡單的推導規則與型別檢查，所有複雜功能都由外部工具產生、並交由核心覆核。

今日的系統（Coq、Lean、Isabelle、Agda）把 Curry-Howard 對應貫徹到底：證明就是程式，檢查證明就是型別檢查。

## 一、可信核心的設計

| 原則 | 理由 | 做法 |
| --- | --- | --- |
| 越小越好 | 審查成本與錯誤機率 | 核心僅數百行 |
| 只含最基本規則 | 避免隱藏假設 | 不含未經證明的最佳化 |
| 獨立重現 | 避免隱藏通道 | 小核心可用另一語言重寫 |
| 明確假設 | 避免隱性前提 | 所有前提必須顯式聲明 |

**範例**：Lean 的核心以一個小型類型檢查器構成，負責驗證所有 tactic 產生的證明項；大型的搜尋與重寫都在核心之外完成，若結果錯誤只需放棄該分支，不會污染可信性。

## 二、互動式工作流程

1. **宣告**：把命題寫成形式語句。
2. **分解**：以 tactic 拆解目標，例如 `intro`、`apply`、`simp`。
3. **求證**：機器搜尋具體證明項。
4. **覆核**：核心檢查證明項是否合法。

**範例（Lean）**：要證明 $\sin^2 x + \cos^2 x = 1$ ，只需一行

```text
nlinarith [Real.sin_sq_add_cos_sq]
```

機器做的是「把已知引理餵給非線性算術 tactic」，核心只確認最終產生的證明項合法。

## 三、數學形式化的現況

| 系統 | 語言 | 特色 |
| --- | --- | --- |
| Coq | Gallina | 最早廣泛使用的形式化平台 |
| Lean | Lean | mathlib 社群規模大、文件完善 |
| Isabelle | Isar | 以結構化證明腳本為特色 |
| Agda | Agda | 依賴型別與終止性檢查整合 |

**範例**：Lean 的 mathlib 已形式化數千則定理，包含一些此前只以計算機輔助證明或長期未解的結果；每則定理都附有可讀的自然語言說明，說明「可讀性」是形式化能否規模化的關鍵。

## 四、瓶頸與對策

| 瓶頸 | 對策 |
| --- | --- |
| 形式化成本高 | 先寫自然語言版本再逐段形式化 |
| 找不到引理 | 建立引理庫、輔助搜尋 |
| 終止性與自動化 | 限制 tactic 組合、使用 timeout |
| 知識門檻 | 提供互動式介面與教學文件 |

**範例（成本）**：把某個中等難度的定理形式化，所需時間往往超過原定理的初次證明數倍。這是形式化推廣的最大障礙，也是「數學家 + 機器」協作模式的原因。

## 六、容易混淆之處

- 定理證明器**只檢查證明**，不保證命題為真——前提可能為假。
- 「已形式化」通常指特定命題版本，而非文獻中的原始表述。
