# SoC

> 隸屬：[積體電路]　·　上層：[製程與架構]　·　狀態：初稿

> 對應維基百科：[中文維基百科：系统单芯片](https://zh.wikipedia.org/wiki/%E7%B3%BB%E7%BB%9F%E5%8D%95%E8%8A%AF%E7%89%87)　·　[English Wikipedia: System on a chip](https://en.wikipedia.org/wiki/System%20on%20a%20chip)

SoC（System on a Chip，系統單晶片）是把整個電腦系統——處理器、記憶體、周邊控制器與介面——整合在單一晶片上的設計架構。手機的主晶片是最典型的例子：中央處理器、圖形處理器、數據機、影像訊號處理器、人工智慧加速器與安全模組全部同住一顆矽片。SoC 的核心動機不是「整合很酷」，而是**把系統間的通訊從電路板縮到晶片內部**：板級訊號延遲以奈秒計，晶片內以皮秒計，且互連密度高幾個數量級；整合同時省下空間與功耗，這是行動裝置能存在的前提。

SoC 設計的本質是「系統工程壓縮到晶片裡」：工程師面對的不只是邏輯設計，還有軟硬體介面（暫存器圖、中斷、啟動流程）、IP（預先設計好的可重用電路區塊）的採購與整合、以及各子系統之間的功耗與時脈協調。因此 SoC 專案的 [規格] 必須涵蓋軟體可見介面，[驗證] 必須包含整機層級的軟體開機測試，這些都是單一功能晶片專案所沒有的面向。

## 技術與理論的關聯

- **匯流排與網狀互連**：子系統之間靠晶片內匯流排（如 AMBA 系列的 AXI/AHB）或網狀互連（NoC，把資料像網路封包一樣路由）溝通；互連的頻寬與延遲往往才是 SoC 的真正瓶頸，而非個別核心。
- **IP 重用**：處理器、介面控制器、實體層電路多以 IP 形式授權或內部重用；SoC 的工程難點從「設計」轉向「整合與驗證」。
- **與 [同步設計] 的關係**：SoC 天生多時脈域（CPU 高頻、周邊低頻、即時時鐘 32 kHz），跨域同步與時脈管理單元是必備基礎建設。
- **與 [低功耗設計] 的關係**：SoC 的功耗管理是分層的——核心級 DVFS、模組級時脈閘控、電源域級電源閘控，再由軟體的電源管理策略統一調度。
- **與 [類比混合訊號] 的關係**：SoC 幾乎必然含 ADC、PLL 與電源管理等混合訊號區塊，介面雜訊隔離是佈局的關鍵議題。
- **與 [製程節點] 的關係**：SoC 是先進節點的主要客戶（密度紅利對整合型產品最有利），但類比與高壓區塊常需混合節點或封裝整合。

## 範例

**範例一：一顆典型手機 SoC 的組成與規模。** 以 5 nm 節點的旗艦手機晶片為例，常見配置約為：

- 8 核心 CPU（4 大核 2.8 GHz + 4 小核 1.8 GHz），多時脈域設計。
- 10 核圖形處理器與神經網路加速器（算力約 30 TOPS）。
- 5G 數據機、影像訊號處理器、音訊編解碼器與安全島。
- 晶片內 L3 快取約 8 MB，經 LPDDR 介面連外接記憶體。
- 總電晶體數約 150 億，功耗牆約 8 W（散熱限制而非電源限制）。

這顆晶片的設計挑戰很少在單一區塊，而在「八個時脈域、六個電源域、數十個 IP 之間的介面與驗證」。

**範例二：記憶體頻寬的帳目。** 假設 CPU 與圖形處理器同時取用 LPDDR5 記憶體（頻寬 51.2 GB/s）：CPU 需 20 GB/s、圖形需 40 GB/s，合計 60 GB/s 超過了頻寬——瓶頸迫使系統設計者做取捨：擴大晶片內快取（面積成本）、壓縮圖形資料（演算法成本）或降頻（性能成本）。SoC 性能調校的大量工作就是這類「頻寬算術」，與單核性能指標關係不大。

**範例三：啟動流程。** SoC 通電後依序執行：晶片內 ROM 的開機碼 → 讀取快閃記憶體的次級載入器 → 載入電源管理與時脈初始化 → 驗證並跳轉作業系統核心。這條鏈上任何一環的介面（時脈未穩就取樣、電源域未上電就存取）都會造成「有時開得了機、有時不行」的隨機錯誤，是 SoC 驗證中最難纏的整機層級問題。

## 前因後果

1990 年代的「系統級整合」概念先以多晶片模組（把多顆晶片封在一起）出現；隨著製程允許，真正的單晶片系統在 1990 年代末進入嵌入式市場（微控制器整合快閃記憶體與周邊是最早形態）。智慧型手機把 SoC 推到工程極限：單一晶片整合超過十個子系統，並且每年迭代。整合壓力持續推進之後，單片整合開始撞上 [製程節點] 的成本牆，產業於是分化出 Chiplet 路線——把系統拆成多顆晶粒，用先進封裝互連，兼取整合與成本之利。SoC 的上游是 [規格] 的系統定義與 IP 選型，下游是 [驗證與量產] 的整機測試；它是 [積體電路] 世界中離「產品」最近的層次。

## 與相鄰分類的關聯

- 與 [規格] 的關係：SoC 規格必須涵蓋軟體可見介面（暫存器圖、中斷表、啟動流程），這是它與功能晶片最大的差異。
- 與 [同步設計] 的關係：多時脈域管理與跨域同步是 SoC 的日常，而非例外。
- 與 [低功耗設計] 的關係：分層功耗管理（核心、模組、電源域）是 SoC 續航力的來源。
- 與 [驗證] 的關係：SoC 層級驗證需要軟體開機與子系統互動場景，覆蓋率方法學比單區塊複雜一個層級。
- 與 [特殊應用] 的關係：ASIC 與 SoC 的界線在於系統完整度——SoC 是「幾乎整台機器」，ASIC 通常只承擔單一功能。
- 在上位概念 [積體電路] 中，本分類屬於製程與架構，代表整合度的最高形態之一。

## 容易混淆之處

- **SoC 不等於「很多 IP 放在一起」**：沒有軟硬體介面定義、電源時脈策略與整機驗證，只是 IP 拼盤；系統完整性才是 SoC 的定義。
- **SoC 不等於單一製程**：先進 SoC 常以多種節點或封裝整合實現，晶片「單一」指的是功能系統，不是一張光罩。
- **整合度高不等於性能高**：互連與記憶體頻寬往往才是瓶頸；核心數量堆疊掩蓋不了互連擁塞。
- **系統單晶片不等於系統級封裝**：前者是單一晶片承載系統，後者是多顆晶片封裝在一起；兩者解決相似的問題，成本與彈性各有得失。

## 技術要點

- 位址圖與中斷配置應在專案一開始凍結，軟體團隊才能同步開發。
- 時脈與電源域的矩陣應在架構階段定案，並由工具自動檢查跨域介面的同步器完備性。
- 互連頻寬要按「最壞同時取用」場景規劃，並保留 20–30% 餘裕。
- 開機流程的每一步都要有可觀測的狀態訊號，否則整機問題無法定位。
- 安全設計（安全啟動、金鑰隔離、偵錯埠鎖定）應納入架構，不可事後附加，參見 [資訊安全]。

## 常見的論爭

- **自研 IP 與外購 IP 的界線**：處理器與關鍵加速器自研可控但昂貴，外購省時但差異化有限；各公司在不同世代的選擇反覆擺盪。
- **Chiplet 會否取代傳統單片 SoC**：拆解帶來成本彈性，但互連延遲與軟體透明度付出代價；界線如何移動仍無定論。
- **整合的極限**：射頻、電源管理與高壓區塊是否永遠該留在晶片外，混合訊號整合的工程成本與產品彈性之間長期拉鋸。
