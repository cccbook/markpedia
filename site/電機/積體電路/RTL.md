# RTL

> 隸屬：[積體電路]　·　上層：[設計流程]　·　狀態：初稿

> 對應維基百科：[中文維基百科：寄存器传输级](https://zh.wikipedia.org/wiki/%E5%AF%84%E5%AD%98%E5%99%A8%E4%BC%A0%E8%BE%93%E7%BA%A7)　·　[English Wikipedia: Register-transfer level](https://en.wikipedia.org/wiki/Register-transfer%20level)

RTL（Register-Transfer Level，暫存器傳輸層）是一種描述數位電路的抽象層次：把晶片看成一群**暫存器**（在時脈邊緣存值的記憶單元）與其間的**組合邏輯**（純粹由輸入算出輸出的電路），並以硬體描述語言寫下「每個時脈週期，資料如何從暫存器流過邏輯、再到下一個暫存器」。工程師最常使用 Verilog 或 VHDL 撰寫 RTL，它是今日絕大多數數位晶片設計的起點，也是 [合成] 的直接輸入。

RTL 的核心思想是**以文字描述代替畫電路圖**。一行 `assign sum = a + b;` 就代表一個加法器，至於它會被合成成波動進位加法器還是前導進位加法器，交給合成工具依面積與延遲決定。這種「行為與實作分離」的特性，讓設計的生產力提升了幾個數量級，也讓晶片設計在某種程度上變得像寫程式。

## 技術與理論的關聯

- **可綜合子集**：並非所有 Verilog 都能變成電路；合成工具只接受「可綜合風格」，例如 `always @(posedge clk)` 的暫存器寫法，而測試用的延遲控制語法會被忽略。
- **阻塞與非阻塞賦值**：`=` 與 `<=` 的區別是 RTL 最容易出錯的地方；描述時序邏輯一律用非阻塞賦值 `<=`，才能正確表達「同一時脈邊緣同時更新」的語意。
- **與 [同步設計] 的關係**：RTL 幾乎總是以同步電路的型態書寫——所有暫存器共享一個或多個時脈，這讓靜態時序分析（用數學方法檢查所有路徑延遲的工具）得以自動化。
- **與 [驗證] 的關係**：RTL 是功能模擬的主要對象；驗證環境以同樣的語言撰寫測試平台，在 RTL 尚未合成前就能發現功能錯誤。
- **與 [低功耗設計] 的關係**：RTL 階段就能插入手脈衝閘控與運算元隔離等功耗技術，此時省電的成本最低、效益最大。
- **高階合成**：以 C/C++/SystemC 描述演算法再自動生成 RTL 的技術正在成熟，但關鍵路徑與面積品質仍比不上手工調校的 RTL，兩者並存互補。

## 範例

**範例一：四位元累加器的 RTL。** 下列 Verilog 描述一個每個時脈把 `d` 累加進去的計數器：

```verilog
module acc4 (
    input  wire       clk,
    input  wire       rst_n,
    input  wire [3:0] d,
    output reg  [3:0] q
);
    always @(posedge clk or negedge rst_n) begin
        if (!rst_n)
            q <= 4'b0000;
        else
            q <= q + d;
    end
endmodule
```

這十幾行經過 [合成] 後，會展開為四個正反器加一個四位元加法器，在 28 nm 製程上約占 60 平方微米，臨界路徑延遲約 0.2 ns，意味著理論最高時脈可達 5 GHz。

**範例二：阻塞與非阻塞的差別。** 若在同一個 `always` 區塊中寫 `b <= a; a <= b;`，兩個暫存器會在每個時脈交換內容（像兩條平行導線）；若誤寫成 `b = a; a = b;`，則 `a` 永遠等於舊的 `b`，交換行為消失。這類錯誤在模擬與實際電路上表現不同，是最經典的 RTL 陷阱。

**範例三：有限狀態機。** 一個簡單的三態狀態機（IDLE、RUN、DONE）在 RTL 中用一個狀態暫存器與兩段 always 區塊描述：一段依輸入算出下一狀態，一段在時脈邊緣更新狀態。這種兩段式寫法是業界標準，因為它讓組合邏輯與時序邏輯的邊界一目了然，方便 [合成] 與 [時序收斂] 分析。

## 前因後果

在 RTL 普及之前，晶片以閘級電路圖描述，數千個閘已是手工能管理極限。[1958年] 積體電路出現後閘數持續攀升，1980 年代開始出現硬體描述語言，讓設計抽象層次上移到暫存器傳輸層；隨後邏輯合成工具商業化，RTL 才真正成為設計的「源代碼」。今日 RTL 的下游是 [合成]（變成閘級網表）與 [驗證]（變成模擬對象），上游是規格；RTL 寫完並通過驗證的那一刻，晶片的行為就已經確定，剩下的是把性能與功耗做進去的物理工程。

## 與相鄰分類的關聯

- 與 [規格] 的關係：規格定義功能與效能目標，RTL 是功能的第一份可執行實作。
- 與 [合成] 的關係：合成把 RTL 映射為閘門網表，RTL 的寫法直接決定合成的品質上限。
- 與 [驗證] 的關係：RTL 是功能驗證的主要戰場，多數功能錯誤必須在此階段攔下。
- 與 [同步設計] 的關係：RTL 的書寫慣例建立在同步設計假設之上，兩者互為表裡。
- 在上位概念 [積體電路] 中，本分類是把「想法」變成「可模擬機器」的關鍵一步。

## 容易混淆之處

- **RTL 不等於軟體程式**：RTL 中的所有語句「同時存在、同時作用」，描述的是並行的硬體結構，與軟體的循序執行語意根本不同。
- **RTL 不等於 Verilog**：RTL 是抽象層次，Verilog 只是承載它的語言之一；VHDL、SystemVerilog 都可以寫 RTL。
- **可模擬不等於可合成**：`#10` 這種延遲語法在模擬器中有意義，但合成器無法把它變成任何實體延遲。
- **模擬通過不等於時脈能跑快**：RTL 模擬不含實際延遲，時序是否達標要等 [佈局] 與 [時序收斂] 之後才見分曉。

## 技術要點

- 時序邏輯一律使用非阻塞賦值 `<=`，組合邏輯一律使用阻塞賦值 `=`。
- 所有暫存器都應有明確的復位策略，並在 RTL 中統一書寫。
- 位元寬度要顯式標明，避免隱式截位造成難以察覺的功能錯誤。
- 組合邏輯必須覆蓋所有分支，避免產生意外鎖存器（latch）。
- 模組介面與命名應遵循團隊編碼規範，因為 RTL 會被合成、驗證、後端三方反覆閱讀。
- 跨時脈域的資料傳遞必須在 RTL 中顯式安排同步器，不可依賴事後修補。

## 常見的論爭

- **Verilog 與 VHDL 之爭**：美系與通訊業偏愛 Verilog 及其後繼 SystemVerilog，歐洲與航太偏愛 VHDL；兩者表達能力接近，選擇多半取決於團隊傳承。
- **手寫 RTL 與高階合成的比重**：高階合成在資料流密集的應用（影像、訊號處理）已實用化，但控制邏輯密集的設計仍以手寫為主。
- **RTL 的可讀性與效能取捨**：為了合成品質，工程師有時必須寫出不直覺的程式碼；編碼規範該向可讀性還是向工具友善傾斜，各團隊各有堅持。
