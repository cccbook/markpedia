# 時序收斂

> 隸屬：[積體電路]　·　上層：[設計方法]　·　狀態：初稿

> 對應維基百科：[中文維基百科：时序收敛](https://zh.wikipedia.org/wiki/%E6%97%B6%E5%BA%8F%E6%94%B6%E6%95%9B)　·　[English Wikipedia: Timing convergence](https://en.wikipedia.org/wiki/Timing%20convergence)

時序收斂是指讓晶片設計中**所有時序路徑都滿足時脈週期要求**的過程：每一條從正反器到正反器的路徑，其延遲加上建立時間必須小於一個週期（建立時間檢查），且資料不得在下一級取樣窗口附近快速變動（保持時間檢查）。這項工作貫穿 [合成] 到 [佈局] 繞線的整個後段流程，因為延遲的真相——特別是繞線造成的寄生電容——要到實體設計後期才完全揭曉。工程師說「晶片時序收斂了」，意思就是最壞製程角下所有路徑的 slack（餘裕，實際延遲與預算的差）都非負。

收斂之所以困難，在於三個效應互相拉扯：收緊時序要加緩衝與加大閘，這增加功耗與繞線擁塞；擁塞迫使線繞更長，延遲又變差；換更快的元件庫（低閾值電壓）能提速，但漏電功耗隨之上升。時序收斂因此是在性能、功耗與面積之間的多維最佳化，而非單純的「把慢路徑修快」。

## 技術與理論的關聯

- **靜態時序分析（STA）**：收斂的主要量測工具。它不跑任何測試向量，而是對圖中每一條路徑計算最壞延遲，因此覆蓋完整、速度快，是簽核的正式依據。
- **製程角**：同一晶片在快、典型、慢三種製程與不同電壓溫度下延遲不同；收斂必須在最壞角驗建立時間、在最快角驗保持時間，兩端都要過。
- **與 [同步設計] 的關係**：STA 的數學基礎是同步設計的週期化不等式；沒有同步紀律就沒有可自動化的時序驗證。
- **與 [低功耗設計] 的關係**：多閾值電壓元件庫是兩者的交會點——臨界路徑用低閾值換速度、非臨界路徑用高閾值省漏電。
- **與 [佈局] 的關係**：收斂的主要手段（緩衝插入、閘尺寸調整、重繞線）全部發生在實體設計階段，兩者實際上是同一個迭代迴圈。
- **OPC 與籤核裕量**：先進製程的光學鄰近效應修正會微調圖形，時序簽核必須預留模型誤差的餘裕。

## 範例

**範例一：一份時序預算表。** 目標 2 GHz（週期 $0.5$ ns）的設計，某臨界路徑的預算拆解如下：

| 項目 | 預算 |
| --- | --- |
| 時脈週期 | 0.500 ns |
| 來源正反器 clk→Q 延遲 | −0.100 ns |
| 組合邏輯（8 層閘） | −0.240 ns |
| 繞線延遲（2.1 mm） | −0.090 ns |
| 時脈歪斜 | −0.020 ns |
| 建立時間 | −0.030 ns |
| slack | $+0.020$ ns |

slack 只有 $+0.020$ ns，代表任何模型誤差都可能翻負；實務上簽核前會把這種「壓線」路徑再修一輪，目標至少 $+0.05$ ns 的餘裕。

**範例二：修路徑的手段清單。** 對一條 slack 為 $-0.08$ ns 的路徑，工程師按代價由低到高依序嘗試：

1. 把路徑上的中驅動閘升級為高驅動閘（省 $0.03$ ns，面積微增）。
2. 在 2 mm 長線中點插一顆緩衝器，把 RC 延遲對切（再省 $0.04$ ns）。
3. 若仍不足，把邏輯重組：將 8 層串聯比較改為 3 層並行選擇（結構修改，需回到 [RTL] 重寫並重新驗證）。

這個「由便宜到昂貴」的順序是收斂工作的紀律：動結構之前先用盡物理手段。

**範例三：多角的收斂矩陣。** 某晶片需要同時通過 6 個時序角（快角／典型角／慢角 × 兩個電壓）。實務報告常見的現象是慢角餘裕 $+0.05$ ns 而快角保持時間餘裕 $-0.02$ ns——兩個角的修復手段互相衝突（修快角要加延遲單元，會讓慢角更差），工程師必須在同一路徑上同時滿足兩個方向的不等式。

## 前因後果

在閘延遲主導的年代，時序可以在合成階段用簡單線負載模型估算就大致正確，收斂工作相對單純。製程進入 0.25 µm 以下後，互連延遲開始超越閘延遲，合成時的估計與佈局後的真相差距擴大，「合成—佈局—再合成」的反覆迭代成為標準做法；工具業界也因此發展出物理合成（合成時就考慮擺位）與整合式 STA 引擎。今日時序收斂的上游是 [規格] 的時脈目標、[RTL] 的邏輯層數與 [合成] 的初始品質，下游是簽核與流片。收斂失敗的直接後果是降頻出貨或延後流片，兩者都是專案最不願承受的結局。

## 與相鄰分類的關聯

- 與 [合成] 的關係：合成決定邏輯層數與初始餘裕，是收斂的第一戰場。
- 與 [佈局] 的關係：收斂手段與實體設計不可分割，兩者共用同一套 STA 引擎迭代。
- 與 [同步設計] 的關係：同步紀律是收斂方法學的數學前提。
- 與 [低功耗設計] 的關係：速度與漏電的取捨在多閾值電壓元件庫上交會。
- 在上位概念 [積體電路] 中，本分類屬於設計方法，是把性能目標兌現成物理現實的技術總集。

## 容易混淆之處

- **STA 過關不等於電路正確**：STA 只驗證時序不等式，功能對錯仍要靠 [驗證]。
- **餘裕越大不一定越好**：過度餘裕意味著用太多緩衝與過強閘，面積功耗雙輸；收斂追求的是「足夠」，不是「最大」。
- **時脈頻率高不等於性能高**：若關鍵操作需要多個週期，頻率與吞吐量沒有直接關係；性能要架構與時序同時配合。
- **簽核工具的過關不等於量測過關**：矽上量測受電壓溫度與製程偏移影響，簽核模型只能逼近不能取代實測。

## 技術要點

- 時序限制檔（SDC）必須版本化管理，與 [規格] 逐條對應。
- 所有虛假路徑與多週期路徑要顯式宣告，否則收斂會浪費在不可能發生的轉換上。
- 收斂過程應固定「先修建立時間、再驗保持時間」的順序，因為兩者的修復手段方向相反。
- 寄生參數抽取的精度應隨流程推進逐步提高，最終簽核使用含電容電阻耦合的完整模型。
- 每輪修復後要回歸全部時序角，避免「修好一角、弄壞另一角」的迴圈。

## 常見的論爭

- **收斂責任在架構師還是後端**：邏輯層數太深的結構問題，後端用物理手段往往修不動；「架構師應為時序負責到什麼程度」是組織分工的長期爭論。
- **簽核餘裕的定義**：模型誤差該預留多少，各家晶圓廠的方法學文件數字不一，設計公司在成本與風險間各有立場。
- **機器學習輔助收斂**：以模型預測繞線延遲指導放置正在興起，但預測錯誤的責任歸屬與簽核有效性仍是開放問題。
