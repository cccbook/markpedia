# 同步設計

> 隸屬：[積體電路]　·　上層：[設計方法]　·　狀態：初稿

> 對應維基百科：[中文維基百科：同步逻辑](https://zh.wikipedia.org/wiki/%E5%90%8C%E6%AD%A5%E9%80%BB%E8%BE%91)　·　[English Wikipedia: Synchronous circuit](https://en.wikipedia.org/wiki/Synchronous%20circuit)

同步設計是數位電路的主流紀律：所有記憶單元（正反器）共用一個或多個**時脈**，資料只在時脈邊緣被取樣，而在兩個邊緣之間，組合邏輯必須把新值算好並穩定下來。這條紀律把「電子學」的問題轉化為「離散時間」的問題——只要每條路徑都能在一個時脈週期內走完，整個電路的行為就可以像軟體一樣一步一步推演。今日絕大多數 [RTL] 都以同步設計假設書寫，所有的靜態時序分析、邏輯合成與 [驗證] 工具鏈，都建立在這個假設之上。

同步設計的兩個基本條件是：任何兩個相連正反器之間的路徑延遲必須小於時脈週期（建立時間要求），且時脈邊緣後資料不得太快改變（保持時間要求）。違反前者，電路跑不快；違反後者，電路在任何頻率下都會錯——保持時間違例不隨降頻而消失，是實驗室中最難纏的問題。

## 技術與理論的關聯

- **時脈分佈網路**：把同一時脈送到數百萬個正反器且歪斜（skew，各點時脈到達時間差）控制在數十皮秒內，需要樹狀緩衝網路，其功耗常占總動態功耗的三成以上。
- **與 [時序收斂] 的關係**：同步設計讓時序問題變成「對每一條路徑驗證不等式」，靜態時序分析因此可行；收斂工作就是修復違反不等式的路徑。
- **與 [RTL] 的關係**：RTL 的 `always @(posedge clk)` 語法直接表達同步設計；編碼規範要求避免鎖存器與非同步路徑，維持這個前提。
- **非同步交界**：不同時脈域之間的資料傳遞違反同步前提，必須用兩級正反器同步器、非同步 FIFO 或握手協定處理；亞穩態（取樣落在切換窗口導致輸出不確定）是這裡的物理根源。
- **非同步電路作為對照**：完全不用全域時脈、以握手訊號協調的非同步設計理論上省時脈功耗且無歪斜問題，但工具鏈不成熟，僅在少數場景商用。
- **全域非同步、局部同步（GALS）**：把晶片切成多個獨立時脈域、域間以同步器相接，是大晶片在時脈功耗與擴展性上的折衷。

## 範例

**範例一：時序不等式的具體計算。** 一個 1 GHz（週期 $1.0$ ns）設計中，某條路徑的組成為：

- 來源正反器時脈到輸出延遲： $0.12$ ns
- 組合邏輯延遲（含 3 層閘與 2 mm 繞線）： $0.61$ ns
- 時脈歪斜貢獻： $0.05$ ns
- 建立時間要求： $0.08$ ns

合計 $0.86$ ns，slack 為 $1.0 - 0.86 = +0.14$ ns，該路徑過關。若繞線因擁塞多繞 3 mm 增加延遲 $0.18$ ns，slack 變成 $-0.04$ ns，就需要插入緩衝或重繞修復。

**範例二：兩級同步器。** 跨時脈域傳送一個單位元控制訊號時，標準寫法是：

```verilog
always @(posedge clk_fast or negedge rst_n) begin
    if (!rst_n) begin
        sync1 <= 1'b0;
        sync2 <= 1'b0;
    end else begin
        sync1 <= async_in;
        sync2 <= sync1;
    end
end
```

`sync2` 是「穩定後」的訊號；亞穩態若發生在 `sync1`，有整整一個快時脈週期讓它衰減，失效率隨週期指數下降。注意這個方法只適用單位元訊號——多位元匯流排各 bit 到達時間不一致，必須改用非同步 FIFO。

**範例三：時脈閘控的節省。** 一個模組在 90% 的時間處於待機。若直接關閉其時脈（閘控），時脈網路與該模組的動態功耗可降約 90%；以時脈樹占總動態功耗 30% 估算，整體動態功耗可省下可觀比例。這是 [低功耗設計] 中最基礎也最有效的手段，而它的正確性完全依賴同步設計的週期化語意。

## 前因後果

早期數位電路混用非同步與同步手法，除錯結果高度依賴示波器運氣。1970 年代起，隨著整合度提升，業界逐漸收斂到「全域同步」的方法學，因為只有同步假設才能讓時序驗證自動化、讓設計可以在團隊間交接。時脈頻率從 MHz 推到 GHz 的過程中，時脈歪斜與功耗成為新瓶頸，於是出現時鐘樹合成、閘控時脈、多時脈域與 GALS 等技術層層補強。同步設計的上游是 [RTL] 的編碼紀律，下游是 [時序收斂] 與 [佈局] 中的時鐘樹建置；它本身不生產任何功能，卻是所有工具鏈賴以運作的憲法。

## 與相鄰分類的關聯

- 與 [RTL] 的關係：同步設計是 RTL 編碼規範背後的理論前提。
- 與 [時序收斂] 的關係：同步紀律使時序驗證可自動化，收斂是其持續實踐。
- 與 [低功耗設計] 的關係：時脈網路是動態功耗大戶，閘控與多域設計是省電主力。
- 與 [驗證] 的關係：同步語意讓模擬結果確定可重現，是覆蓋率方法學成立的前提。
- 在上位概念 [積體電路] 中，本分類屬於設計方法，規範「所有階段該共同遵守的紀律」。

## 容易混淆之處

- **同步不等於只有一個時脈**：多時脈域設計仍是同步設計，只要每個域內部遵守紀律、域間有正確同步器。
- **時脈歪斜小不等於時序過關**：歪斜只是時序方程的一項；組合邏輯與繞線延遲同樣要驗證。
- **同步器不等於萬靈藥**：兩級同步器只解決單位元訊號；多位元資料誤用同步器會產生撕裂值，屬於高頻率的功能錯誤。
- **降頻不能修保持時間違例**：保持時間違例與時脈週期無關，必須靠延遲插入修復，這與建立時間違例完全不同。

## 技術要點

- 時脈應由單一鎖相迴路樹狀分佈，避免長距離平行走線造成歪斜。
- 所有跨域訊號都要登記在跨時脈域清單中，逐一審查同步方式。
- 複位策略（同步或非同步復位、復位釋放順序）應全晶片統一。
- 時脈閘控單元應使用元件庫提供的無毛刺版本，並由工具自動插入。
- 時脈樹的功耗、歪斜與插入延遲應在 [佈局] 階段一併最佳化，不可事後補救。

## 常見的論爭

- **全域時脈能否擴展到下一代晶片**：晶片變大後時脈歪斜與功耗持續惡化，GALS 與非同步技術的支持者認為轉折點將至，主流工具鏈則持續以改進時鐘樹回應。
- **同步復位與非同步復位之爭**：非同步復位省邏輯但釋放時序難控制，同步復位佔面積但行為確定；兩派在各家公司的方法學文件中各有擁護者。
- **亞穩態容忍度的量測方式**：失效時間常數的推算高度依賴製程與電路拓撲，如何定義「夠安全」的同步器級數，至今沒有統一標準。
