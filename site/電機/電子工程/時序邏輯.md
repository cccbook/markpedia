# 時序邏輯

> 隸屬：[電子工程] › [數位電子]　·　狀態：初稿

> 對應維基百科：[中文維基百科：时序逻辑电路](https://zh.wikipedia.org/wiki/%E6%97%B6%E5%BA%8F%E9%80%BB%E8%BE%91%E7%94%B5%E8%B7%AF)　·　[English Wikipedia: Sequential logic](https://en.wikipedia.org/wiki/Sequential_logic)

時序邏輯是**輸出不只由當前輸入、還由電路過往狀態決定的數位電路**（「時序」指行為沿時間展開、有先後與記憶；對照只看當下輸入的 [組合邏輯]）。記憶的本體是 [正反器]——能在時脈邊緣抓住一位資料的元件——而時脈則像指揮的節拍器，讓數百萬個暫存器在同一瞬間同步動作。處理器的暫存器堆、計數器、狀態機、快取，全部屬於時序邏輯；可以說**組合邏輯負責「算」，時序邏輯負責「記」與「等」**。

理論上，時序邏輯對應自動機理論：米利機（輸出依賴狀態與輸入）與摩爾機（輸出只依賴狀態）在 1950 年代被形式化，有限狀態機從此成為控制器設計的通用語言。硬體上，同步設計原則——所有暫存器由同一時脈驅動、組合邏輯夾在兩排暫存器之間——讓「驗證電路正確」簡化為「驗證時序約束成立」，這是數位設計能在億級閘規模下管理複雜度的根本原因。

## 技術要點

- **基本節奏**：每一級的公式是 $T_{clk} \geq t_{cq} + t_{comb} + t_{setup}$ ，即時脈週期必須涵蓋「暫存器輸出延遲加組合路徑延遲加下一級建立時間」；不滿足就違反時序，電路以隨機機率出錯。
- **同步與非同步**：同步設計以全域時脈為準，易於分析但時脈樹耗電可占晶片三成；非同步（自時鐘）設計省時脈樹，但握手協定與驗證困難。
- **狀態機三段式**：狀態暫存器、次態組合邏輯、輸出組合邏輯分開撰寫，是可綜合 RTL 的標準寫法。
- **時序例外與跨時脈域**：不同時脈域之間的資料必須經雙正反器同步器或非同步 FIFO，否則會出現亞穩態——暫存器停在 0 與 1 之間不確定值。
- **亞穩態**：在建立或保持時間視窗內取樣，輸出進入介於兩態的暫態；機率隨時間指數衰減，MTBF（平均無故障時間）公式用來量化風險。

## 範例

**用時序公式算時脈上限。** 某路徑：發射暫存器 $t_{cq} = 0.2\,\text{ns}$ ，組合邏輯 $t_{comb} = 3.1\,\text{ns}$ ，接收暫存器 $t_{setup} = 0.15\,\text{ns}$ 。最小週期 $T_{min} = 0.2 + 3.1 + 0.15 = 3.45\,\text{ns}$ ，最高時脈 $f_{max} = 1 / 3.45\,\text{ns} \approx 290\,\text{MHz}$ 。若目標是 500 MHz（ $T = 2\,\text{ns}$ ），必須把這條組合路徑拆成兩級：在中間插入暫存器，每級組合延遲降到約 1.5 ns。這就是管線化（pipelining）的時序動機——切一刀， throughput 立即翻倍，代價是延遲（latency）多一拍與多一排暫存器的功耗。反方向看，違反保持時間（ $t_{cq} + t_{comb(min)} < t_{hold}$ ）與時脈無關、連降頻都救不了，只能改電路，這是跨時脈域事故最難纏的原因。

## 前因後果

- **前因**：1919 年艾克勒斯與喬丹發明真空管觸發電路（正反器的祖先）；[夏儂] 與 1940 年代自動機理論給出狀態機的數學；1950 年代 [正反器] 隨電晶體與 TTL 標準化。
- **里程碑**：1968 年 CD4000 CMOS 系列把時序元件功耗壓到微瓦；1980 年代硬體描述語言與靜態時序分析工具把時序約束變成可自動檢查的規格。
- **後果**：同步時序方法是 [積體電路] 設計流程的中樞——綜合、布局、時序收斂都在滿足 $T_{clk}$ 約束；時脈分配網路成為晶片上最龐大的「電路」，低功耗設計因此發展出時脈閘控與多電壓域。
- **未來壓力**：製程微縮放緩後，時脈樹功耗與全局同步的伸縮性成為瓶頸，多核異構、近閾值運算與非同步路線重新被認真討論。

## 與相鄰分類的關聯

- 與 [組合邏輯] 的關係：兩者是一體兩面——暫存器之間夾組合邏輯；組合路徑的長短直接決定時脈上限。
- 與 [正反器] 的關係：正反器是時序邏輯的原子；鎖存器、暫存器、計數器都是它的組織化形式。
- 與 [邏輯閘] 的關係：時脈樹要驅動百萬閘級負載，閘的驅動力與緩衝器插入是時鐘設計的日常。
- 與 [取樣] 的關係：訊號鏈的取樣定理與時序的建立保持時間，本質都是「何時讀取才不失真」。
- 與 [自動控制] 的關係：狀態機是離散時間的控制迴路；控制器與被控物之間的介面常用同步電路實現。
- 與 [積體電路] 的關係：靜態時序分析是晶片簽核（sign-off）必經關卡，時序違例可以否決整顆晶片的量產。

## 容易混淆之處

- **鎖存器與正反器不同**：鎖存器在電平有效期間「透傳」，正反器只在時脈邊緣取樣一次；RTL 裡非預期的鎖存器是設計錯誤。
- **時脈偏斜與抖動**：偏斜是同一時脈到各暫存器的時間差（系統性），抖動是週期隨機變動（雜訊性）；兩者都吃掉時序餘量但成因與對策不同。
- **亞穩態無法根除**：同步器只是把故障機率壓到極低，不能證明不會發生；安全關鍵系統要再加冗餘與多數決。
- **latency 與 throughput 不是一回事**：管線加深提高吞吐率但增加單筆延遲；行銷文件常混用這兩個詞。

## 常見的論爭

- **全域同步是否到牆**：數十億閘的時脈樹功耗與偏斜控制越來越貴；多時脈域與全域非同步局部同步（GALS）是熱門替代，但工具鏈成熟度仍以同步為王。
- **RTL 教學要不要先教狀態機**：一派主張從狀態圖入手建立「硬體是並行的」直覺，一派主張從 Verilog 語法入手；爭論背後是軟體思維對硬體教學的入侵。
- **軟體定義硬體的邊界**：FPGA 與高階綜合讓演算法工程師也能產生時序電路，批評者指出自動產生的電路時序與功耗往往比手工設計差數倍。

## 小結

時序邏輯給電路裝上記憶與節拍：組合邏輯在兩拍之間算出答案，暫存器在下一拍把它接住。建立與保持兩個視窗、一條不等式，撐起了從電子錶到資料中心的全部數位世界；理解它，等於握住數位設計的心跳。

## 設計檢核清單

- 每個時脈域內，確認所有路徑滿足建立與保持約束；靜態時序分析報告必須零違例才能簽核。
- 跨時脈域訊號一律經同步器（單位元用雙正反器，多位元用非同步 FIFO 或握手），不得心存僥倖。
- 狀態機用三段式撰寫，狀態編碼考慮獨熱（FPGA）或格雷碼（低翻轉功耗）；加入非法狀態的預設分支。
- 時脈樹避免閘控散置；需要省電時用標準的整合時脈閘控單元，並檢查閘控引發的偏斜。
- 復位策略明確化：同步復位還是非同步復位加同步釋放，兩者混用是隱蔽 bug 的溫床。

## 狀態機設計的三個口訣

- 先畫狀態圖再寫碼：狀態、事件、動作三件事在圖上講清楚，RTL 只是翻譯。
- 一個 always 塊管一件事：狀態暫存、次態邏輯、輸出邏輯分開，綜合結果可預期。
- 給非法狀態留出口：default 分支回到安全狀態，看門狗與超時計時器是長壽系統的標配。

## 計數器與分頻的日常

- 二進位漣波計數器最簡單但各位翻轉不同步，同步計數器以進位預測換取同拍翻轉。
- 分頻是時脈世界的呼吸：晶振 25 MHz 經鎖相環倍頻再分頻，長出 CPU、匯流排與外設各自的時脈。
- 計數器溢位與回繞（回繞到零）是嵌入式 bug 常客，無符號比較與回繞感知的寫法要刻意練習。
