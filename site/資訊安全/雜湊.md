# 雜湊

> 隸屬：[資訊安全] › [密碼學基礎]　·　狀態：初稿

> 對應維基百科：[中文維基百科：密碼雜湊函數](https://zh.wikipedia.org/wiki/%E5%AF%86%E7%A0%81%E6%9D%82%E5%87%91%E5%87%BD%E6%95%B0)　·　[English Wikipedia: Cryptographic hash function](https://en.wikipedia.org/wiki/Cryptographic%20hash%20function)

雜湊函數把**任意長度的輸入壓成固定長度的指紋**，且具有單向性：從指紋反推原文在計算上不可行。密碼學雜湊還需抗碰撞——找不到兩個不同輸入有相同指紋。它不加密、無金鑰、不可逆，是完整性與一致性的「膠水」：密碼儲存、檔案驗證、區塊鏈區塊連結、憑證簽署，全都以它為地基。密碼儲存這一用途尤其普遍：系統根本不需要知道你的密碼，只需要能驗證你輸入的密碼產生同樣的指紋。

## 技術與理論的關聯

- **單向性是防洩漏的關鍵**：資料庫外洩後，攻擊者拿到的是雜湊值而非密碼；若系統另加了鹽（salt），彩虹表等預計算攻擊也隨之失效。
- **碰撞即崩潰**：MD5 於 2004 年、SHA-1 於 2017 年被證實可實際產生碰撞——兩份內容不同、指紋相同的檔案可以騙過任何以指紋驗真偽的系統，簽章體系因此被迫升級。
- **慢雜湊是密碼專用**：一般雜湊（SHA-256）太快，暴力猜測每秒數十億次；Argon2、bcrypt 等密碼導出函數刻意引入成本（迭代與記憶體），把每個猜測變慢千萬倍。
- **HMAC 把雜湊金鑰化**：加入金鑰的訊息驗證碼讓「只有持有金鑰者能產生」，補上雜湊「人人可算」的缺口，廣用於 API 簽署與 [對稱加密] 方案。
- **Merkle 樹把完整性規模化**：區塊鏈與版本控制以雜湊指標串起資料，任何一環被改動都會使下游指紋全部失配。
- **雜湊也是 [演算法] 問題**：鴿籠原理保證碰撞必然存在（輸入空間大於輸出空間），密碼學雜湊的目標只是「找不到，而非不存在」。

## 範例

**範例：密碼儲存的三個世代。** 世代一：明文儲存——資料庫一洩全軍覆沒。世代二：直接 SHA-256——攻擊者對常見密碼預先算好指紋表（彩虹表），一秒反查。世代三：鹽值加 Argon2——每個使用者有獨立隨機鹽，且演算法刻意耗費 100 毫秒與 64 MB 記憶體；攻擊者即使拿到整個資料庫，對單一密碼的暴力猜測也被拉慢到不經濟。若使用者密碼是「password123」，任何雜湊都救不了——所以 [多因素] 仍是必要的第二道門。

## 前因後果

- **前因**：資料庫外洩與檔案竄改的現實需求，加上 [夏儂] 之後對單向函數的理論興趣，催生了 MD4、MD5 與 SHA 家族。
- **後果**：雜湊成為所有完整性檢查的預設：軟體更新簽章、下載檔案校驗、區塊鏈的鏈式結構；碰撞攻擊則促成 SHA-2、SHA-3 的標準遞補。
- **互相驅動**：[數位簽章] 對文件先雜湊再簽，降低簽章成本；[非對稱加密] 體系依賴雜湊做憑證指紋；碰撞攻擊的歷史反過來教育了 [安全治理] 的演算法淘汰政策。

## 與相鄰分類的關聯

- 與 [數位簽章] 的關係：簽章簽的是雜湊值，兩者是包裝關係。
- 與 [對稱加密] 的關係：HMAC 使兩者結合為金鑰化的完整性方案。
- 與 [多因素] 的關係：密碼（第一因素）的安全性極度依賴儲存方式，慢雜湊是第一道實際防線。
- 在 [資訊安全] 與 [密碼學基礎] 體系中，雜湊承擔完整性的數學基礎，回答「資料被改過嗎」這個問題。

## 容易混淆之處

- **雜湊不是加密**：雜湊不可逆，「把雜湊解密」是不存在的操作，只能逐項猜測比對。
- **加鹽不等於加密**：鹽不是祕密，它的作用是讓每個使用者的雜湊計算方式不同，阻斷預計算。
- **SHA-256 安全不代表系統安全**：單純用 SHA-256 存密碼仍是錯的，需慢雜湊函數。
- **碰撞攻擊不等於原像攻擊**：能造出兩個相撞的文件，不等於能反推指定指紋的原文；兩種強度需求不同。
- **檔案指紋比對需信任來源**：攻擊者若連官網與指紋一起偽造，比對就失去意義。
- **雜湊輸出不需保密也不需防偽**：指紋可以公開，因為它的價值在比對而非隱藏。
- **速度是雜湊的缺點也是優點**：一般用途要快（每秒 GB 級），密碼儲存要慢（Argon2），場景錯置就是事故。
- **雜湊不提供真實性**：指紋相同只證明內容相同，不證明內容值得信任。
- **長度延伸攻擊的教訓**：把資料直接拼接在雜湊輸入後（`hash(secret || data)`）會被延伸攻擊利用，正確做法是 HMAC。
- **雜湊在區塊鏈中是信任的代價單位**：挖礦的本質就是尋找特定性質的雜湊值——用計算困難換取不可竄改。
- **核對碼的文化差距**：多數使用者從不比對下載檔的指紋，這是教育與工具（自動驗證的套件管理器）共同的責任。
- **鹽與胡椒的差別**：鹽不需保密、每人不同；胡椒是全域祕密，加了它資料庫單獨洩漏也不夠——但胡椒的輪替是難題。
- **雜湊也是時代的鏡子**：MD4 到 SHA-3 的演進，每一步都踩在某次實際碰撞攻擊的屍體上，密碼學史也是攻擊史。
- **編碼陷阱**：以十六進位或 Base64 傳遞指紋時須固定大小寫與填充規則，否則同一雜湊會出現多種字串形式，比對邏輯容易出錯。

## 技術要點

- 選擇 SHA-2 家族或 SHA-3；MD5 與 SHA-1 不得用於任何安全用途。
- 密碼儲存用 Argon2id 或 bcrypt，鹽隨機且逐使用者唯一。
- HMAC 的金鑰與訊息拼接順序有標準構造，切勿自行設計。
- 雜湊輸出長度決定碰撞難度：256 位元輸出約需 $2^{128}$ 次運算才能找到碰撞。
- 檔案完整性應在可信信道上取得指紋（如官網 HTTPS），否則比對無效。
- 保留演算法升級能力：儲存的雜湊應標註演算法版本，以便全量重雜湊。
- 鹽值長度至少 128 位元隨機生成，不可使用使用者名稱或時間戳。
- 對長訊息的完整性驗證，Merkle 樹可只重傳根指紋即可覆核整體。
- API 請求簽署以 HMAC 綁定請求內容，防重放與竄改。
- 雜湊樹的根指紋可作為整份資料集的單點承諾，適合對外發布。

## 常見的論爭

- **SHA-1 撞撞事件的責任**：實用碰撞展示後，該淘汰而未淘汰的系統（如 Git 早期、憑證簽章）引發責任歸屬的辯論。
- **密碼導出函數的成本參數**：調多慢才算「夠慢」涉及使用者體驗與伺服器成本的拉鋸。
- **後量子對雜湊的影響**：Grover 演算法將對稱安全減半，雜湊輸出長度是否需要加倍尚有爭議，但主流做法是加大安全邊際。
