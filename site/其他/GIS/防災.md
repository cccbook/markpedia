# 防災

> 隸屬：[GIS] › [應用領域]　·　狀態：初稿

> 對應維基百科：[English Wikipedia: Disaster management](https://en.wikipedia.org/wiki/Disaster_management)

## 定義

[GIS]是地理資訊系統的英文縮寫。

白話說，GIS就是把「某個地方發生了什麼」與「事情發生在哪裡」放在一起整理、查詢與分析的工具。

防災是利用地理空間資料辨識災害威脅、評估可能受影響的人與資產，並協助擬定減災、準備、應變與復原對策的應用領域。

此處的「防災」不只指事前降低災害發生機率，也涵蓋災前準備、災中救援及災後復原。

白話說，它要回答的是「可能在哪裡出事、會影響誰、應該先把資源送到哪裡，以及怎麼安全撤離」。

GIS在其中的角色，是把地形、降雨、火勢、道路、建物、人口與避難設施等資料放在可比較的空間框架中。

它可以把零散紀錄轉成風險地圖、受影響清單、可達性分析、情境比較與動態指揮地圖。

防災通常涵蓋四個相互銜接的階段：

1. 減災：在災害發生前降低發生機率或可能損失。
2. 準備：確認責任分工、器材、人員、資料與替代方案是否充足。
3. 應變：災害發生時迅速辨識情況、疏散人員並調配救援資源。
4. 復原：評估損害、恢復基本服務並安排長期重建。

災害風險是防災分析的核心概念。

白話說，災害風險就是「事件可能造成多大損害」，不是事件本身，也不是單一危險因子。

風險通常由致災因子、暴露度、脆弱性與應變能力共同形成。

致災因子是可能引發災害的自然或人為過程，例如豪雨、颱風、崩塌、地震、火勢或傳染病流行。

暴露度是可能受到事件影響的人、建物、設施與生態系。

白話說，暴露度就是「有多少重要東西位於可能受影響的地方」。

脆弱性是對象受到損害的容易程度。

白話說，兩棟同樣靠近河道的建物，若其中一棟結構較弱、沒有防水設備或居民需要協助，其脆弱性便較高。

應變能力則包括預警、疏散、救援、醫療、避難場所及物資供應等條件。

白話說，應變能力就是「即使事件發生，社會有多大的能力降低損失並維持基本生活」。

在GIS中，風險圖是把上述因素轉換成可比較空間單元的成果。

例如，淹水深度是致災因子的空間表現，受淹建物與住戶是暴露度表現，建築結構與人口特性可反映脆弱性，而道路可達性與避難所容量則反映部分應變能力。

## 為何出現

早期防災主要依賴紙本地圖、經驗判斷、獨立台帳與口頭通報。

每個單位可能各自保存河川、道路、人口或避難所資料，卻缺少共同的座標基準與更新規則。

這種分屬造成多項瓶頸。

第一，管理人員很難迅速看出多個危險因子在何處同時出現。

第二，兩個部門使用不同年份或不同座標系統的資料，疊圖後可能產生偏移。

第三，資源清冊知道有多少物資，卻不一定知道應在多久內送到哪些社區。

第四，紙本清單難以因應道路中斷、人數變化與避難所容量調整而快速更新。

第五，災害發生後若無法重建當時採用的資料版本與分析參數，決策將難以檢討及重現。

一九六〇年代，Ian McHarg以分層地圖比較環境條件，顯示把不同主題疊在同一地區判讀的價值。

一九七〇年代，地理資訊系統逐漸把圖形、屬性與空間運算整合到可重複使用的電腦流程中。

此後，衛星觀測、數位地形資料、全球定位系統及政府開放資料逐漸成熟。

防災因此從依賴少數專家經驗的靜態紙圖，轉向可以整合多源資料、比較不同情境的空間決策支援。

二〇〇〇年代以後，網路地圖服務、群眾回報、行動定位與雲端運算又推動了下列變化：

- 官方資料能與即時道路阻斷及群眾通報互相補充。
- 同一套分析流程可透過網頁或行動介面供多個單位使用。
- 相同參數與版本可以保存，使跨單位協調和事後稽核更可行。
- 風險圖能由災後評估工具逐步轉為災前決策工具。
- 資料更新由定期批次製圖轉向事件驅動的動態發布。

GIS解決的核心問題，不是替官員畫一張漂亮地圖，而是讓不同來源、不同時間的資訊能以一致的空間與語意規則互相比較。

它讓「哪裡最需要優先處理」具有可分析的依據，也讓「若道路或雨量改變，結果會怎樣」能夠被反覆測試。

這項能力又推動了後續的資料標準、事件共通作業程序、跨部門共享平台與災害風險減輕制度。

## 技術與理論的關聯

防災與GIS各項技術的關聯，主要建立在「位置」與「風險」這兩個核心上。

- **空間參考**：不同資料必須在一致的坐標系統與基準下比較，否則相鄰、交會與重疊判斷可能失真。
- **疊圖分析**：將地形、危險區、人口、建物與避難設施疊合，可建立致災因子與暴露度之間的關係。
- **鄰近分析**：可用直線距離或區域網路關係辨識醫院、避難所、消防站及高風險聚落。
- **路徑分析**：道路橋梁、坡度、車流與封路狀況會直接改變疏散時間及救援可達性。
- **適地性分析**：可比較不同避難所位置、人口分布、服務容量與地勢條件。
- **地形與水文模型**：高程、坡度、匯流方向及河道容量是判斷崩塌、泥流與淹水風險的基礎。
- **遙測與影像判讀**：衛星或航空影像可用來辨識火場、淹水痕跡、崩塌範圍及道路阻斷。
- **時間序列**：降雨、水位、風速與火勢隨時間變化，風險圖必須保留有效時間與更新頻率。
- **統計與機率模型**：可估計不同重現期情境下的事件機率、損失分布與不確定性。
- **決策分析**：可把生命安全、經濟損失、社會公平與救援成本納入方案比較。
- **網路與拓樸**：道路是否連續、橋梁是否斷裂及避難所是否有足夠容量，會改變疏散體系的可行性。
- **不確定性傳遞**：位置誤差、模型參數與群眾回報偏差都會影響最後的風險排序。
- **資料版本管理**：保留來源、日期、處理步驟與參數，才能比較不同時期的風險圖並重現決策。
- **人本考量**：分析結果應避免把服務不足的地區誤認為「低風險」，也應限制個人位置資料的不當使用。

實務上，靜態風險圖不是最終答案。

例如，地勢低窪不代表一定淹水，道路距離短也不代表一定能快速到達。

堤防、水閘、抽水站、橋梁狀況、當日降雨量與人群移動，都可能改變實際結果。

因此，防災GIS通常需要區分「長期風險底圖」與「事件期間動態圖」。

前者供減災、準備及土地使用決策使用，後者則隨警報、現場回報與救援進度更新。

## 孫分類

防災在GIS應用中可依工作目的分成下列子類。

| 子類別 | 主要問題 | 常見成果 |
| --- | --- | --- |
| 致災因子分析 | 哪裡可能發生何種災害，強度多大 | 淹水深度圖、火勢圖、滑坡機率圖 |
| 暴露度分析 | 哪些人與資產位於影響範圍 | 受影響人口、建物與關鍵設施清單 |
| 脆弱性分析 | 哪些對象較容易受損或難以應變 | 脆弱度圖、特殊需求人口清單 |
| 應急疏散分析 | 如何在期限內把人送往安全地點 | 可達範圍、疏散路線、避難所分配 |
| 災害監測 | 事件目前發展到哪裡 | 動態事件圖、即時資源位置圖 |
| 災損評估 | 哪些建物與設施受到何種程度的損害 | 災損分類圖、損失估算表 |
| 復原規劃 | 如何依需求與風險安排重建先後 | 重建優先區、服務恢復路線 |

上述分類可共用一套[資料模型]，但分析尺度與更新頻率不同。

例如，長期減災適合較穩定的行政區或流域彙整，事件疏散則需要道路與人群資訊快速更新。

## 範例：沿海城市颱風洪水與疏散

以下情境為虛構教學案例，用來說明GIS如何支援一次颱風事件的準備與應變，不代表任何城市的官方判定。

研究範圍是一個面積二十四平方公里的沿海城市，總人口約六萬二千人。

城市中有八千六百棟建物、七座避難所，以及一條會受潮汐影響的沿海道路。

### 一、界定事件與問題

規劃單位設定兩種颱風情境。

第一種情境的二十四小時累積雨量為三百二十公釐，並假設河道水位超過警戒值一點二公尺。

第二種情境的累積雨量相同，但高潮位較高，並假定沿海泵站在登陸後六小時內有一組停止運作。

團隊要回答四個問題：

1. 哪些區域可能出現至少二十公分、八十公分或一百五十公分的淹水深度？
2. 哪些建物、住戶與醫療等關鍵設施位於不同淹水等級內？
3. 避難所是否有足夠容量，以及道路是否仍可通行？
4. 若一條主要道路中斷，哪些聚落需要改用替代路線？

### 二、準備輸入資料

團隊先透過[資料取得]整合下列資料：

| 資料 | 空間形式 | 範例精度或尺度 | 用途 |
| --- | --- | --- | --- |
| 數位地形模型 | 柵格 | 五公尺像元 | 計算地勢、坡度與積水方向 |
| 建物輪廓 | 向量多邊形 | 全區最新版本 | 判斷受淹與避難人數 |
| 道路中心線 | 向量線 | 每季更新 | 計算疏散時間與救援可達性 |
| 降雨與潮位 | 時序資料 | 每十分鐘 | 驅動淹水情境 |
| 人口資料 | 區塊或建物 | 事件前一日 | 估算各區暴露人口 |
| 避難所 | 點與容量 | 開放前人工核對 | 配置受災人口 |
| 道路阻斷 | 點或線 | 事件期間即時回報 | 更新可通行網路 |

所有資料先保存原始版本與取得日期，再統一轉入適合距離計算的投影坐標。

建物邊界若偏移超過兩公尺，便列入人工複核，不直接參與正式受淹判定。

道路則檢查端點是否連續、橋梁是否跨接，以及單向與限行資訊是否完整。

這些前置工作把資料整理成一致的[資料模型]，並由[GIS軟體]執行格式檢查與圖層管理。

### 三、建立淹水情境

以五公尺像元計算，研究範圍共包含九十六萬個像元。

水力模型分別產生兩種情境的淹水深度，再將連續深度轉為三個決策等級。

第一種情境估計有三百七十二公頃土地達到二十公分以上淹水深度。

第二種情境因高潮位與泵站失效，面積增加為四百七十一公頃。

團隊再以淹水像元與建物多邊形進行疊圖，結果如下：

| 指標 | 第一種情境 | 第二種情境 |
| --- | ---: | ---: |
| 受淹建物 | 五百三十六棟 | 八百零二棟 |
| 淹水深度達八十公分以上 | 一百四十四棟 | 二百九十七棟 |
| 受影響或需要撤離人口 | 約四千六百人 | 約七千四百人 |

數字來自特定建物、居住人口與水深門檻的組合，並非人口總數的固定比例。

團隊另抽查一百棟受淹建物，發現其中五棟的輪廓跨越堤外道路與堤內住宅區。

這五棟被標為邊界敏感案例，必要時以現場照片及門牌位置修正，而不會把所有估算值視為同等可靠。

### 四、檢查避難容量

七座避難所的登記事項總容量為五千八百人。

只看總量時，第二種情境的七千四百名撤離人口似乎仍有缺口。

但實際需求並非同時湧入所有避難所。

團隊以[空間分析]分別計算各聚落到最近三座避難所的範圍，再以道路長度、平均步行速度、出入口容量及無障礙通行時間修正配置結果。

若採用每小時三公里的步行速度，某一高地聚落到最近避難所的道路距離為一點八公里。

理論步行時間約為三十六分鐘，但其中有四百公尺坡道及一段施工便道。

加入這些條件後，模型把可達時間調高為四十七分鐘，並將該聚落列為需要接駁的優先區。

這顯示直線距離短的聚落不一定實際可達，而[GIS軟體]中的自動路徑仍需由現場資訊與專家判斷補充。

### 五、比較撤離方案

團隊建立三種撤離方案：

1. 全部受影響人口前往最近可達避難所。
2. 高風險人口先前往高地臨時集合點，再由接駁車分流。
3. 醫院、養老機構與行動不便者使用專車路線及專屬收容場所。

經過[空間分析]比較，第二種方案可把第一小時內需要接駁的人數由一千一百四十人降至六百八十人。

但第二種方案需要十二輛接駁車、二十六名引導人員及三處可用集合點。

若其中一處集合點因道路積水不能使用，方案仍可保留，但需重新分配三百二十名居民。

這顯示疏散規劃不是只求一條最短路線，還要同時考量容量、時間、替代性與弱勢者的需求。

### 六、發布事件圖表

現場指揮中心取得的成果包括：

- 以二十公分、八十公分與一百五十公分分級的淹水預測圖。
- 受淹建物、住戶與關鍵設施清單。
- 可用道路、阻斷道路及替代路線圖。
- 避難所容量、剩餘容量與特殊需求空間表。
- 接駁優先區、候選車隊與人員位置圖。
- 資料時間、模型版本、不確定性與已知錯誤說明。

地圖不只呈現危險區，也呈現可用道路與資源位置，避免把「沒有受淹預測」誤讀成「所有系統都能正常運作」。

### 七、事件後更新與檢討

當晚八時，社群回報顯示沿海路某路段積水三十公分。

團隊將阻斷點加入道路網，重新計算後，沿海醫院到外傷中心的最佳時間由二十二分鐘增加至三十一分鐘。

另一組回報在九時被證明是大型貨車故障造成的短暫阻斷，因此事件紀錄保留回報、查核與撤除時間，而不只保留最後狀態。

災害結束後，團隊將實際淹水範圍與預測圖比較。

若預測漏掉一處低窪通道，便更新地形或排水資料；若預測範圍明顯偏大，便檢查降雨時間對齊、堤防條件與模型參數。

更新後的資料可以回饋下一次減災工程、避難所配置與[都市規劃]檢討。

這些步驟也顯示，防災成果不是一次性地圖，而是資料、分析、決策、現場回報與版本更新之間的循環。

## 與相鄰分類的關聯

防災是[GIS]在[應用領域]中的一個重要分支，與同資料夾內其他分類具有下列關聯。

- 與[資料取得]的關聯：地形、遙測、建物、道路、人口、群眾回報與避難所資料，是形成風險判斷的證據基礎；來源時效、精度與授權會直接改變分析可信度。
- 與[資料模型]的關聯：防災資料必須明確表示事件時間、空間範圍、危險因子、暴露對象、脆弱性與容量，才能避免把不同語意或不同版本的資料任意疊合。
- 與[空間分析]的關聯：受淹範圍、重疊、鄰近、可達性、疏散與適地性等運算，是把危險位置轉成行政決策的主要方法。
- 與[GIS軟體]的關聯：軟體負責資料整合、模型串接、製圖、服務發布與批次更新，但參數選擇、專業判讀及制度責任仍須由防災團隊承擔。
- 與[都市規劃]的關聯：土地使用、避難空間、排水設施與災害風險區會相互影響；規劃若忽略淹水或崩塌風險，可能把更多人口與資產置於危險位置。
- 與[資源管理]的關聯：消防車、醫療床位、避難所空間、食物、飲水及發電機等資源，必須透過空間供需與可達性分析分配，才能避免總量足夠但送達不及的問題。
- 與[應用領域]的關聯：同一套空間資料會因應用目的而有不同尺度與更新需求；防災特別著重即時性、不確定性、生命安全與作業流程整合。

防災與上述分類並非彼此分開。

[資料取得]提供證據，[資料模型]整理語意，[空間分析]形成判斷，[GIS軟體]協助執行與發布，而[都市規劃]及[資源管理]則把成果轉為長期建設與現場行動。

因此，一套有效防災系統的品質，不取決於單一地圖或單次運算，而取決於整條資訊鏈能否穩定運作並被人類理解。

## 限制、倫理與治理

GIS能支援決策，但不能代替決策責任，也不能消除自然與制度上的不確定性。

預測範圍不是實際受災範圍的保證，模型中的容納量也不等於現場實際可用容量。

模型若只納入正式行政資料，可能低估臨時避難所、居家照護者、遊客或未登錄住戶的需求。

反之，社群回報數量多也不代表分布均勻；沒有回報的區域可能是真的沒有事件，也可能是網路、供電或行政能力不足。

發布個人位置、建物風險與特殊需求資訊時，應採取最小必要原則。

這包括降低位置精度、限制存取權限、避免姓名與健康資料不相稱地並列，以及對外發布時聚合小樣本。

不同社區承受的災害風險並不相同，風險排序若只用經濟損失，可能使高人口密度但資產較少的地區得到較少資源。

評估方案時還應檢查可達性、時間成本、資訊使用能力與身心障礙需求。

制度上應指定資料負責人、模型審核者、現場聯絡窗口與決策授權者。

每次發布都要附上資料日期、情境假設、版本、已知限制及回報管道。

只有把技術品質與公共治理放在同等地位，GIS的精確外觀才不會製造過度確定的安全感。
