# GRASS

> 隸屬：[GIS] › [GIS軟體]　·　狀態：初稿

> 對應維基百科：[中文維基百科：GRASS GIS](https://zh.wikipedia.org/wiki/GRASS_GIS)　·　[English Wikipedia: GRASS GIS](https://en.wikipedia.org/wiki/GRASS_GIS)

地理資訊系統（GIS）是將位置、屬性資料與空間關係放進電腦中，以便查詢、分析及繪製地圖的一類資訊系統。

GRASS 是一套免費、開放原始碼且可自由修改的 GIS 軟體套件。

白話而言，GRASS 就是一套能夠把「匯入地圖資料、清理資料、計算坡度或土地變更、輸出圖表與成果檔」串成重複作業流程的工具箱。

它不只是一個能畫地圖的程式，而是一群具有共同資料管理規則的專業工具。

## 定義

GRASS 最初是「地理資源分析支援系統」（Geographic Resources Analysis Support System）的縮寫。

「軟體套件」是指由多個功能不同的程式共同组成、使用同一套工作環境的軟體集合。

GRASS 的主要用途是處理具有空間位置的地圖資料。

它可以讀取格網資料、向量資料、影像、表格與時間序列資料。

格網資料是把地表切成規則方格，每個方格記錄數值或類別，例如高程、溫度或土地使用類別。

向量資料則以點、線和面來表示地物，例如井位、道路、建物邊界與行政區。

除了資料處理之外，GRASS 也能進行空間分析。

空間分析是利用位置關係與鄰近規則，從原始地理資料推求新資訊，例如由高程判斷哪些地方較陡。

GRASS 的輸出不限於螢幕上的地圖。

它也能產生數值網格、統計表、向量成果、影像檔與其他可再加工的資料。

GRASS 的核心設計著重於可重現性。

可重現性是指同一份輸入資料、同一組參數與同一版本軟體，能夠再次得到一致的處理結果。

由於採用開放原始碼模式，研究人員可以閱讀、修改及重新散布相關程式碼。

GRASS 也可透過批次作業與程式設計方式進行自動化。

批次作業是把許多資料或參數交由電腦依序處理，減少逐項點擊介面的重複工作。

GRASS 所屬的 [GIS軟體] 類別，涵蓋桌面軟體、伺服器端平臺、命令列工具與嵌入式元件等不同形態。

它與一般以繪圖為主要訴求的軟體相比，更常被用於需要大量計算、反覆驗證與批次處理的科學及工程工作。

## 產生背景與前因後果

GRASS 的起源可追溯至 1980 年代初期的美國陸軍工程兵團。

當時，政府部門需要處理地形、土壤、水文與土地管理資料。

不同單位往往使用不同工具，造成資料格式、座標系統與分析方法不一致。

若每次研究都重新撰寫程式，也會增加成本並降低成果的可比性。

這些瓶頸促使美國陸軍工程兵團於 1982 年啟動一項通用的地理資源分析支援系統計畫。

早期工作主要在維吉尼亞州的工程研究與發展環境中進行。

1983 年前後，GRASS 的早期版本開始對外提供使用。

早期版本已能結合向量與格網資料進行地形及水文分析。

隨著個人電腦能力增加，GRASS 也從專用的大型電腦環境轉向較普及的工作站。

1991 年的 GRASS 4.0 是其發展史上的重要里程碑。

這個版本改善了資料介面、命令列工具與不同作業系統間的相容性。

1997 年的 GRASS 5.0 進一步擴充格網、向量、三維及影像處理功能。

2004 年成立的 GRASS Software Foundation 將社群協作、資金籌措與版本發布納入較正式的治理架構。

同年附近的第六代版本也採用較一致的資料庫與模組架構。

專案後來採用 GNU 通用公眾授權，使程式碼可以由更多組織共同維護。

2020 年發布的第八代版本延續開放原始碼傳統，並改善圖形操作介面及大量資料的處理能力。

GRASS 的出現解決了早期 GIS 工具各自為政、分析難以重現的問題。

它把多種分析方法組織成可以組合的模組，讓使用者能以相同資料和參數重做流程。

模組是指把一項明確功能包裝成可獨立呼叫的工具，例如坡度計算、向量清理或流域劃分。

這種模組化設計也推動了後來 GIS 社群對腳本化、資料互通與可重現研究的重視。

GRASS 並非憑空出現，而是承接了 1970 年代以來 GIS、衛星遙測、電腦繪圖與數值地形模型快速發展的趨勢。

它把原本分散於各研究機構的經驗，整合成可供教學、研究與公共管理採用的共同工具。

## 核心運作方式

GRASS 的基本操作單位是「專案」。

GRASS 專案是一個具有固定座標系統與資料目錄的工作環境，用來承載一次完整研究或作業流程。

同一專案內可以放置高程、土壤、土地利用、向量邊界及分析結果。

各種資料再依用途分組管理，避免所有檔案混在同一資料夾中。

GRASS 的模組通常透過命令列介面執行。

命令列介面是以文字指令啟動功能，與主要依靠滑鼠操作的圖形介面不同。

這種方式適合把固定流程記錄下來，也適合在大量檔案上重複執行。

GRASS 同樣提供圖形操作介面，讓初學者能瀏覽資料並建立常用流程。

一般使用者可以從圖形介面選擇工具及其參數，不必直接記憶每項指令。

熟悉資料結構後，資深使用者則常以命令列結合批次檔或指令碼執行工作。

GRASS 的模組遵循一致的基本原則。

讀取模組負責把外部檔案轉換為 GRASS 可處理的格式。

寫出模組則把處理結果轉回其他 GIS、影像或交換格式使用。

查詢模組用來列出地圖資訊、計算統計量或檢查錯誤。

轉換模組負責裁切、重新分類、合併、投影與格式轉換。

分析模組處理坡度、視域、覆疊、網路、徑流及分類等問題。

視覺化模組可將格網或向量成果加入圖形視窗，並調整色彩、圖例與版面。

這些模組的共同點，是在前一步產生的資料可以直接成為下一步的輸入。

例如，數值高程模型可先轉成坡度，再依坡度門檻分類，最後統計各類面積。

整條流程可由同一個環境中的多個模組完成。

GRASS 透過集中管理座標系統與資料結構，降低不同模組之間的接續錯誤。

當資料格式改變時，使用者也能在匯入階段先檢查範圍、解析度、網格對齊與無效值。

這種資料檢查有助於避免錯誤在後續分析中被放大。

## 技術與理論的關聯

演算法是解決問題的具體計算規則；GRASS 的多數模組都會公開其參數與假設，讓分析者可判斷成果是否合理。

高程與坡度分析以數值地形模型為基礎。

數值地形模型是以格網數值近似地表起伏，常用來表示高程或地形表面。

GRASS 可從高程計算坡度、坡向、曲率及太陽輻射等量。

坡度表示地表傾斜的陡峭程度，坡向則表示下降或上升的主要方向。

這些量可用於工程選址、土石崩塌初篩、耕作規劃及景觀分析。

視域分析用來計算某個位置能看到哪些區域。

其結果會受到觀察高度、地球曲率、建物遮蔽及地表粗糙度影響。

曲面插值則從離散測量點推估未測量位置的數值。

插值的基本假設是附近的測量值具有一定關聯，因此可比較不同方法對成果的影響。

向量疊加將兩套或多套面狀資料放在相同座標系統中，判斷重疊與差異。

它可用於找出建物與保育區衝突路段，或比較不同行政區的服務涵蓋情形。

網路分析著重於點與線組成的道路或管線系統。

此類分析可處理最佳路徑、服務範圍、供需配置與設施可達性。

水文分析會先修正高程資料中的凹陷，再推估流向、匯流及流域。

匯流指水流逐漸集中到較低通道的過程；流域則是依分水界線劃分的集水區域。

影像分類可將遙測影像中的像元歸入預先定義類別。

遙測是以不接觸地表的方式取得地表資訊，常見來源包括衛星與航空影像。

分類成果可用於監督分類法、叢集分析及土地覆蓋變遷偵測。

GRASS 也提供抽樣工具，以部分觀測值檢查整體成果。

抽樣是把可觀測位置分成較小集合，用來估計母體特徵或檢核模型表現。

空間統計與圖形模型可用來呈現聚集、趨勢及不確定性。

不確定性是指已知資料品質與模型假設仍可能使成果產生誤差。

這些工具讓研究者不只得到一個圖層，也能分析方法本身的可靠程度。

## 資料模型

GRASS 採用格網、向量、表格與三維資料並存的混合 [資料模型]。

混合資料模型的意思，是讓不同資料型態各自採用適合的表示方法，再透過共同空間參考彼此連結。

格網模型擅長處理連續現象與像元運算。

向量模型擅長表現具有明確邊界的地物。

表格模型則容納與空間圖層相連的統計或屬性資料。

GRASS 的向量資料具有拓撲結構。

拓撲是描述點、線、面之間相鄰與包含關係的規則，例如線段端點必須落在適當節點上。

這項特性有助於道路、河川與行政邊界在接合時保持一致。

在處理過程中，屬性資料可描述每一個圖形要素。

例如，一條道路向量除了線形狀，還可以包含路面材料、限速、建造年代與維護單位。

同一套屬性欄位可以連到其他表格，形成較完整的資料關係。

三維資訊可透過高程欄位、節點高度或獨立三維點資料表達。

GRASS 支援時間序列與快照式資料。

時間序列資料記錄同一地物在多個時點的值，快照資料則只呈現某一特定時點。

這兩種方式都可支援變更偵測，但是否能比較仍取決於分類標準與時間是否一致。

所有空間成果都需要依附於座標參考系。

座標參考系是描述資料在地球上如何定位的一套規則，包括基準面、投影方式與單位。

若兩個圖層的座標參考系不同，必須先進行轉換，否則疊加結果會產生位移。

GRASS 的資料管理也鼓勵保存處理來源。

例如，輸入檔名、來源日期、解析度、分類表、分類版本與分析參數，都可作為成果的追溯資訊。

這對長期研究尤其重要，因為後續使用者需要知道某個數值如何產生。

## 孫分類

GRASS 在本分類体系中是 [GIS] 之下、[GIS軟體] 之下的孫分類。

下列項目是 GRASS 內部的功能群，而不是另外建立的百科條目。

| 功能群 | 主要內容 | 常見用途 |
|---|---|---|
| 圖形操作介面 | 地圖視窗、工具選單、資料瀏覽器 | 互動式選圖、調整樣式及建立流程 |
| 模組命令列 | 讀取、查詢、轉換與分析工具 | 重複作業、批次處理及遠端執行 |
| 格網資料工具 | 高程、坡度、覆疊、分類與水文分析 | 地形、遙測及環境分析 |
| 向量資料工具 | 清理、拓撲、緩衝、網路與差異分析 | 道路、設施及行政邊界處理 |
| 三維資料工具 | 點、線、面與高程的立體關聯 | 視域、視覺化及工程模擬 |
| 資料庫與轉接 | 表格、空間資料庫及外部格式轉換 | 跨軟體整合與成果交換 |
| 自動化介面 | 指令碼、批次檔及外部程式呼叫 | 重現流程、連續監測及大量處理 |

## 工具鏈與互通性

GRASS 可透過 GDAL 讀取及寫出多種常見的地理資料格式。

GDAL 是用於轉換格網、向量及相關中繼資料的程式庫。

向量資料可利用 OGR 介面操作。

OGR 是 GDAL 中負責向量資料格式支援的元件。

這使 GRASS 能與其他 GIS 軟體交換成果，而不必要求所有資料先轉成專屬格式。

GRASS 也可連結 PostgreSQL 與 PostGIS 等空間資料庫。

PostgreSQL 是關聯式資料庫，PostGIS 則在其上加入空間型態、索引與查詢能力。

使用空間資料庫的好處，是能讓多人共享同一份資料並以條件查詢取得所需結果。

Python 是 GRASS 常用的自動化程式語言。

透過 Python，使用者可以批次啟動模組、整理參數、讀取結果並輸出報表。

對研究團隊而言，這能把人工操作轉為可稽核的計算流程。

## 優勢

GRASS 的首要優勢是開放原始碼與可自由修改。

使用者可以檢查程式行為，也能針對特殊研究需求建立自訂模組。

其次，它具有大量成熟的分析工具。

其中不少功能源自地形、水文、土壤及遙測研究，因此能處理較專業的問題。

GRASS 對批次作業與重複流程的支援也較完整。

相同流程可套用到不同區域、不同時間或大量試算組合。

它能以相同資料與參數重新執行，適合建立可重現的證據鏈。

跨平台使用也是重要特色。

GRASS 可在 Linux、Windows 與 macOS 環境中安裝。

然而，不同發行套件所附版本、驅動程式及相依元件可能不同。

因此，重要研究仍應記錄軟體版本與套件版本。

## 限制與使用考量

GRASS 的完整資料與模組架構具有較高學習門檻。

初學者需要理解專案、圖層、解析度、範圍及座標參考系之間的關係。

命令列工具的名稱與參數也需要一段時間熟悉。

對習慣以精緻圖形介面完成工作的使用者而言，批量設定工作可能顯得繁瑣。

部分視覺化與資料庫設定需要額外安裝相依軟體。

不同作業系統或發行版本的功能也可能不完全一致。

在多人協作環境中，檔案命名、版本控制與資料備份需要另行建立制度。

GRASS 的成果檔與說明文件未必能直接轉換為其他機構的報告格式。

若研究單位主要使用商業套件，可能仍需要匯出標準格式，再於 [ArcGIS] 或 [QGIS] 中完成特定版面配置。

這些限制不表示 GRASS 不適合一般使用者，而是說它通常需要較明確的流程設計。

選擇工具時，應依資料規模、分析深度、協作方式與既有制度判斷。

## 範例

### 範例一：找出坡度大於十五度的區域並計算面積

假設研究區有一份十公尺解析度的數值高程模型。

檔名為 `dem.tif`。

高程模型涵蓋一千列、八百列，共八百萬個像元。

研究區使用以公尺為單位的投影座標，示例坐標參考代碼為 `EPSG:32650`。

目標是找出坡度大於十五度的像元，並估算其總面積。

第一步是建立專案，並指定研究區的坐標參考系。

可使用 `grass -c EPSG:32650 terrain` 啟動一個名為 `terrain` 的專案。

第二步是匯入高程模型。

使用 `r.in.gdal input=dem.tif output=dem`，把外部影像轉為 GRASS 格網資料。

第三步是確認資料範圍與解析度。

使用 `g.region raster=dem` 將目前處理範圍設定為與高程模型一致。

這一步很重要，因為後續每一個像元計算都依據目前的區域設定。

第四步是計算坡度。

使用 `r.slope input=dem output=slope unit=degrees` 產生以角度表示的坡度圖。

第五步是套用研究假設。

例如，使用 `r.mapcalc expression="slope > 15" output=steep` 找出坡度大於十五度的像元。

符合條件的像元記為 1，其餘像元記為 0。

第六步是統計面積。

使用 `r.stats input=steep units=meters` 計算各類別所占的面積。

假設結果顯示符合條件者共有 1,200 個像元。

每個像元為十公尺乘十公尺，即 100 平方公尺。

因此，符合條件的面積為 1,200 乘 100，等於 120,000 平方公尺。

換算為公頃後，結果為 1.2 公頃。

第七步是輸出可交接成果。

使用 `r.out.gdal output=steep.tif format=GTiff` 將結果輸出為標準影像格式。

這個數值例子只示範計算方式。

十五度門檻並不是所有研究都適用的標準。

若研究目的為道路施工坡度限制、工程土方或崩塌風險，應依規範選擇不同門檻。

高程資料的垂直基準、原始解析度與量測誤差，也會直接影響坡度結果。

在平坦地形中，儀器誤差可能使小數值被誤判為明顯坡度。

若資料含有無效值，必須在匯入與清理階段確認其位置。

若研究區跨越多個投影帶，則應先選擇適合整體區域的投影方式。

### 範例二：偵測一九九〇年至二〇一〇年的土地覆蓋變更

假設研究區有兩個土地覆蓋圖層。

第一個圖層 `cover_1990` 對應一九九〇年的分類結果。

第二個圖層 `cover_2010` 對應二〇一〇年的分類結果。

兩張圖層皆使用三十公尺像元及相同的土地類別代碼。

第一步是檢查兩張圖層的範圍、解析度及座標參考系是否一致。

若分類代碼的意義不同，即使數值相同，也不能直接比較。

第二步是建立變更遮罩。

使用 `r.mapcalc expression="cover_2010 != cover_1990" output=land_change`。

這個運算會把分類值不同的像元標為 1，分類值相同的像元標為 0。

第三步是按土地類別進一步拆解。

實務上不能只看總變更面積，還要分別比較耕地、林地、建成區與水域之間的轉移。

例如，可針對不同類別分別建立遮罩，再計算每一方向的變更量。

第四步是進行面積統計。

若總變更像元為 400 個，每個像元面積為 900 平方公尺，總變更面積就是 360,000 平方公尺。

換算為公頃後，結果為 36 公頃。

第五步是抽查變更像元。

可從變更區中抽取若干位置，對照原始影像判斷變更是否真實。

這種抽查能發現分類誤差、雲影、影像配準問題及年度定義不一致。

例如，若某類影像在某些區域大量缺測，缺測值不應直接被當成土地類別改變。

第六步是保留處理紀錄。

紀錄內容至少應包含原始影像日期、分類方法、分類訓練樣本、像元大小與閾值設定。

如此一來，後續更新至其他年份時，才能判斷新成果是否具有可比性。

### 範例三：把 GRASS 成果用於跨軟體協作

在 [資料取得] 階段，可先蒐集政府開放資料、測量成果、衛星影像與地籍資料。

整理後匯入 GRASS，完成座標轉換、圖層清理與空間分析。

分析結果可透過 GDAL 或 GRASS 的輸出模組轉為常見交換格式。

研究人員可在 GRASS 中保留計算流程與參數紀錄。

若後續需要與其他團隊共同製作簡報，可將成果匯入 [QGIS] 或 [ArcGIS]。

此時，GRASS 負責較深入的批量分析，其他軟體負責版面配置與跨部門發布。

這樣的分工不必以「只能選一種軟體」為前提。

## 與相鄰分類的關聯

| 相鄰條目 | 關聯 |
|---|---|
| [GIS] | GRASS 是地理資訊系統的一種實作，處理對象包含位置、屬性與空間關係。 |
| [GIS軟體] | GRASS 屬於 GIS 軟體中的開放原始碼、模組化與分析導向工具。 |
| [資料取得] | 遥感、測量、影像與既有資料可先經整理後匯入 GRESS，開始分析流程。 |
| [資料模型] | GRASS 內建格網、向量、表格與三維資料模型，並以統一規則連結各模組。 |
| [空間分析] | 坡度、疊加、水文、網路與土地變更偵測，是 GRASS 最具代表性的分析能力。 |
| [ArcGIS] | ArcGIS 是常見的商業 GIS 平台；兩者可透過標準格式交換資料並分別處理分析與發布。 |
| [QGIS] | QGIS 同為開放原始碼 GIS，兩者皆重視社群、互通性與自動化，但資料模型及工具取向不同。 |
| [應用領域] | GRASS 常用於水文、生態、工程、都市、農業、災害與行星科學等需要反覆計算的領域。 |

GRASS 與 [ArcGIS]、[QGIS] 的關係並非單純的優劣競賽。

ArcGIS 的優勢之一是與大型組織既有商業資料及服務緊密整合。

QGIS 的優勢之一是容易取得、桌面操作直覺，以及能連接廣泛的開放格式。

GRASS 的優勢則集中於成熟的科學分析模組、命令列自動化及高度可重現的處理流程。

三者可以同時存在於同一個組織。

研究階段可使用 GRASS 進行批次計算。

資料發布階段可使用 QGIS 製作網頁地圖或一般成果。

需要納入企業資料服務與既有治理制度時，可能再使用 ArcGIS。
