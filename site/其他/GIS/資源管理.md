# 資源管理

> 隸屬：[GIS] › [應用領域]　·　狀態：初稿

> 對應維基百科：[English Wikipedia: Resource management](https://en.wikipedia.org/wiki/Resource_management)

## 定義

在地理資訊系統（GIS）的語境中，資源管理是指以空間資料為基礎，辨識、評估、配置、維護及調控自然資源、公共設施、土地與其他地理資源的過程。

白話說明，資源管理就是回答三個問題：有哪些資源、資源可以用在哪些地方，以及如何讓資源在滿足需求時不被浪費或破壞。

此處的「資源」不只包括土壤、水、森林與礦產，也包括農地、道路、公園、學校、醫院、工業區、住宅用地及保護區等具有空間分布的對象。

資源管理的核心並非單純製作地圖，而是將「資源在哪裡」「現況如何」「未來如何使用」連結成可執行的決策。

因此，[GIS] 不僅是查詢與展示空間資料的工具，也是資源管理進行盤點、比較、模擬、協商及追蹤的共同基礎。

資源管理同時具有空間性與制度性。

空間性表示管理對象具有位置、範圍、鄰接關係及移動或擴散的可能。

制度性表示資源的配置受到法律、權限、預算、產業需求、社會公平及環境規範共同影響。

資源管理的成果可以是一份空間資料庫、一套土地使用規則、一張配置圖、一份優先順序清單，也可以是一套定期監測與重新調整的制度。

## 為何需要資源管理

早期空間資訊的應用偏向描述現況，例如繪製道路、建物、土地使用及地形分布。

當資料只被用來「看見」現況，管理者仍須自行判斷資源是否足夠、配置是否合理，以及不同方案會產生什麼後果。

自然資源有限、需求持續增加及城鄉發展相互競爭，逐漸形成資源分配瓶頸。

洪水、乾旱、滑坡與都市擴張也可能讓原有土地使用配置迅速失效。

資源管理因而出現，用來處理以下問題：

- 不同地區的資源供給與需求是否平衡。
- 高風險地區是否仍存在不當的開發活動。
- 公共設施是否位於實際需要服務的人口附近。
- 農地、棲地與生態廊道是否受到過度分割。
- 資源開發是否符合成本效益及環境承載條件。
- 決策過程是否能保留紀錄、接受追蹤並向公眾說明。

資源管理解決的不只是「選哪一塊地」的問題，也包括「由誰決定」「依據什麼」「如何執行」及「何時修正」等問題。

它推動了跨部門資料整合、公共參與、情境分析與持續監測，使空間資料由靜態成果轉為決策支援系統。

## 核心概念

### 資源盤點

資源盤點是建立資源數量、位置、狀態及管理屬性的基礎工作。

白話說明，資源盤點就像替家中物品建立清單，記錄每件物品是什麼、位於何處、目前狀況如何。

盤點成果應盡量包含：

- 資源的空間範圍與中心位置。
- 資源的數量、面積、容量或品質。
- 資源的所有權、使用權及管理單位。
- 資源目前的使用狀態與變動趨勢。
- 資源面臨的限制、風險及潛在價值。
- 資料來源、取得日期、解析度與可信程度。

### 空間配置

空間配置是把有限資源分配至特定地區、用途或受益對象的過程。

配置可能追求公共安全、经济效益、服務公平、環境保育或土地價值平衡。

同一項配置標準在不同情境下可能產生相反結果，因此不能只依單一指標排序。

例如，靠近道路的農地可能具有較佳的物流條件，卻也可能因交通噪音、土壤壓實及景觀破碎而降低農業永續性。

### 管理區劃

管理區劃是將管理責任、規則或資源責任分配至明確空間範圍的工作。

它可用於劃定集水區、保護區、服務區、優先整治區或禁止開發區。

合理區劃能降低責任重疊與管理空隙，也能讓政策更容易落實。

### 情境分析

情境分析是設定若干可能未來，用來比較不同管理方案在需求、氣候、人口或預算變動下的表現。

其目的不是預言唯一正確的未來，而是測試方案是否具有彈性。

### 回饋與調整

回饋與調整是把實際執行結果重新帶入管理流程的機制。

白話說明，回饋就是做完後再檢查成效，若與原目標不同便修正方法。

例如，保留農地政策若因灌溉不足而無法耕作，管理單位便需要調整灌溉設施，而不是只維持形式上的保留面積。

## 技術與理論的關聯

- 地理資訊系統：整合空間位置、屬性、關係與時間變化，支援資源盤點及配置查詢。
- 資料模型：表達資源、位置、邊界、權屬、用途與管理事件之間的關係。
- 空間分析：評估距離、鄰近性、疊合、視域、可達性及資源分布的聚集或離散情形。
- 多準則決策分析：將安全、經濟、生態、社會及成本等目標轉為透明的權衡。
- 最佳化：尋找在限制條件下達成目標的資源配置方式。
- 遙測與變遷偵測：比較不同日期的地表狀態，辨識植被、建設或災害的變化。
- 網路分析：分析交通、管線、物流、緊急救援及公共服務的連通關係。
- 空間統計：判斷資源分布是否存在群聚、異常值或明顯的空間型態。
- 土地覆蓋分類：將地表區分為耕地、林地、水體、建地或其他資源型態。
- 代理人模型：以人口、活動強度或服務容量近似呈現不可直接觀察的需求。
- 系統理論：將資源投入、分配、使用、产出與回饋視為持續循環的整體。
- 公共治理：處理權責分工、利益協商、資訊公開、執行能力與問責機制。
- 經濟學：比較替代方案、邊際效益、機會成本及外部成本。
- 環境承載：判斷特定地區在合理條件下可承受的活動量與資源消耗程度。

技術計算本身不會決定政策方向。

評分方法、權重、資料缺漏及假設條件都會影響結果，因此資源管理必須同時說明技術限制與制度考量。

## 資源管理的基本流程

### 一、界定問題與管理範圍

先確認管理目的、地理邊界、時間範圍、責任單位及主要利益關係者。

問題定義應可被觀察與評估，例如「每年增加多少公共設施容量」或「哪些聚落必須納入避難服務範圍」。

### 二、建立資源盤點

盤點既有資料，辨識重複、缺漏、過時及互相衝突的紀錄。

資源項目、分類原則與編碼方式應一致，才能進行後續彙整及比較。

### 三、取得並整合資料

透過 [資料取得] 收集地形、地籍、建物、土地使用、遙測、人口、交通及即時監測資料。

資料取得應同時考量授權、隱私、解析度、更新頻率、精度與取得成本。

### 四、建立資料模型

使用 [資料模型] 連結資源實體、空間幾何、屬性、時間、權屬及管理措施。

例如，一處水庫可連結蓄水量、服務範圍、維修紀錄、監測站及下游風險人口。

### 五、進行空間分析

利用 [空間分析] 比較需求與供給，並評估不同方案對安全、效率、公平及生態的影響。

分析結果應呈現假設、限制與敏感程度，而非只輸出一張看似精確的排名圖。

### 六、形成配置方案

將分析結果轉為管理優先順序、用途限制、資源配額、時程及執行單位。

方案應保留人工覆核與例外處理機制，避免資料誤差直接造成不公或危險決策。

### 七、執行、監測與修正

管理措施完成後，應設定監測週期、績效指標、通報門檻及重新調整條件。

對於災害、天候或重大建設造成的情境變化，不應等到例行檢討時才處理。

## 評估指標

| 指標 | 衡量內容 | 典型用途 |
|---|---|---|
| 空間覆蓋率 | 已納入分析的適當管理面積占總面積比例 | 判斷盤點是否遺漏重要區域 |
| 資料完整率 | 具備必要欄位及有效位置的資源紀錄比例 | 評估資料是否能支援決策 |
| 更新時效 | 資料現況與本次分析之間的時間差距 | 判斷變動頻繁地區是否需要自動更新 |
| 位置精確度 | 資源邊界或位置與實際現況的相符程度 | 評估圖上結果能否直接執行 |
| 方案達標率 | 符合選定方案的指標項目占目標項目比例 | 檢查管理措施是否落實 |
| 需求滿足率 | 已提供服務或資源的人口或面積比例 | 評估公共設施配置是否合理 |
| 單位面積成本 | 執行措施所需成本除以服務或保全面積 | 比較不同方案的資源效率 |
| 風險降低程度 | 措施前後暴露於災害或危害的差異 | 檢查防災及環境管理成效 |
| 公平性 | 不同地區或群體獲得基本服務的差異 | 防止效率考量排除弱勢地區 |
| 資源使用強度 | 單位土地、用水或能源所承載的活動量 | 判斷是否接近環境承載程度 |

達標率可簡單表示為：

達標率＝已達成目標的項目數 ÷ 目標項目總數 × 100％

指標應與決策目的直接相關，並設定資料來源、計算方式、責任單位及檢查頻率。

## 孫分類

| 類型 | 核心問題 | 典型成果 |
|---|---|---|
| 土地資源管理 | 土地適合何種用途，如何兼顧發展與保育 | 土地適宜性圖、用途分區與配額 |
| 水資源管理 | 水源是否充足，水庫與河川如何聯合調度 | 供需平衡、蓄水區劃與調度方案 |
| 礦產資源管理 | 開採位置、規模與環境成本如何衡量 | 採礦區位、總量限制與復育計畫 |
| 森林與生態資源管理 | 如何維持森林覆蓋、棲地及生物多樣性 | 保育優先區、採伐管制與廊道配置 |
| 公共設施管理 | 設施應建在何處，如何滿足服務需求 | 候選地點、可達性與服務缺口分析 |
| 基礎設施管理 | 道路、管線及能源設施如何維護與擴建 | 設施台帳、維修優先序與替代路線 |
| 農業資源管理 | 農地如何保存，生產效率與生態需求如何平衡 | 農地分級、灌溉配置與耕作適宜區 |
| 空間資料資產管理 | 資料由誰維護、授權、更新及承擔品質責任 | 資料目錄、品質規範與更新排程 |

上述類型可以共享基礎資料與分析工具，但決策標準、主管機關及執行週期未必相同。

例如，水資源調度偏重季節與流量，公共設施配置偏重人口與可達性，農地管理則還涉及耕作身分、灌溉條件及糧食安全。

## 範例

以下為虛構但可重現的「溪口流域都市發展區」資源管理案例，用於說明流程。

案例背景設定於 2010 年，當地管理範圍為 1,250 公頃。

其中包含 620 公頃一般發展用地、310 公頃農地、180 公頃河川與生態保育用地，以及 140 公頃公共設施用地。

近五年資料顯示，區內主要道路在強降雨時曾出現最高 0.8 公尺的積水紀錄。

地方政府希望同時降低 flood 風險、維持農地、補足公共服務，並避免保育用地被零碎分割。

### 第一步：設定目標

管理單位設定四項量化目標：

- 將高淹水風險區內的住宅與公共設施使用限制明確化。
- 保留至少 180 公頃河川與生態保育用地。
- 使 90％ 以上人口位於緊急救援可達範圍。
- 在既有預算內完成公共設施優先配置。

### 第二步：盤點與取得資料

管理單位透過 [資料取得] 整合 1 比 5,000 地形圖、地籍資料、土地使用圖建物輪廓、人口分布、道路網、學校、醫院及 1990 至 2010 年的雨量與水位紀錄。

道路資料統一轉為相同座標系統，並以最新航照與地面調查核對變動地物。

資料表中分別記錄資料日期、來源、負責單位、精度及已知限制。

### 第三步：建立資料模型

在 [資料模型] 中，河川保育區、淹水潛勢區、農地、服務人口與候選設施位置分別成為不同圖層。

每一筆公共設施紀錄均連結容量、服務人口、更新日期及管理機關。

模型另以事件類型保存淹水、建設與設施啟用紀錄，使未來能比較措施前後的差異。

### 第四步：進行空間分析

使用 [空間分析] 計算聚落至醫院與避難場所的距離、道路救援可達時間、農地連續程度及生態區塊邊緣的破碎程度。

高風險區是依历史降雨、地勢、排水現況與道路淹水紀錄綜合判定，而不是僅以單一河岸距離決定。

評估公共設施時，採用下列權重：

| 評估準則 | 權重 |
|---|---:|
| 洪水安全 | 35％ |
| 服務人口缺口 | 25％ |
| 基礎設施可達性 | 20％ |
| 農地與生態影響 | 10％ |
| 土地取得及建設成本 | 10％ |

各項總和為 100％，並另外檢查權重改變時結果是否仍然穩定。

### 第五步：配置土地與設施

分析將 620 公頃一般發展用地劃分為三類：

- 420 公頃列為一般適宜發展區，但必須維持排水改善條件。
- 140 公頃列為附帶條件發展區，需先完成微滯洪設施及公共設施同步建設。
- 60 公頃列為保留區，避免高風險與零碎開發。

公共設施優先配置於服務缺口較大的聚落外圍，而非只設在人口最多的中心。

農地管理則以完整灌溉、鄰近道路污染風險及耕作維持成本為條件，避免名義上保留但實際失去耕作能力。

### 第六步：使用工具執行與查核

管理人員在 [GIS軟體] 中建立可重現的方案比較流程，將不同權重、人口成長情境及降雨情境納入比較。

每一個候選方案都保留輸入資料、參數、運算日期與核准結果，以利後續審計。

軟體負責處理複雜資料與重複作業，但法規符合性、公共溝通及最終核准仍由負責機關執行。

### 第七步：監測及回饋

管理單位每季更新土地使用及公共設施資料，汛期則在強降雨事件後額外檢查道路與低窪地區。

若可達人口比例低於 90％，便重新啟動設施位置分析；若農地碎片增加或河川保護區遭侵占，則調整土地配置方案。

三年後的示例成果顯示，緊急救援可達人口比例由 82％提高至 94％，高淹水風險區新增開發面積降至零，180 公頃生態與河川保育用地則維持完整。

上述數字屬示範案例，不代表任何實際地區的官方成果。

## 與相鄰分類的關聯

- [資料取得] 是資源管理的資料入口，決定後續盤點、模型與分析能看見哪些現況。
- [資料模型] 把資源及其權屬、用途、風險與管理措施組織成一致結構，避免相同資料因部門不同而互相矛盾。
- [空間分析] 將地理關係轉為配置依據，是辨識服務缺口、衝突區域及優先位置的技術核心。
- [GIS軟體] 提供整合、運算、繪圖與發布工具，但工具本身不能替代政策判斷及制度責任。
- [都市規劃] 將資源管理結果落實為土地使用、交通、產業、住宅與公共設施的長期配置。
- [防災] 運用資源分布、暴露程度及韌性條件，決定避難、疏散、減災與災後復原安排。
- [應用領域] 是資源管理在 [GIS] 中的上位分類，與其他應用共享資料基礎、分析方法及治理要求。

資源管理也會反向影響相鄰領域。

都市規劃若持續將住宅與產業推向高風險地區，會增加防災負擔並降低有限公共資源的配置效率。

防災若只處理災害發生後的搶救，而未改善土地使用與資源預留，則可能反覆投入而無法降低長期風險。

資料取得若缺乏更新與品質管理，管理圖看似完整，實際上可能掩蓋資源流失、權屬衝突或服務不足。

因此，資源管理應被視為跨資料、技術、規劃與公共政策共同參與的過程。
