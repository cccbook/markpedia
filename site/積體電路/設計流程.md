# 設計流程

> 隸屬：[積體電路]　·　狀態：初稿

> 對應維基百科：[中文維基百科：積體電路設計](https://zh.wikipedia.org/wiki/%E9%9B%86%E6%88%90%E7%94%B5%E8%B7%AF%E8%AE%BE%E8%AE%A1)　·　[English Wikipedia: Integrated circuit design](https://en.wikipedia.org/wiki/Integrated_circuit_design)

積體電路設計流程是把**產品需求逐級轉化為可製造的物理實體**的標準工序。起點是規格：功能、效能、功耗、成本與時程；終點是交給晶圓廠的光罩資料。兩個終點之間有五個主要階段——規格、硬體描述語言（RTL）、邏輯合成、布局、以及驗證——每個階段都有明確的輸入與輸出，並且下一階段的錯誤通常只能在上一階段修正，這是流程分階段的根本理由。

這套流程之所以能夠分工，是因為每個階段的抽象層次都不同。規格在描述「產品要做什麼」，RTL 在描述「邏輯如何運算」，網表在描述「用哪些閘門與延遲」，布局在描述「這些閘門放在晶片的哪裡、怎麼連」，光罩則描述「每一層的圖形」。抽象層次每降一級，可選擇的空間急遽縮小，但正確性驗證也越來越困難。

## 技術與理論的關聯

- **抽象層次的遞減**：從行為到結構再到幾何，每一步都丟棄自由度以換取可驗證性；這是所有硬體設計方法論的共同骨架。
- **RTL 與邏輯合成**：RTL 是可模擬的行為描述，合成把行為轉為閘門網表並在面積與延遲之間最佳化，因此合成器的成本函數直接反映設計哲學。
- **時序簽核**：靜態時序分析是流程中最重要的關卡，它用最壞情況的延遲模型檢查所有路徑是否滿足時序要求。
- **布局的物理效應**：布局決定線長與電容，而線長與電容決定延遲與功耗；因此布局不是「排版」，而是性能與可製造性的決定步驟。
- **驗證的窮盡性問題**：狀態空間爆炸使形式驗證只能用於小區塊，大型設計仍須以模擬與斷言覆蓋率來管理風險。
- **可重複性與版本管理**：每次交付給晶圓廠的資料都必須是確定的、可重現的，光罩資料的任何差異都可能造成整批晶片的功能異常。

## 範例

**範例一：從 RTL 到面積。** 一個 32 位元帶進位加法器在 RTL 中不過十幾行：

```verilog
module add32 (
    input  wire [31:0] a,
    input  wire [31:0] b,
    output wire [32:0] sum
);
    assign sum = {1'b0, a} + {1'b0, b};
endmodule
```

以 7 nm 製程合成後，工具估計其組合邏輯約 1200 個等效閘（相當於 900 個 AND、300 個全加器），臨界路徑延遲約 0.35 ns。這說明 RTL 的一行運算式，可能展開為數百顆實體電晶體——「程式碼行數」與「晶片面積」之間沒有簡單關係。

**範例二：時序簽核報告。** 對一個 1 GHz 目標頻率的設計，時序簽核會列出每個時序路徑的延遲、slack 與時序路徑群組。若最差路徑的 slack 為 $-0.08$ ns，代表該路徑會比時脈週期超出 80 ps，必須透過插入緩衝、重布線或降低邏輯層級來改善；slack 為正是最惡劣的簽核結論。

**範例三：驗證覆蓋率的意義。** 一個數位驗證團隊的追蹤覆蓋率若為 95%，代表 95% 的設計程式碼曾被激發，但仍有 5% 的路徑從未被測試到。代碼覆蓋率只是指標而非證明；功能覆蓋率則檢查規格中的功能點是否都被驗證到，兩者都需達成門檻才允許簽核。

## 前因後果

早期積體電路設計由少數工程師手工繪製版面圖，隨著 [基爾比] 的單片積體化與 [諾伊斯] 的平面製程，「先在紙上想清楚、再整片製造」的想法成形，但手工設計無法支撐功能複雜度。電腦輔助設計工具因此出現，把布局、繞線與模擬交給機器；接著邏輯合成讓硬體描述語言可以直接產生網表，把「寫電路」變成「寫程式」；而製程節點縮小後，物理效應無法再靠人工估算，時序簽核與物理驗證成為強制關卡。流程因此逐漸固化成今日五階段的樣貌。

## 與相鄰分類的關聯

- 與[設計方法]的關係：流程規定「做什麼、什麼順序」，設計方法規定「每一階段怎麼做才不會出錯」，兩者互為表裡。
- 與[製程與架構]的關係：製程節點決定可用的閘門庫、規則與設計方法學，架構選擇決定流程中該做多少層次抽象的重複使用。
- 與[驗證與量產]的關係：驗證與量產涵蓋流程的前段（模擬）與後段（後端、布局路由、晶圓測試），是同一條流水線的兩端。
- 與[特殊應用]的關係：ASIC 走完整流程，FPGA 則跳過合成到實體映射的部分，改以查表與可重組連線的架構完成。
- 在上位概念[積體電路]中，本分類扮演「骨架」，提供所有其他子分類共同遵循的交接規範。

## 容易混淆之處

- **RTL 不等於 C 語言**：RTL 是描述硬體並行結構的語言，`<=` 這種非阻塞賦值代表「同一時脈內同時發生」，與軟體的順序語意完全不同。
- **邏輯合成不等於編譯**：合成不保證語意等價於原始 RTL，它最佳化的是面積與延遲，因此RTL 必須寫成可綜合風格。
- **布局不等於繞線**：布局決定位置與朝向，繞線決定連線路徑與層別，兩者在流程中先後相接但目標不同。
- **驗證不等於測試**：驗證是在設計階段確認「符合規格」，測試是在量產階段確認「這批晶片是好的」，兩者的方法與團隊都不同。
- **簽核不等於完成**：簽核是流程中的關卡，之後還有布局繞線、寄生參數抽取、功耗分析與後端等階段。
- **「迭代次數」不是品質指標**：設計往往需要多輪迭代，關鍵是每次迭代都要能定位到是哪一階段的問題。

## 技術要點

- 每一階段的交接都應以機器可檢查的檔案格式定義，避免口頭傳遞造成資訊遺失。
- 規格需量化：延遲以時脈週期計、功耗以瓦特計、面積以平方毫米計，否則無法驗收。
- 時序簽核必須覆蓋所有時序路徑群組，包含跨時脈域的虛假路徑檢查。
- 邏輯等價性檢查用來確認綜合前後的功能一致，是合成階段的守門員。
- 驗證環境的激發空間管理是專案進度的主要瓶頸，需要系統性的覆蓋率模型與隨機化手段。
- 流程中的任何手動修改都應可被追蹤，因為量產階段只允許重現已被驗證過的設計。

## 常見的論爭

- **是否應把驗證前移到 RTL 階段**：早期驗證能節省大量重做成本，但功能錯誤有時只有整機系統才能暴露，前移程度因此需要依專案調整。
- **流程的嚴格程度與創新速度**：大型專案偏好嚴格流程以確保可重現，小型專案則偏好快速試錯，這個矛盾在快速變動的產品線中最為尖銳。
- **自動化的邊界**：工具在語意正確性上仍需人工判斷，「完全自動」與「完全手工」之間，業界並無共識。
