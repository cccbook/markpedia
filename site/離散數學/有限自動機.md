# 有限自動機

> 隸屬：[離散數學] › [邏輯與計算]　·　狀態：初稿

> 對應維基百科：[中文維基百科：有限狀態機](https://zh.wikipedia.org/wiki/%E6%9C%89%E9%99%90%E7%8A%B6%E6%80%81%E6%9C%BA)　·　[English Wikipedia: Finite-state machine](https://en.wikipedia.org/wiki/Finite-state_machine)

有限自動機是**由有限個狀態與狀態間轉移組成的計算裝置**：讀入符號串，從初始狀態出發逐符號轉移，最後依是否落在接受狀態決定接受或拒絕。

它的價值在於「記憶有限」。正因如此，它能辨認的語言恰好是正規語言，也就是可用正則表達式描述的語言。從軟體的詞法分析器到作業系統的行程狀態機，從通訊協定到正則引擎，有限自動機是把「行為規則」寫成可執行規格的最簡模型。

## 技術要點

- **五要素**：狀態集合 $Q$ 、初始狀態集合 $F_0$ 、接受狀態集合 $F$ 、字母表 $\Sigma$ 、轉移函數 $\delta$ 。
- **確定性與非確定性**：每個狀態對每個符號恰有一個後繼的是 DFA，可以有多個的是 NFA。
- **轉移函數的延伸**：由轉移函數可定義狀態對應的函數 $\delta^*(q, w)$ ，這是自動機「計算」的形式化。
- **最小化**：兩個狀態等價若對所有後綴而言接受性相同；等價類構成最小自動機。
- **Myhill–Nerode 定理**：字串等價類與狀態一一對應，故狀態數有下界。
- **封閉性**：正規語言對聯接、聯集與星號運算封閉，這些運算正對應硬體的串接、並聯與迴路。

## 範例

**問題**：為一個只能吃奇數個煎餅的機器建模：狀態為「已吃 0 個（偶）」與「已吃奇數個」；每吃一個煎餅狀態翻轉；若最後為奇數個則接受。請寫出轉移函數並求等價類。

1. **定義狀態**： $Q = \{q_E, q_O\}$ ， $q_E$ 表示已吃的煎餅數為偶數， $q_O$ 表示為奇數； $F_0 = \{q_E\}$ ；接受狀態 $F = \{q_O\}$ 。
2. **轉移函數**： $\delta(q_E, \text{煎餅}) = q_O$ ， $\delta(q_O, \text{煎餅}) = q_O$ ；若考慮「不吃的選擇」，則 $\delta(q_O, \varepsilon) = q_O$ 。
3. **運行**：吃 3 個煎餅，路徑為 $q_E \to q_O \to q_O \to q_O$ ，落在接受狀態 $q_O$ ，故接受；吃 2 個則 $q_E \to q_O \to q_E$ ，拒絕。
4. **等價類判定**：兩個狀態等價若對所有後綴的接受性相同。取後綴「吃 1 個」： $q_E$ 之後接受， $q_O$ 之後仍接受（ $q_O \to q_O$ ）。取後綴「吃 0 個」： $q_E$ 不接受， $q_O$ 接受。故兩狀態不等價，此自動機已最小。
5. **狀態數的下界**：由 Myhill–Nerode 定理，字串 $\varepsilon$ 與「吃 1 個」屬於不同等價類（前者接任何偶數長後綴不接受，後者相反），故至少需 2 個狀態，與構造相符。
6. **推廣**：若要辨認「煎餅數為 3 的倍數」，狀態集合擴充為 $\{q_0, q_1, q_2\}$ 三個狀態，轉移為 $\delta(q_i, \text{煎餅}) = q_{(i+1) \bmod 3}$ ，接受狀態為 $q_0$ 。

第二個例子說明自動機的實務用法。在詞法分析中，識別 C 語言的整數常數需要一個自動機：狀態包括「剛讀到數字」「數字後接 e/E」「數字後接 +/-（等待指數）」等，規則由正規表達式描述。在編譯器的正規表達式引擎中，正則表達式先被轉換成 NFA，再以子集構造法確定化為 DFA，最後以狀態集合的預先計算加速匹配——這整條流水線，正是有限自動機理論的直接應用。

## 與相鄰分類的關聯

- 與 [命題邏輯] 的關聯：自動機的可判定性與邏輯系統的可判定性同屬「可計算性」的主題。
- 與 [函數] 的關聯：轉移函數 $\delta^*$ 把字串映到狀態，是自動機的基本計算；把狀態畫成頂點、轉移畫成邊，即得一個有向 [圖]。
- 在上位概念 [邏輯與計算] 中，有限自動機扮演**可計算性階梯**的角色：它是「可計算」的最簡模型，位於正則語言與上下文無關語言之間。

## 容易混淆之處

- **有限自動機與圖靈機不同**：後者有無限帶，能辨認所有可計算語言，前者只能辨認正規語言。
- **DFA 與 NFA 的語言能力相同**：非確定性不增加表達力，但轉換成本與實作難度不同。
- **狀態數最小與語言最小不同**：兩者相關但不等價。
- **正則表達式不支援回溯**：正則引擎不具備通用回溯能力，這與許多程式語言的正規表達式不同。

## 技術要點

- 子集構造法把 NFA 轉成 DFA，狀態數可能指數爆炸，故實務上常用 lazy DFA。
- 最小化可用 Hopcroft 演算法，複雜度為 $O(n \log n)$ 。
- DFA 的轉移表可直接以表格或位元組跳躍表實作，後者是 grep 等工具的加速手法。
- 帶計數的自動機（如「n 的倍數」）需要把計數值編入狀態，狀態數因而增大。
- 文法（context-free grammar）對應推導自動機（pushdown automaton），其語言包含正規語言。
- 自動機可與代數結合：轉移的合成可用關係的合成表示。

## 常見的論爭

- **正則表達式是否「太弱」**：實務中常需回溯或上下文相關的匹配，導致實作與理論脫節。
- **DFA 爆炸是否不可避免**：理論上確有需要指數狀態的例子，但實務中是否真的常見仍有討論。
- **形式語言分類是否對實務重要**：批評者認為分類學優雅但與工程問題脫節，支持者則以編譯器理論的實證反駁。
